# 모바일 카메라 녹화

## 목표
웹 녹화를 유지하면서 Android/iOS에서도 카메라 미리보기와 영상·음성 녹화가 가능하고, 결과 파일이 기존 업로드 흐름에 전달되게 한다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md` (가이드라인 저장소는 워킹 트리 밖에서 읽기만)
3. `lib/src/data/repositories/browser_camera_recording_repository.dart`
4. `lib/src/data/datasources/microphone_track_recorder.dart`, `lib/src/data/datasources/microphone_track_recorder_stub.dart`, `lib/src/data/datasources/microphone_track_recorder_web.dart`, `lib/src/domain/repositories/camera_recording_repository.dart`, `lib/src/domain/entities/camera_recording.dart`, `lib/src/presentation/core/di/locator.dart`, `lib/src/presentation/features/video_multimodal/camera_recording_view_model.dart`, `lib/src/presentation/features/video_multimodal/widgets/camera_recording_dialog.dart`, `android/app/src/main/AndroidManifest.xml`, `ios/Runner/Info.plist`, `pubspec.yaml`
5. 계약·화면안: 없음

## 현재 상태
- `lib/src/data/repositories/browser_camera_recording_repository.dart`: `prepare()`에서 웹이 아닌 플랫폼을 거부하며, 웹 카메라와 `MicrophoneTrackRecorder`를 이용해 영상·음성 바이트 파일을 만든다.
- `lib/src/data/datasources/microphone_track_recorder.dart`: `dart.library.html` 조건부 export로 웹 구현 또는 기본 스텁을 선택한다.
- `lib/src/data/datasources/microphone_track_recorder_stub.dart`: 녹화 시작/정지에서 웹 전용 오류를 반환한다.
- `lib/src/presentation/core/di/locator.dart`: 카메라 녹화 ViewModel에 `BrowserCameraRecordingRepository`를 직접 주입한다.
- `lib/src/domain/entities/camera_recording.dart`: 업로드 입력은 메모리의 `Uint8List`, MIME 타입, 파일명이다.
- `lib/src/presentation/features/video_multimodal/widgets/camera_recording_dialog.dart`: 녹화 파일을 기존 업로드 큐에 전달한다.
- `android/app/src/main/AndroidManifest.xml`, `ios/Runner/Info.plist`: 카메라·마이크 런타임 권한에 필요한 선언이 없다.

## 바꿀 것
1. 웹 구현과 Android/iOS 구현이 각 플랫폼에서 선택되도록 녹화 저장소 구성을 조정한다.
2. 모바일 구현은 기존 `camera` 패키지로 카메라 미리보기 및 영상을 녹화하고, 호환되는 모바일 오디오 녹음 플러그인으로 별도 음성 파일도 녹화한다. 플러그인 API와 지원 플랫폼은 공식 문서 및 현재 Flutter/Dart 프로젝트 제약으로 확인한다.
3. 두 녹화 결과를 기존 `CameraRecording` 및 `CameraRecordingFile` 계약으로 변환해 기존 업로드 UI가 사용하게 한다.
4. Android 카메라·마이크 권한 선언 및 iOS 카메라·마이크 사용 설명을 추가하고, 런타임 권한 거부·녹화 오류를 기존 안내 상태에 전달한다.
5. 시작·정지·취소·해제 및 오류 발생 시 카메라·마이크 자원을 정리한다.
6. 기존 브라우저 녹화 기능은 유지한다.

## 유지할 것
- 기존 웹 카메라/마이크 녹화 동작
- 기존 녹화 UI, 업로드 대화상자, 업로드·타임라인 배치 흐름
- 도메인 녹화 결과 및 업로드 계약
- 생성 코드

## 이번 작업에서 만들지 않음
- 서버 업로드 API 변경
- 파일 바이트 계약을 스트림/경로 기반으로 바꾸는 작업
- 백그라운드 녹화, 녹화 후 편집, 플랫폼별 별도 화면
- 무관한 리팩터와 정리

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
