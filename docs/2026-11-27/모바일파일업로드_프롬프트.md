# 모바일 파일 업로드

## 목표
Android/iOS에서 녹화 파일을 기존 POST /assets multipart 계약으로 업로드하고, 업로드 실패 시 서버 응답 오류를 기존 메시지 처리 흐름으로 전달한다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md` (가이드라인 저장소는 워킹 트리 밖에서 읽기만)
3. `lib/src/data/datasources/asset_multipart_upload.dart`
4. `lib/src/data/datasources/asset_multipart_upload_stub.dart`
5. `lib/src/data/datasources/asset_multipart_upload_web.dart`
6. `lib/src/data/repositories/remote_asset_upload_repository.dart`
7. `lib/src/data/datasources/asset_tus_upload.dart`
8. `test/asset_upload_test.dart`
9. 계약·화면안: `lib/src/data/datasources/generated/mediatag/asset/v1/asset.connect.spec.dart`

## 현재 상태
- `asset_multipart_upload.dart`: 웹에서만 브라우저 구현을 선택하며, 다른 플랫폼은 stub을 선택한다.
- `asset_multipart_upload_stub.dart`: 항상 웹 전용 UnsupportedError를 발생시킨다.
- `remote_asset_upload_repository.dart`: 32 MiB 이상은 tus를 시도하고 UnsupportedError면 multipart로 이어진다. 그보다 작은 파일은 곧바로 multipart를 호출한다.
- `asset_multipart_upload_web.dart`: metadata, 파일, Bearer 토큰으로 `POST /assets` 요청을 만들고 응답을 반환한다.

## 바꿀 것
1. Android/iOS에서 선택되는 `dart:io` 기반 multipart 업로드 구현을 추가하고 조건부 export에 연결한다.
2. multipart의 `metadata`/`file` 파트, 파일명, MIME 타입, 선택적 Bearer 토큰을 기존 웹 요청 및 서버 계약과 일치시킨다.
3. 성공 응답 본문은 그대로 반환하고, 실패 응답은 서버 본문 또는 HTTP 상태를 포함한 오류로 반환한다.
4. 요청 스트림과 응답 스트림을 종료해 연결 자원을 정리한다.

## 유지할 것
- 웹 multipart 구현과 브라우저 동작
- `RemoteAssetUploadRepository`의 Tus→multipart 대체 흐름
- 서버 업로드 계약, metadata 생성, 업로드 결과 변환
- 스텁의 지원되지 않는 플랫폼 오류 동작

## 이번 작업에서 만들지 않음
- 파일 선택기나 JSON 등록, Tus 업로드 구현 변경
- 서버 API 및 업로드 파일 모델 변경
- UI, 업로드 큐, 녹화 저장소 변경
- 범위 밖 리팩터

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
