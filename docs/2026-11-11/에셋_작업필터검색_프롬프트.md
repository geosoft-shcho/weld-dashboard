# 작업 필터 자연스러운 레이아웃

## 목표
작업 필터의「더 보기」를 없애고, 공통키 검색으로 ListJobs를 좁힌 뒤 결과 콤보에서 고르는 레이아웃으로 바꾼다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md`
3. `lib/src/presentation/features/asset_lookup/asset_lookup_screen.dart` 필터
4. `lib/src/presentation/features/asset_lookup/asset_lookup_view_model.dart` load·jobs
5. `WorkHistoryQuery.commonKey` → ListJobs

## 바꿀 것
1. 작업 검색 필드(`LookupSearchField`) + 결과 콤보.「작업 더 보기」제거.
2. 진입 시 ListJobs 선호출 안 함. 검색 debounce 후 ListJobs(pageSize 20, commonKey).
3. 콤보에서 작업 선택 → 기존 ListAssets(job_id) + 패스.
4. 검색어 비우면 작업 선택 해제(전체), 콤보는 전체만.
5. 장비「더 보기」도 필터 줄에서 제거(장비는 첫 페이지 콤보 유지).

## 유지할 것
- ListAssets 표·스크롤, 종류/후처리/파일/미지정
- 패스 콤보·올리기 다이얼로그 기본 구조
- ListJobFilters 캐스케이드는 이번 범위 밖

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
