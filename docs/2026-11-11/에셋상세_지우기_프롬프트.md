# 에셋 상세 지우기

## 목표
에셋 상세에서 [지우기]로 `DeleteAsset`을 호출하고, 성공 시 목록으로 돌아간다. 첨부·파생 부모면 화면에서 막고, 그 외 FailedPrecondition은 서버 메시지를 보여 준다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md`
3. `lib/src/presentation/features/asset_lookup/asset_lookup_detail_screen.dart` (actions 지우기 `onPressed: null`)
4. `docs/2026-10-19/관리 화면안.html` `a-del` · `protos/mediatag/asset/v1/asset.proto` `DeleteAsset`
5. 패턴: `equipment_lookup_detail_screen.dart` `_didTapDelete`

## 현재 상태
- 상세 헤더에 [지우기]가 있으나 비활성.
- `AssetService.deleteAsset` 생성 클라이언트는 있음. Repository/UseCase/VM 미연결.
- 상세 VM은 `asset`(childCount) · `jobs`(ListJobs asset_id)를 이미 가진다.
- Asset 행에 성적서 원본 플래그는 없음 → 성적서는 서버 FailedPrecondition으로 처리.

## 바꿀 것
1. `AssetLookupRepository.deleteAsset` + `RemoteAssetLookupRepository`에서 `assetService.deleteAsset` 호출. `failedPrecondition`은 한국어 `_WriteFailure`(첨부·파생·성적서 안내).
2. `DeleteAssetUseCase` 추가, locator 등록.
3. `AssetLookupDetailViewModel.deleteAsset()` → UseCase.
4. 상세 화면: [지우기] 활성. 장비 상세와 같은 ContentDialog 흐름.
   - 차단 다이얼로그(닫기만)
   - 확인 다이얼로그 → 성공 시 `didTapBackFromLookupDetail`

## 유지할 것
- GetAsset·수정·후처리·미리보기·작업 목록 UI
- MergeAssets / DetachAsset은 이번 범위 밖

## 이번 작업에서 만들지 않음
- 성적서 원본 클라이언트 사전 플래그 필드 추가
- 목록 화면 일괄 삭제, 합치기 UI

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
