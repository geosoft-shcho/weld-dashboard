# 에셋 작업 콤보 더 보기

## 목표
공통키 검색 필드로 ListJobs를 좁히는 레이아웃을 제거하고, 작업 콤보에 첫 페이지를 채운 뒤 맨아래「더 보기」로 이어 받게 한다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md`
3. `lib/src/presentation/features/asset_lookup/asset_lookup_screen.dart`
4. `lib/src/presentation/features/asset_lookup/asset_lookup_view_model.dart`

## 현재 상태
- 작업 검색 LookupSearchField + debounce ListJobs(commonKey)
- 작업 콤보는 검색 결과만 표시, 필터 줄「더 보기」없음
- 진입 시 ListJobs 선호출 없음

## 바꿀 것
1. 작업 검색 필드·`didChangeJobSearch`·`_searchJobs` 제거.
2. 진입 필터 카탈로그에 ListJobs pageSize 20 복구(장비와 함께, 표와 분리).
3. 작업 콤보 맨아래에「더 보기」항목(센티널). 선택 시 `didTapLoadMoreJobs`만 호출하고 선택 작업은 유지.
4. nextPageToken 없으면「더 보기」행 숨김.

## 유지할 것
- ListAssets 표 우선 로드, pageSize 20
- 종류/후처리/파일/장비/패스/미지정
- 장비 필터 줄「더 보기」없음(첫 페이지만)

## 이번 작업에서 만들지 않음
- ListJobFilters 캐스케이드
- 공통키 검색 필드 재도입

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
