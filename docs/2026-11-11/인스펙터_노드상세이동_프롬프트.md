# 인스펙터 노드 상세 이동

## 목표
타임라인 인스펙터에서 선택한 노드 종류에 맞는 상세 화면으로 아이콘 버튼으로 이동한다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md`
3. `collection_timeline_inspector.dart`
4. `app_coordinator.dart` (lookup·work detail 진입), `remote_collection_catalog_repository.dart` (노드 매핑)

## 현재 상태
- 인스펙터는 정보만 표시한다.
- Coordinator: 장비·작업자·공사(projectId)·에셋·작업상세(`jobId`) 진입이 있다.
- `CollectionPath`는 `project_no`만 있고 `project_id`가 없다. Asset은 매핑에 `contentUrl`만 있고 `assetId`가 없다.
- 품목 전용 상세 진입 API는 없다.

## 바꿀 것
1. `CollectedNode`에 `assetId`(없으면 빈 문자열)를 두고, ListCollectionNodes 매핑에서 `asset.asset_id`를 채운다.
2. 인스펙터 제목 옆에 이동 가능 시 `FluentIcons.red_eye` 아이콘(툴팁은 대상 상세명)을 둔다.
3. 탭 동작:
   - 장비 → `didTapOpenEquipmentDetail(equipmentId)`
   - 작업자 → `didTapOpenWorkerDetail(workerId)`
   - 공사 → `projectNo`로 공사 ID를 찾은 뒤 `didTapOpenProjectDetail(projectId)`
   - 작업(파일 아님) → `didTapOpenWorkDetail(jobId)`
   - 파일(`assetId` 있음) → `didTapOpenAssetDetail(assetId)`
4. 공사 ID 해석은 ViewModel에 `ListProjectLookupUseCase`로 `resolveProjectId`를 둔다(locator 등록 포함).
5. 품목·미지정·필수 ID 없음 → 버튼 숨김.

## 유지할 것
- 인스펙터 필드 목록, 선택 로직, Coordinator 기존 시그니처

## 이번 작업에서 만들지 않음
- 품목 상세 화면·Coordinator API 신설
- 패스/품질/멀티모달 버튼
- CollectionPath proto에 project_id 추가(서버 변경)

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
