# 초기화 시 페이지 셸 유지

## 목표
초기화(및 동일 경로의 조회) 때 **목록만** 다시 불러오고, `CatalogLookupFrame` 전체가 `ProgressRing`/실패 판으로 **언마운트되지 않게** 한다. pending/미적용은 넣지 않는다.

## 원인
- 에셋 `didTapReset`/`didTapQuery`가 `load()`를 호출해 필터 카탈로그까지 다시 받고 초기 로딩 플래그를 켠다.
- 장비·작업자·공사 화면은 `isLoading && visible*`.isEmpty`일 때 본문 전체를 ProgressRing으로 바꾼다. 초기화로 클라이언트 필터가 바뀌면 `visible*`만 비고 서버 목록은 남아 있어도 프레임이 사라진다.

## 바꿀 것
1. 에셋 VM: `didTapQuery` / `didTapReset` → `_reloadListAssets()` (필터 값만 비운 뒤). `load()`는 최초·재시도용으로 유지.
2. 장비·작업자·공사·에셋 화면: 전체 ProgressRing은 **첫 로드 전**만. VM에 `hasLoaded`를 두고, 첫 `_reload`/`load` 완료 후 true. 이후 초기화·조회·필터 재조회는 Frame을 유지한 채 행만 교체.
3. 장비·작업자·공사: ProgressRing 조건을 `visible*` 비움이 아니라 `!hasLoaded && isLoading`으로 맞춤.

## 유지할 것
- 필터 변경 시 기존 자동 재조회.
- `CatalogLookupFilterActions` UI·`didTapQuery`/`didTapReset` 이름.
- 미적용→조회 모델 금지.

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.

- 에셋 초기화 시 장비·작업 콤보 카탈로그를 다시 받지 않음
