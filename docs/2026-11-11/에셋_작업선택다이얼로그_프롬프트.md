# 에셋 작업 선택 다이얼로그

## 목표
작업 필터를 ComboBox「더 보기」가 아니라, 열린 채로 목록을 이어 받고 고를 수 있는 선택 다이얼로그로 바꾼다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md`
3. `lib/src/presentation/features/asset_lookup/asset_lookup_screen.dart`
4. `lib/src/presentation/features/asset_lookup/asset_lookup_view_model.dart` `didTapLoadMoreJobs`

## 현재 상태
- 작업 ComboBox 맨아래 `jobLoadMoreToken`「더 보기」선택 시 팝업이 닫힘
- ListJobs 첫 페이지·이어 받기는 ViewModel에 있음

## 바꿀 것
1. 작업 ComboBox 제거. 필터 줄에는 현재 선택 라벨 + 눌러 다이얼로그를 여는 버튼.
2. ContentDialog: 전체 + 작업 목록 ListView, 하단에「더 보기」(nextToken 있을 때만). 더 보기 시 다이얼로그 유지·목록 갱신.
3. 행 탭 → 해당 jobId로 닫고 `didSelectJob`. 닫기만 하면 선택 유지.
4. `jobLoadMoreToken` 제거.

## 유지할 것
- ListAssets 우선 로드, 장비 콤보, 패스·미지정
- `didTapLoadMoreJobs` / pageSize 20

## 이번 작업에서 만들지 않음
- 공통키 검색 필드, ListJobFilters 캐스케이드
- 장비 선택 다이얼로그화

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
