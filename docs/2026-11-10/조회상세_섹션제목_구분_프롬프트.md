# 조회 상세 섹션 제목을 구분선으로 분명히 나눈다

## 목표
에셋 상세(및 같은 제목을 쓰는 조회 상세)에서 섹션 제목이 구분선·여백으로 분명히 나뉜다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md` (가이드라인 저장소는 워킹 트리 밖에서 읽기만)
3. `lib/src/presentation/core/widgets/lookup_detail_scaffold.dart`
4. `lib/src/presentation/features/asset_lookup/asset_lookup_detail_screen.dart`
5. 없음

## 현재 상태
- `LookupDetailSectionTitle`은 top 20·bottom 8 패딩과 굵기 14 텍스트만 있어 「후처리」「정보」「붙은 작업」이 한 덩어리처럼 보인다.
- 에셋 상세의 「주제·상황」은 별도 카드라 상대적으로만 구분된다.

## 바꿀 것
1. `LookupDetailSectionTitle`에 위쪽 hairline 구분선과 top 여백을 키운다. 제목 아래 bottom 여백은 유지한다.
2. trailing은 기존처럼 제목 옆에 둔다.
3. `asset_lookup_detail_screen` 등 호출부는 API 그대로 두고 공통 스타일만 받는다.

## 유지할 것
- 「주제·상황」카드·KV/표/Expander 내용·섹션 순서
- 다른 lookup detail의 `LookupDetailSectionTitle` 호출 방식

## 이번 작업에서 만들지 않음
- 섹션 전체를 카드로 감싸기
- 새 디자인 시스템·아이콘 장식
- 화면별 전용 제목 위젯

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
