# 패스 표 기능 열을 오른쪽 끝에 고정한다

## 목표
패스 표 「기능」열이 첨부 표처럼 행 오른쪽 끝에 붙는다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md` (가이드라인 저장소는 워킹 트리 밖에서 읽기만)
3. `lib/src/presentation/features/job_lookup/widgets/job_pass_tab.dart`
4. `lib/src/presentation/features/job_lookup/widgets/job_attachment_tab.dart` (기능 열 고정폭 패턴)
5. 없음

## 현재 상태
- 패스 표 기능 열이 `Expanded(flex: 1)`라 남는 폭을 나눠 먹고, 버튼이 열 안 왼쪽에 붙는다.
- 첨부 표 기능 열은 고정폭 `SizedBox(width: 72)`로 행 끝에 있다.

## 바꿀 것
1. 기능 열을 `Expanded` 대신 고정폭(`SizedBox`, 첨부와 같은 72)으로 둔다.
2. 패스·시작·종료만 `Expanded`로 두고, 헤더 flex와 동일하게 맞춘다.
3. 헤더 「기능」열도 같은 고정폭으로 맞춘다.

## 유지할 것
- 수정·지우기 동작, 카드/보더 스타일, 첨부 탭 코드

## 이번 작업에서 만들지 않음
- 공통 테이블 위젯 추출
- 첨부 표 수정
- 열 비율 재설계(패스·시작·종료 flex는 현재 헤더 기준 유지)

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
