# 작업 이력 행에 멀티모달 액션을 넣고 기능 열 UI를 다듬는다

## 목표
작업 이력 행에서 「멀티모달」로 바로 들어가고, 행 액션이 기본 Button 나열이 아닌 제품형 기능 열로 보인다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md` (가이드라인 저장소는 워킹 트리 밖에서 읽기만)
3. `lib/src/presentation/features/work_history/widgets/work_history_table.dart`
4. `lib/src/presentation/navigation/app_coordinator.dart` (`didTapOpenVideoMultimodal`)
5. 없음

## 현재 상태
- 행 액션이 `Wrap` 안의 기본 `Button`(상세·프로파일·품질) 세 개다.
- 멀티모달은 작업 상세 CommandBar에서만 열고, `didTapOpenVideoMultimodal`은 이미 잡힌 `_jobId`만 쓴다.
- 우클릭 메뉴에도 상세·프로파일·품질만 있다.

## 바꿀 것
1. 행 액션을 아이콘+툴팁 기능 열로 통일한다(상세·프로파일·품질·멀티모달).
2. 멀티모달은 `canAccessVideoMultimodal`일 때만 표시한다.
3. `didTapOpenVideoMultimodal`에 `jobId`를 받아 목록에서도 열리게 한다.
4. 우클릭 메뉴에도 멀티모달을 같은 조건으로 추가한다.
5. 헤더 빈 칸을 「기능」으로 표기한다.

## 유지할 것
- 행 선택·스크롤 더 불러오기
- 프로파일·품질·상세 기존 네비 스택
- 작업 상세 CommandBar의 멀티모달 버튼(제거하지 않음)

## 이번 작업에서 만들지 않음
- NavigationPane 단독 메뉴
- 작업 상세 본문 CTA
- 새 디자인 시스템·공통 액션 위젯 추출(필수 아니면)

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
