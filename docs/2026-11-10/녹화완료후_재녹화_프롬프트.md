# 녹화 업로드 완료 후 재녹화

## 목표
영상·음성 타임라인 저장이 모두 끝나면 카메라를 다시 준비해, 곧바로 「시작」으로 다음 녹화를 할 수 있게 한다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md`
3. `lib/src/presentation/features/video_multimodal/camera_recording_view_model.dart`
4. `test/screen_comment_test.dart`
5. 계약·화면안: 없음

## 현재 상태
- `didFinishAssetUpload` 성공 후에도 `phase`는 `stopped`, `recording`·업로드 플래그가 남는다.
- `canStart`는 stopped에서도 true이지만, 브라우저 MediaRecorder/스트림이 한 번 녹화 뒤 깨진 채로 남아 `start`가 실패할 수 있다.
- `prepare()`는 컨트롤러를 다시 초기화하고 ready로 돌린다.

## 바꿀 것
1. `didFinishAssetUpload`에서 영상·음성 모두 성공(`didFinish`)이면 `onUploadCompleted` 호출 뒤 `prepare()`를 호출해 다음 녹화 준비를 한다.
2. `prepare()`가 ready면 안내를 「타임라인에 올렸습니다… 다시 녹화하려면 시작을 누르세요.」처럼 완료 문구 + 재시작 안내로 맞춘다. prepare 실패면 기존 prepare 오류 문구를 쓴다.
3. 일부만 올린 경우·실패 시에는 prepare를 부르지 않는다.
4. `test/screen_comment_test.dart`는 IdleCamera로 prepare가 성공하므로, 완료 후 ready·재시작 안내를 검증하도록 맞춘다.

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
