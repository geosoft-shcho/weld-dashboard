# 녹화 업로드 → 에셋 올리기 다이얼로그 공통

## 목표
`_CameraRecordingCard`에서 주제·상황·장비 입력을 없애고, **녹화 파일 업로드** 클릭 시 에셋 올리기 다이얼로그를 공통으로 연다. 첨부 목록은 방금 녹화한 영상·음성으로 채운다. 다이얼로그가 metadata·업로드·후처리를 담당하고, 성공 후 녹화 쪽은 타임라인 배치·CreateComment만 한다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md`
3. `lib/src/presentation/features/asset_lookup/asset_upload_dialog.dart`
4. `lib/src/presentation/features/video_multimodal/widgets/camera_recording_dialog.dart`
5. `lib/src/presentation/features/video_multimodal/camera_recording_view_model.dart`
6. `lib/src/presentation/features/asset_lookup/asset_lookup_screen.dart`
7. 계약·화면안: 없음

## 현재 상태
- 에셋 조회: `showAssetUploadDialog` + `uploadAssetQueue`로 metadata·다건 업로드.
- 녹화: 카드에 주제·상황·장비 필드 + `uploadFile` 직접 호출 후 배치·코멘트.
- 다이얼로그는 `initialFiles`가 없어 항상 파일 고르기로만 줄을 추가한다.

## 바꿀 것
1. `showAssetUploadDialog`에 `initialFiles`, `initialTimeOrigin`, `filesLocked`를 추가한다.
2. `filesLocked == true`이면 파일 고르기 숨김·행 삭제 금지.
3. 녹화 카드에서 주제·상황·장비 입력을 제거하고, 업로드 시 다이얼로그를 연다.
4. ViewModel은 `didFinishAssetUpload`로 배치·코멘트만 이어 간다. 직접 uploadFile/후처리 폴링 제거.
5. 테스트는 새 API에 맞춘다.

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
