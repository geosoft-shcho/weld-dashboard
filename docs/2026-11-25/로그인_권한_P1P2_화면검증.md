# (2026-11-25) 로그인·권한 P1+P2 화면 검증

| 항목 | 값 |
|------|-----|
| 근거 | [`README.md`](../2026-11-23/README.md) §2, [`로그인_권한_P1P2_프롬프트.md`](./로그인_권한_P1P2_프롬프트.md) |
| API | `AuthService.ChangePassword`, `AccountService` (Accounts · Roles · Permissions · ServiceTokens) |
| 화면 | 셸 타이틀바 · 계정 그룹(계정 관리 · 권한 관리 · 서버 연동 토큰) |
| 권한 | 계정 그룹은 `account.manage`일 때만 |

이 문서는 **지금 앱에서 손으로 검증하는 절차**다. 코드를 고치지 않는다.

---

## 1. 화면에서 무엇이 보이는지

```text
[타이틀바 오른쪽]
  표시이름   [비밀번호 변경]  [로그아웃]

[왼쪽 셸 — account.manage 있을 때만]
  …관리(공사·작업자·…)
  계정
    계정 관리
    권한 관리
    서버 연동 토큰
```

| UI | 동작 |
|----|------|
| 비밀번호 변경 | ContentDialog: 현재 / 새 / 확인 → `ChangePassword` |
| 계정 관리 | 목록 + 새 계정 · 고치기(이름·역할·inactive·비번 재설정) |
| 권한 관리 | 목록 + 새 역할 · 고치기(권한 체크) · 지우기 |
| 서버 연동 토큰 | 목록 + 발급(원문 1회) · 폐기 |

---

## 2. 검증 준비

1. MediaTag 서버에 관리자 계정(`account.manage`)과, 가능하면 **관리 권한이 없는** 계정이 각각 있는지 확인한다.
2. 앱을 띄운다. localhost면 Login 응답 **Bearer**로 RPC가 가는지 Network에서 확인한다(쿠키 `include`는 CORS `*`와 충돌하므로 쓰지 않음).
3. Chrome DevTools → Network에서 `ChangePassword` · `ListAccounts` · `ListRoles` · `ListPermissions` · `CreateServiceToken` 등을 필터할 수 있게 둔다.
4. (선택) 같은 계정으로 브라우저 탭을 하나 더 열어 둔다 — 비밀번호 변경 후 다른 세션 끊김 확인용.

## 3. 시나리오별 검증

### A. 로그인 · 셸 기본

| 단계 | 조작 | 기대 |
|------|------|------|
| A1 | 앱 진입(세션 없음) | 로그인 Overlay |
| A2 | 올바른 아이디·비밀번호로 로그인 | 셸 진입, 타이틀바에 표시이름(없으면 login_name) |
| A3 | 로그아웃 | 로그인 Overlay로 돌아감 |
| A4 | 틀린 비밀번호 / 없는 아이디 | 같은 실패 문구(어느 쪽인지 구분하지 않음) |
| A5 | (가능하면) 같은 아이디로 5번 연속 실패 | 1분 막힘 안내(`ResourceExhausted`) |

### B. 비밀번호 변경 (P1)

| 단계 | 조작 | 기대 |
|------|------|------|
| B1 | **비밀번호 변경** | 다이얼로그(현재·새·확인) |
| B2 | 현재 비번 비우고 변경 | 「현재 비밀번호를 넣으세요」 |
| B3 | 새 비번 ≠ 확인 | 「새 비밀번호 확인이 같지 않습니다」 |
| B4 | 새 비번 7바이트 이하 또는 73바이트 초과 | 「8~72바이트」 안내 |
| B5 | 현재 비번 틀리고 변경 | 「현재 비밀번호가 올바르지 않습니다」(`PermissionDenied`) |
| B6 | 올바른 값으로 변경 성공 | 「다른 세션은 끊깁니다 … 다시 로그인」 안내 |
| B7 | 안내에서 **확인** | 로그아웃 후 **로그인 화면** |
| B8 | (선택) 다른 탭에서 이후 RPC | 401 → 로그인 화면(세션 끊김) |

### C. account.manage 메뉴 노출 (P2)

| 단계 | 조작 | 기대 |
|------|------|------|
| C1 | `account.manage` **있는** 계정으로 로그인 | 셸에 **계정** 그룹(계정·역할·토큰) 보임 |
| C2 | `account.manage` **없는** 계정으로 로그인 | 계정 그룹 **없음** |
| C3 | 권한 없는 계정에서 URL `/#/accounts` (또는 roles · service-tokens) 직접 진입 | 수집 모니터링으로 되돌림(또는 메뉴 없이 진입 거부) |
| C4 | 관리자에서 계정 관리 → 로그아웃 → 비관리자로 로그인 | 계정 메뉴 사라짐 |

### D. 계정 관리

| 단계 | 조작 | 기대 |
|------|------|------|
| D1 | 계정 관리 열기 | `ListAccounts` · 목록(아이디·이름·역할·상태) |
| D2 | **+ 새 계정** — login_name · display_name · role · password(8~72) | 생성 후 목록에 나타남 |
| D3 | 같은 login_name으로 다시 만들기 | AlreadyExists 계열 오류 안내 |
| D4 | 다른 계정 **고치기** — 표시 이름 · 역할 · 막기 · 비번 재설정 | 저장 후 목록 반영 |
| D5 | **자기 계정** 포함 모든 계정 고치기 | `account.manage`면 역할·막기·이름·비번 재설정 가능 |
| D6 | 자기 계정 역할·막기 저장 시 서버가 거절하면 | FailedPrecondition 등 오류 InfoBar |
| D7 | 다른 계정을 inactive로 저장 | 상태 「막힘」, 그 계정으로 로그인 불가 |

### E. 권한 관리

| 단계 | 조작 | 기대 |
|------|------|------|
| E1 | 권한 관리 열기 | `ListRoles` · 권한 수 표시 |
| E2 | **+ 새 역할** — 이름 · 설명 · `ListPermissions` 체크 | 생성 후 목록에 나타남 |
| E3 | 역할 **고치기** — 권한 통째로 변경 후 저장 | 그 역할 계정은 다음 요청부터 권한 반영(메뉴 유무 등) |
| E4 | 계정이 쓰는 역할 **지우기** | FailedPrecondition 안내(계정 역할 먼저 변경) |
| E5 | 쓰는 계정 없는 역할 지우기 | 목록에서 사라짐 |
| E6 | (주의) 자기 역할에서 `account.manage` 제거 시도 | 서버 FailedPrecondition — 오류 문구 확인 |

### F. 서버 연동 토큰

| 단계 | 조작 | 기대 |
|------|------|------|
| F1 | 서버 연동 토큰 열기 | 목록(이름·만든 시각·마지막 사용·상태). **원문 없음** |
| F2 | **+ 토큰 발급** — 이름 입력 | 다이얼로그에 **원문 한 번만** + 복사 가능 |
| F3 | 발급 다이얼로그 닫은 뒤 목록만 다시 봄 | 원문이 다시 나타나지 않음 |
| F4 | 살아 있는 토큰 **폐기** | 상태 「폐기」, 이후 그 토큰으로 내부 호출 시 401(서버 정책) |
| F5 | 이미 폐기된 행 | 폐기 버튼 없음(「—」) |

### G. 회귀 · 연동 스모크

| 단계 | 조작 | 기대 |
|------|------|------|
| G1 | 관리자 로그인 후 수집 모니터링 · 공사/파일 목록 조회 | 기존 조회 정상(Bearer 또는 동일 출처 쿠키) |
| G2 | 로그인 직후 새로고침(F5) | `GetCurrentAccount`로 세션 복원 → 셸 유지(토큰 prefs 있을 때) |
| G3 | prefs/토큰 지운 뒤 새로고침 | 로그인 Overlay |
| G4 | 공사·작업자·장비·작업·파일 상세의 작성자/수정자 칸 | 값 없으면 「시스템」(1차 작성자 표시 유지) |

## 4. 통과 기준 (체크)

- [ ] A 로그인·로그아웃·실패 문구
- [ ] B 비밀번호 변경 검증·성공·(선택) 타 세션 끊김
- [ ] C `account.manage`일 때만 계정 메뉴 / URL 직접 진입 차단
- [ ] D 계정 CRUD·역할·막기(자기 계정 포함)·inactive
- [ ] E 역할 CRUD·권한 체크·삭제 제약
- [ ] F 토큰 발급 원문 1회·폐기

하나라도 실패하면 이 문서에 재현 단계·Network RPC·응답 코드만 짧게 남기고 수정 요청한다.
