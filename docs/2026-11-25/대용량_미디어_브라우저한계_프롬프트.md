# 대용량 미디어 브라우저 한계 UX

## 목표
약 2GB mkv처럼 브라우저 메모리로 통째로 받을 수 없는 `/api/files`는 미리보기·내려받기를 시도하지 않고, 사용자에게 용량 한계를 분명히 안내한다.

## 권장 표시
- 미리보기: 「브라우저에서 미리볼 수 없습니다. 파일이 너무 큽니다(약 X).」
- 내려받기: InfoBar로 「브라우저로는 이 크기(약 X) 파일을 받을 수 없습니다.」
- 임계값: Web in-memory 100MB (`sizeBytes` 또는 Range 프로브)

## 바꿀 것
1. `MediaTagDataSource.probeContentLength` + `authenticated_media` 공통 검사·문구
2. blob 재생·`downloadBrowserUrl`이 임계값 초과 시 전체 fetch 전에 중단
3. Asset 미리보기·내려받기 버튼이 `sizeBytes`/결과로 안내 UI 표시

## 이번 작업에서 만들지 않음
- 서버 스트리밍·mp4 변환
- Range 재생 플레이어

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
