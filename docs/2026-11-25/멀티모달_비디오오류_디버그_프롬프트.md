# 멀티모달 비디오 재생 오류 디버그

## 목표
[`multimodal_video_player.dart`](lib/src/presentation/features/video_multimodal/widgets/multimodal_video_player.dart)에서 `initialize` 실패 시 `_errorText`만으로는 원인 파악이 어렵다. **임시 디버그 로그·화면 메타**를 넣어 재생 실패 URL과 예외를 확인하고, 원인 후보를 짧게 기록한다. 재생 자체 수정(Bearer 헤더·프록시)은 이번 범위 밖이다.

## 먼저 읽을 것
- [`multimodal_video_player.dart`](lib/src/presentation/features/video_multimodal/widgets/multimodal_video_player.dart) `_open` 152–204행, build 오류 UI 484–489행
- [`media_tag_data_source.dart`](lib/src/data/datasources/remote/media_tag_data_source.dart) `resolveContentUrl`
- [`로그인_권한_남은작업.md`](docs/2026-11-23/로그인_권한_남은작업.md) — 영상 태그는 Bearer 불가·교차 출처 프록시 미완

## 현재 상태
- `mediaUrl`은 클립 `playbackUrl` → `resolveContentUrl(contentUrl)`로 만든 **절대 HTTP(S) URL**.
- `_open`은 `VideoPlayerController.networkUrl(Uri.parse(source))` 후 `initialize()`; catch에서만 `_errorText = error.toString()` 설정. **console 로그 없음**, URL·`VideoPlayerValue.hasError`/`errorDescription` 미출력.
- Web `<video>`는 Authorization 헤더를 못 붙인다. RPC는 Bearer로 우회 중이라, 서버가 content에 쿠키/세션을 요구하면 initialize가 401/CORS로 실패할 가능성이 문서에 이미 적혀 있다.
- 터미널(`flutter run`)에는 아직 「비디오를 열 수 없습니다」 본문/URL이 안 찍혀 있음 — 재현 후 DevTools·콘솔로 확인 필요.

## 바꿀 것

### 1. `_open` catch 디버그
[`multimodal_video_player.dart`](lib/src/presentation/features/video_multimodal/widgets/multimodal_video_player.dart) `initialize` catch에서:

- `debugPrint`로 남긴다: `source`(mediaUrl), `error`, `StackTrace`, 가능하면 `videoController.value.hasError` / `errorDescription`.
- `_errorText`에 사용자용 한 줄 + 디버그용 URL 호스트·경로(쿼리 시크릿 있으면 잘라)를 넣는다. 예: `error.toString()` + `\nURL: …` (토큰 쿼리는 마스킹).

### 2. 오류 UI 가독성
같은 파일 build의 오류 `Text`에 `softWrap`/`textAlign`/`style`(밝은 글자)만 보강해 긴 `_errorText`가 보이게 한다. 새 위젯·팩토리 없음.

### 3. 확인 절차 (구현 후 Agent가 재현 안내)
1. hot reload 후 멀티모달에서 실패 클립 재진입.
2. Chrome DevTools Console의 `MultimodalVideoPlayer` debugPrint와 Network의 content URL 상태(401/CORS/404)를 본다.
3. 원인 한 줄로 채팅에 보고한다. **프록시·httpHeaders 수정은 이 작업에서 하지 않는다** (P5/별도 프롬프트).

### 문서
- 확인된 프롬프트를 `docs/2026-11-25/멀티모달_비디오오류_디버그_프롬프트.md`로 저장 후 구현.

## 복잡한 코드 제거 및 금지
- 새 로거·에러 리포터·추상 계층을 만들지 않는다. `debugPrint` + 기존 `_errorText`만 쓴다.
- `VideoPlayerController.networkUrl`에 Bearer/`httpHeaders` 추가·동일 출처 프록시·CORS 서버 수정은 하지 않는다.
- `work_detail_chewie_stage` 등 다른 플레이어·범위 밖 리팩터 금지.
- generated proto 수정 금지.
