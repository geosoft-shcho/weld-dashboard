# 파형 컨트롤 툴바 (A안)

## 목표
패스·품질 화면에서 비교 작업과 범례를 한 `WaveformControlToolbar` 패널로 묶어, 차트 위 컨트롤이 한 덩어리로 보이게 한다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `lib/src/presentation/core/widgets/comparison_job_normalize_bar.dart`
3. `lib/src/presentation/core/widgets/pass_legend_toolbar.dart`
4. `pass_profile_screen.dart` / `quality_issue_screen.dart` ready ListView

## 현재 상태
- 비교 줄과 범례 줄이 ListView에 각각 있어 세로로 끊긴다.
- UI 위젯은 이미 core에 분리돼 있다.

## 바꿀 것
1. `lib/src/presentation/core/widgets/waveform_control_toolbar.dart`
   - SURFACE_RAISED 패널 안에 위: 비교·파형 기준, 아래: 범례.
   - notice / comparisonError는 패널 하단(범례 아래)에 모은다.
   - `ComparisonJobNormalizeBar`·`PassLegendToolbar`를 조합만 한다(로직 복제 없음).
2. `ComparisonJobNormalizeBar`에 상태 메시지 표시를 끄는 인자(`includeStatus`, 기본 true)를 두어 툴바 안에서 중복 표시하지 않는다.
3. 패스·품질 ready ListView: `_NormalizeCombo`/`_QualityComparisonJob` + Legend 섹션을 `_…WaveformToolbar` 한 섹션으로 교체.

## 유지할 것
- ViewModel API·범례 empty 조건·quality notice·pass mastersForPass

## 이번 작업에서 만들지 않음
- ViewModel 공통화, `_LegendSelection` 통합, 도메인 변경

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
