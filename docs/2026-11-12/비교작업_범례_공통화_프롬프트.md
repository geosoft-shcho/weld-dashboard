# 비교 작업·범례 공통화

## 목표
비교 작업·파형 기준 줄을 presentation core 공유 위젯으로 두고 패스/품질이 참조한다. 범례 툴바는 `core/widgets`로 옮겨 두 화면이 같은 공유 경로를 쓰게 한다. ViewModel·도메인 로직은 합치지 않는다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. 가이드라인(워킹 트리 밖) — shared UI는 `presentation/core/widgets`
3. `pass_profile_screen.dart` `_NormalizeCombo` / `_PassLegendSection`
4. `quality_issue_screen.dart` `_QualityComparisonJob` / `_QualityLegendSection`
5. `pass_profile/widgets/pass_legend_toolbar.dart`

## 현재 상태
- `_NormalizeCombo`와 `_QualityComparisonJob`는 비교 작업 Combo + 파형 기준 + comparisonError가 동일. quality만 `waveformNotice` InfoBar.
- `_comparisonJobLabel` / `_comparisonKey` 복제.
- `PassLegendToolbar`는 이미 공유되나 `pass_profile/widgets`에 있음.

## 바꿀 것
1. `lib/src/presentation/core/widgets/comparison_job_normalize_bar.dart` 추가
   - props: `jobs`, `selectedJobId`, `normalize`, `comparisonError`, `notice`(기본 `''`), `onOpenJobs`, `onSelectJob`, `onSelectNormalize`
2. 패스/품질 화면에서 해당 위젯 참조. 중복 라벨·키 헬퍼 제거(select용 키는 화면에서 props 조합)
3. `pass_legend_toolbar.dart`를 `lib/src/presentation/core/widgets/`로 이동. 섹션은 얇은 바인딩 유지
4. `_LegendSelection`은 화면별로 유지

## 유지할 것
- 각 ViewModel의 비교/정규화/범례 토글
- quality `waveformNotice`
- pass 명장 프로파일 Combo

## 이번 작업에서 만들지 않음
- ViewModel 공통 베이스/믹스인
- `_LegendSelection` 통합 타입
- 도메인·use case 변경

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
