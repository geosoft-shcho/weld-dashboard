# 녹화 업로드 → 녹화 영상/음성 트랙 클립 보장

## 목표
카메라 녹화 파일 업로드 후 영상·음성 각각이 `녹화 영상` / `녹화 음성` 트랙에 클립으로 남게 한다. 서버가 `video`/`audio` 등 다른 트랙에 먼저 놓아도 녹화 전용 트랙으로 맞춘다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md` (가이드라인 저장소는 워킹 트리 밖에서 읽기만)
3. `lib/src/presentation/features/video_multimodal/video_multimodal_view_model.dart` (`didPlaceUploadedRecording`, `_hasAssetClip`, `_ensureTrackId`, `updateTimelineClip`, `createTimelineClip`)
4. `lib/src/presentation/features/video_multimodal/camera_recording_view_model.dart` (`_placeUploaded`)
5. `lib/src/presentation/features/video_multimodal/video_multimodal_screen.dart` (콜백 연결)
6. `test/ask_question_test.dart` (녹화 배치 관련 테스트)
7. 없음 (별도 계약·화면안 없음; 트랙 이름은 기존 상수 유지)

## 현재 상태
- 멀티모달 화면은 `onRecordingPlaced` → `didPlaceUploadedRecording`을 연결한다.
- `didPlaceUploadedRecording`은 타임라인 재조회 후 `_hasAssetClip(assetId)`가 참이면 **즉시 return**한다. 같은 asset이 `video`/`audio` 등 다른 트랙에만 있어도 스킵된다.
- 스킵되지 않을 때만 `녹화 영상`/`녹화 음성`을 `_ensureTrackId`로 만들고 playhead 기준으로 `createTimelineClip`한다.
- `createTimelineClip`/`updateTimelineClip` 실패는 bool·hint로만 남고, `didPlaceUploadedRecording`은 예외를 던지지 않아 카메라 업로드 UI에 “타임라인 배치 실패”가 잘 안 보인다.
- 테스트: 빈 타임라인 → `녹화 영상` 생성; 이미 아무 트랙에나 있으면 재배치하지 않음(현 증상과 같은 가드).

## 바꿀 것
1. `didPlaceUploadedRecording`의 전역 `_hasAssetClip` 조기 return을 제거·교체한다. 흐름은 다음과 같다.
   - `녹화 영상`(isVideo) 또는 `녹화 음성`(!isVideo) 트랙 id를 `_ensureTrackId`로 확보한다(없으면 생성).
   - 해당 **녹화 트랙**에 이미 같은 `assetId` 클립이 있으면 아무 것도 하지 않고 끝낸다.
   - 같은 `assetId` 클립이 **다른 트랙**에만 있으면 `updateTimelineClip`으로 `trackId`를 녹화 트랙으로 옮긴다. 시작·끝·소스 구간은 기존 클립 값을 유지한다.
   - 클립이 없으면 기존과 같이 playhead·duration(없으면 5초)으로 `createTimelineClip`한다. kind는 video/audio.
2. `_hasAssetClip`을 트랙 한정 조회로 쓰거나, 녹화 배치 전용 private 헬퍼로 대체한다. 인용 피드백 등 다른 호출부는 깨지지 않게 한다(`_hasAssetClip`이 녹화에만 쓰이면 시그니처를 바꿔도 된다).
3. 트랙 확보·클립 생성·이동이 실패하면(`createTimelineTrack`/`createTimelineClip`/`updateTimelineClip`이 false이거나 타임라인 재조회 실패) `JobTimelineException` 또는 명확한 예외를 throw해 `_placeUploaded` catch → 카메라 안내 `타임라인 배치 실패`에 보이게 한다. 조용한 early return으로 성공처럼 보이게 두지 않는다. assetId 빈 값만 기존처럼 무시한다.
4. `test/ask_question_test.dart`를 새 규칙에 맞게 고친다.
   - 빈 타임라인 → `녹화 영상` + 클립(기존 유지).
   - 다른 트랙(`video`/`audio`/`서버` 등)에만 있던 asset → `녹화 영상`(또는 음성) 트랙으로 **이동**되고, 그 트랙 이름이 생긴다.
   - 이미 `녹화 영상`에 있으면 추가 생성·이동 없음.
   - 가능하면 audio(`녹화 음성`) 한 케이스도 넣는다.
5. 멀티모달 콜백 연결·업로드 API·TUS·playhead 기본 배치 공식(신규 생성 시)은 유지한다. pass_profile/quality의 `CameraRecordingScope` 스텁은 이번 범위 밖이다.

## 유지할 것
- `RECORDING_VIDEO_TRACK_NAME` / `RECORDING_AUDIO_TRACK_NAME` 상수 문자열
- 업로드 → postprocess → `onRecordingPlaced` 호출 순서
- 수동 드롭(`didDropAsset`)·인용 피드백 트랙 로직
- 서버 CreateClip/UpdateClip/CreateTrack use case 자체

## 이번 작업에서 만들지 않음
- 서버 자동 배치(postprocess) 로직·proto 변경
- `video`/`audio` 트랙 삭제·이름 변경 일괄 정리
- pass_profile / quality_issue 녹화 스코프 연결
- 신규 클립 시각을 `recorded_at` 기준으로 바꾸는 작업(이동 시에는 기존 구간 유지)
- Assets Import, 로컬 다운로드 재도입

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.

## 완료 확인
- 녹화 업로드 후 `녹화 영상`·`녹화 음성` 트랙이 보이고, 각각에 video/audio 클립이 있다.
- 서버가 먼저 `video`/`audio`에 놓아도 최종적으로 녹화 전용 트랙에 클립이 있다(이동).
- 이미 녹화 전용 트랙에 있으면 중복 클립이 생기지 않는다.
- 배치 실패 시 카메라 패널에 실패 안내가 보인다.
- 관련 단위 테스트가 새 규칙과 맞는다.
