# 조회 실패 메시지 중앙 표시

## 목표
페이지 본문을 대체하는 조회 실패 `InfoBar`가 화면 왼쪽 위에 붙지 않고, 로딩 `ProgressRing`과 같이 **콘텐츠 영역의 중앙**에 보이도록 한다. 재시도 동작과 문구는 유지한다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md` (가이드라인 저장소는 워킹 트리 밖에서 읽기만)
3. `lib/src/presentation/features/worker_lookup/worker_lookup_screen.dart` (대표: 본문 전체를 InfoBar로 교체)
4. `lib/src/presentation/features/work_detail/work_detail_screen.dart` (`_banner` = topLeft Align)
5. `lib/src/presentation/core/widgets/placeholder_page.dart`
6. 없음 (별도 계약·화면안 없음)

## 현재 상태
- 목록·상세·이력·수집 모니터링 등 다수 화면이 `hasError`일 때 `InfoBar`만 return한다. 부모는 `Padding`뿐이라 InfoBar가 **콘텐츠 상단 왼쪽**에 붙는다.
- 같은 화면의 로딩은 `Center(child: ProgressRing())`로 **중앙**이다. 실패만 위치가 어긋난다.
- `work_detail_screen`은 `_banner`로 `Align(alignment: Alignment.topLeft)`라 더 위에 붙는다.
- `pass_profile` / `quality_issue`의 페이지 모드 error 위젯도 동일하게 맨 위 InfoBar다.
- `video_multimodal_screen`은 툴바 아래 **상단 배너**로 두고 아래 본문을 유지한다(부분 실패). 이 패턴은 페이지 전체 교체가 아니다.
- 로그인 폼·준비된 화면 안의 부차 InfoBar(시간 범위 오류, 파형 조회 실패 등)는 본문 상단 인라인이 맞다.

## 바꿀 것
1. `lib/src/presentation/core/widgets/query_failure_pane.dart`에 공통 위젯을 둔다.
   - `Center` + `ConstrainedBox(maxWidth: 520)` + `InfoBar`(error).
   - 인자: `title`, `message`, 선택 `onRetry`, `retryLabel`(기본 `재시도`).
2. **본문 전체를 조회 실패 InfoBar로 바꾸는** 화면만 `QueryFailurePane`으로 교체한다.
   - worker/equipment/project/asset 목록·상세
   - job_lookup_detail
   - work_history, collection_monitoring, work_detail(조회 실패 분기; `_banner` 제거 가능하면 제거)
   - pass_profile `_PassProfileError`, quality_issue `_QualityIssueError`
   - `placeholder_page` 조회 실패
3. 기존 title/message/재시도 콜백·라벨은 화면마다 그대로 넘긴다.

## 유지할 것
- ViewModel의 `hasError` / `errorMessage` / load·reload 호출
- `video_multimodal` 상단 배너 + 본문 유지 패턴
- 로그인·필터 경고·파형/패스 부분 실패 등 **인라인** InfoBar
- CatalogLookupFrame·테이블 레이아웃, 로딩 Center

## 이번 작업에서 만들지 않음
- 에러 문구·재시도 정책 변경
- 빈 목록/빈 상세 경고 InfoBar 중앙화(조회 실패만)
- 새 디자인 시스템·토스트·다이얼로그
- video_multimodal 실패 UX 변경

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.

## 완료 확인
- 작업자 조회 등 목록에서 조회 실패 시 InfoBar가 콘텐츠 **중앙**에 보인다.
- 상세·작업 이력·수집 모니터링·패스/품질 페이지 모드 error도 동일하다.
- 재시도 버튼이 기존과 같이 동작한다.
- 멀티모달 타임라인 실패는 기존처럼 상단 배너다.
