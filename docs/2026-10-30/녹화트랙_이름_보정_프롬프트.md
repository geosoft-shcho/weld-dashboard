# 녹화 트랙 이름 보정 (`- · video` → 녹화 영상)

## 목표
카메라 녹화 업로드 후 서버가 만든 `- · video` / `- · audio` 트랙을 `녹화 영상` / `녹화 음성`으로 맞춘다. 같은 이름의 빈 트랙을 새로 만들지 않는다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md`
3. `docs/2026-10-19/공사·작업·패스 관리와 업로드 안내.md` (트랙 이름 `장비 · 자료 계열`)
4. `lib/src/data/repositories/remote_asset_upload_repository.dart` (`upload` → `equipmentId: ''`)
5. `lib/src/presentation/features/video_multimodal/video_multimodal_view_model.dart` (`didPlaceUploadedRecording`, `_ensureTrackId`)
6. `test/ask_question_test.dart`
7. 없음

## 현재 상태
- 서버 후처리 자동 배치 트랙 이름은 `장비 · video|audio|…`. 장비가 없으면 `- · video` / `- · audio`.
- 카메라 업로드는 `equipmentId: ''`로 올린다.
- 클라이언트는 별도로 `녹화 영상`/`녹화 음성`을 CreateTrack 한다 → 이름 불일치·중복 트랙.

## 바꿀 것
1. 녹화 배치 시 트랙 확보: 이름이 정확히 `녹화 영상`/`녹화 음성`이면 그대로 쓴다.
2. 없으면 이름이 정확히 `- · video` / `- · audio`인 트랙을 `UpdateTrack`으로 `녹화 영상`/`녹화 음성`으로 바꾼 뒤 그 id를 쓴다. (`앞 카메라 · video` 같은 장비 트랙은 건드리지 않는다.)
3. 그래도 없으면 기존처럼 CreateTrack(`녹화 영상`/`녹화 음성`).
4. playhead 배치·클립 이동 규칙은 유지한다.
5. 테스트: `- · video`만 있는 타임라인에서 배치 후 트랙 이름이 `녹화 영상`이 되고 CreateTrack 이름이 비는지(또는 rename만 하는지) 확인.

## 유지할 것
- playhead 구간 배치
- CreateClip / UpdateClip 흐름
- 일반 에셋 업로드의 equipmentId 선택 UI

## 이번 작업에서 만들지 않음
- 서버 자동 배치·트랙 이름 규칙 변경
- 카메라 업로드에 장비 선택 UI 추가
- `앞 카메라 · video` 등 장비 트랙 일괄 이름 변경

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
