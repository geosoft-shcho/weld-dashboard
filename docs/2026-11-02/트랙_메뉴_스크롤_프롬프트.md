# 트랙 메뉴 영역 내 스크롤

## 목표
트랙 메뉴가 열렸을 때 항목이 많아도 보드를 넘치지 않고, 메뉴 박스 안에서만 세로 스크롤로 트랙 목록을 볼 수 있게 한다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md`
3. `lib/src/presentation/features/video_multimodal/widgets/multimodal_timeline_board.dart` (`_trackMenu` 568–619)
4. 계약·화면안: 없음

## 현재 상태
- `_trackMenu`는 `Positioned(right: 12, top: 36)` + `Material` + `Padding` + `Column(mainAxisSize: min)`로 트랙 전 항목을 그린다.
- 높이 제한·`ScrollView`가 없어 트랙이 많으면 보드 밖으로 늘어난다.
- 체크 토글(`didTapToggleTrackVisibility`)·메뉴 열기(`didTapToggleTrackMenu`) 로직은 ViewModel에 있다.

## 바꿀 것
1. `_trackMenu`의 목록을 `ConstrainedBox` + `SingleChildScrollView`로 감싼다.
   - `maxHeight`는 보드 안 남는 공간에 맞춘다: `LayoutBuilder` 또는 부모 `Stack`에서 쓸 수 있으면 보드 높이 기준, 아니면 고정값으로 **보드 높이의 약 70% / 최소 120·최대 320 근처**처럼 메뉴가 툴바 아래·보드 안에 머물게 한다. 구현 시 부모 `height`를 이미 쓰는 `_filled`/`Stack` 맥락을 보고, 가능하면 `MediaQuery`/`LayoutBuilder`로 `maxHeight = 가용 높이 - top(36) - 여백`을 쓴다.
   - 목록 `Column`은 `mainAxisSize: min` 유지, 스크롤은 세로만.
2. 스크롤·탭이 보드 제스처와 싸우지 않게 메뉴 `Material` 안 포인터는 기존처럼 메뉴가 먹게 둔다(새 제스처 레이어·흡수 위젯 추가하지 않음. `SingleChildScrollView`만).
3. 확인 후 프롬프트를 `docs/2026-11-02/트랙_메뉴_스크롤_프롬프트.md`에 저장한 뒤 그 문서만 보고 구현.

기본 선택: `maxHeight`는 메뉴 `top: 36`을 뺀 보드 가용 높이(하한 120, 상한 없이 보드 하단 여백 8px)로 잡고, `SingleChildScrollView`로 목록만 스크롤한다.

## 유지할 것
- 메뉴 열기/닫기, 체크박스 가시성 토글
- 위치(`right: 12`, `top: 36`), 색·elevation·체크 아이콘 스타일
- ViewModel API (`didTapToggleTrackMenu` 등) 시그니처·로직

## 이번 작업에서 만들지 않음
- 메뉴 검색·가상 리스트·외부 클릭 닫기
- ViewModel·도메인 변경
- 보드 본문 스크롤과의 연동 리팩터

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.

## 완료 확인
- 트랙이 많을 때 메뉴가 보드 안에서 잘리고, 메뉴 안에서 세로 스크롤된다.
- 스크롤 후 항목 탭으로 가리기/보이기가 된다.
- 트랙이 적을 때는 이전처럼 내용 높이만큼만 보인다(불필요한 빈 스크롤 영역 없음).
