# Lane→트랙 이름 통일 (가시성·트랙 ID만)

## 목표
UI·API에서 트랙 행을 가리키던 `Lane` 명칭을 `Track`/`트랙`으로 통일한다. 한 트랙 안 겹침 줄(`laneIndex` 등)과 첨부 숨김(`didTapToggleLane`)은 의미가 다르므로 건드리지 않는다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md`
3. `lib/src/presentation/features/video_multimodal/widgets/multimodal_timeline_board.dart`, `lib/src/presentation/features/video_multimodal/video_multimodal_view_model.dart`, `lib/src/presentation/features/video_multimodal/widgets/timeline_board_helpers.dart`, `lib/src/presentation/features/video_multimodal/video_multimodal_models.dart`
4. 계약·화면안: 없음

## 현재 상태
- 툴바 버튼 라벨이 `'Lanes'`이고, 메뉴/가시성은 `isLaneMenuOpen` / `didTapToggleLaneMenu` / `_laneMenu` / `didTapToggleLaneKey` / `_hiddenLaneKeys` / `isLaneVisible`.
- 보드 행·샘플 클립의 트랙 ID 필드가 `laneKey`(값은 `track.trackId`).
- 겹침 줄은 `laneIndex` / `laneCount` / `assignClipLanes` / `TIMELINE_TRACK_LANE_HEIGHT`로 별도 의미.
- `didTapToggleLane(attachmentId)`는 첨부 숨김(`_hiddenAttachmentIds`)이며 트랙과 무관.

## 바꿀 것
1. UI: `'Lanes'` → `'트랙'`; `_laneMenu` → `_trackMenu`; 로컬 변수 `lanes`/`lane` → `tracks`/`track`.
2. ViewModel 가시성·메뉴:
   - `_isLaneMenuOpen` / `isLaneMenuOpen` / `didTapToggleLaneMenu` → `_isTrackMenuOpen` / `isTrackMenuOpen` / `didTapToggleTrackMenu`
   - `_hiddenLaneKeys` / `isLaneVisible` / `didTapToggleLaneKey` → `_hiddenTrackIds` / `isTrackVisible` / `didTapToggleTrackVisibility`
   - 파라미터 `laneKey`(트랙 ID 의미) → `trackId` (`isServerTimelineTrack`, 드롭 헬퍼 등)
3. 모델/보드: `TimelineBoardRow.laneKey` → `trackId`; `TimelineSampleClip.laneKey`/`laneLabel` → `trackId`/`trackLabel`; 호출부·테스트(`job_timeline_edit_test.dart`의 `laneKey:`) 동기 수정.
4. 스크롤 동기화 이름: `_syncTrackLanesFromLabels` / `_syncTrackLabelsFromLanes` → `_syncTrackRowsFromLabels` / `_syncTrackLabelsFromRows` (세로 스크롤 대상이 트랙 행이므로).
5. 확인 후 프롬프트를 `docs/2026-11-02/트랙_명칭_통일_프롬프트.md`에 저장한 뒤 그 문서만 보고 구현.

## 유지할 것
- `laneIndex`, `laneCount`, `assignClipLanes`, `_laneCount`, `TIMELINE_TRACK_LANE_HEIGHT` 및 겹침 줄 로직
- `didTapToggleLane` / `_hiddenAttachmentIds` / `isBarHidden` (첨부 숨김)
- `collection_roadmap`의 lane
- 과거 docs의 Lane 서술 일괄 수정은 하지 않음
- 가시성·메뉴 동작 자체는 변경 없음 (이름만)

## 이번 작업에서 만들지 않음
- 동작 변경, 새 UI, 서버 연동
- 겹침 줄을 track로 강제 리네임
- 첨부 숨김 API를 track로 오인 리네임

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.

## 완료 확인
- 툴바에 `트랙` 버튼이 있고 메뉴·가리기 동작이 이전과 같다.
- 트랙 가시성 API·보드 행 ID가 `track*`/`trackId`로 읽힌다.
- `laneIndex`/`assignClipLanes`/`didTapToggleLane`(첨부)는 그대로다.
- analyzer/테스트에서 옛 `laneKey`/`isLaneVisible` 등 참조가 없다(범위 안).
