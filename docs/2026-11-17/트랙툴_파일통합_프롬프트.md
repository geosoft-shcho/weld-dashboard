# 트랙 툴 파일 통합

## 목표
트랙 편집 줄과 트랙 목록 오버레이를 같은 “트랙 툴” UI 파일에서 관리한다. `edit_tools`에 메뉴만 억지로 넣지 않는다.

## 판단
- `TimelineBoardEditTools` = 트랙 CRUD(추가·이름·삭제)
- `TimelineBoardTrackMenu` = 활성/비활성 체크 목록
- 둘 다 트랙 툴이지만 “edit” 파일에 메뉴를 넣는 이름은 틀리다.
- 권장: `timeline_board_track_tools.dart`에 두 위젯을 두고, `edit_tools`·`track_menu` 단독 파일은 제거한다.

## 바꿀 것
1. `timeline_board_track_tools.dart` 신설 — `TimelineBoardEditTools` + `TimelineBoardTrackMenu`
2. `timeline_board_edit_tools.dart`, `timeline_board_track_menu.dart` 삭제
3. toolbar·board import 갱신

## 유지할 것
- 위젯 public 이름·동작·문구
- ToolButton은 toolbar에 유지

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
