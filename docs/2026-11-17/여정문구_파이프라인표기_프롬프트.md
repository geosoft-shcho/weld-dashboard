# Trace UI 「여정」→ 파이프라인 표기

## 목표
TraceService 연동 화면·사용자에게 보이는 메시지에서 「여정」을 파이프라인 관련 문구로 바꾼다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md` (가이드라인 저장소는 워킹 트리 밖에서 읽기만)
3. `lib/src/presentation/features/collection_monitoring/widgets/pipeline_trace_list.dart`
4. `lib/src/presentation/features/collection_monitoring/widgets/pipeline_trace_tab_body.dart`
5. `lib/src/data/repositories/remote_trace_repository.dart`

## 현재 상태
- 목록 빈 상태·파일명 없을 때·선택 요약·조회 실패 타이틀·Repository TraceException에 「여정」/「Trace」가 있다.

## 바꿀 것
1. UI 문자열: 여정 → 파이프라인(표시할 파이프라인 없음, 파이프라인 {id} 등).
2. `Trace 조회 실패` → `파이프라인 조회 실패`.
3. Repository 사용자 메시지(목록/단건/상태 실패)도 동일하게 파이프라인 표기.
4. 생성 코드·proto는 건드리지 않는다.
5. `./scripts/agent_check.sh` 통과.

## 유지할 것
- 식별자·API·도메인 타입명(TraceSnapshot 등)

## 이번 작업에서 만들지 않음
- 문서·가이드 전면 치환, 생성 코드 수정

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
