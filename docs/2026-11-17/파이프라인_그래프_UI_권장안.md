# (2026-11-17) 적재 파이프라인 그래프 UI 권장안

| 항목 | 값 |
|------|-----|
| 화면 | 수집 모니터링 · 적재 파이프라인 |
| 목적 | **하나의 적재 여정**이 받기→등록→후처리→(도구)→임베딩→완료로 흐르는 모습을 사용자에게 맞게 보여 줄 UI를 권한다 |
| 대상 | 현행 **단계별 세로 열** 레이아웃의 대안 |

---

## 1. 문제

받기 · 등록 · 후처리 · 임베딩 · 완료는 **한 줄짜리 파이프라인**이다.  
지금은 단계를 **가로로 나란히 둔 뒤, 각 단계 안 이벤트를 세로로 쌓는 열(column) UI**다.

| 사용자 기대 | 지금 UI가 주는 인상 |
|-------------|---------------------|
| 왼쪽에서 오른쪽으로 **한 흐름**이 진행된다 | 단계마다 **따로 세로 목록**이 있어 여러 파이프라인처럼 보인다 |
| “지금 어디인가”가 한 점·한 구간으로 보인다 | 열마다 원이 가득 차 **어디가 현재인지** 찾기 어렵다 |
| 세부 이벤트는 그 단계의 **하위 과정**이다 | 세부 이벤트가 단계와 **같은 무게의 노드**로 보여 단계·노드·상태가 섞인다 |
| 여러 여정은 **목록 또는 레인**으로 겹친다 | 모든 여정이 같은 골격 노드에 색만 얹어 **한 파이프라인인지 다건 집계인지**가 흐리다 |

레퍼런스 IoT 모니터의 “세로 열”은 **서로 다른 시스템 구간**을 나란히 두는 용도였다.  
Trace는 그 모델이 아니라 **단일 여정의 단계 시퀀스**이므로, 같은 시각 문법을 그대로 쓰면 어긋난다.

---

## 2. 원칙

1. **한 파이프라인 = 한 가로 축.** 단계는 항상 왼쪽→오른쪽.
2. **단계는 큰 칸, 세부 이벤트는 단계 안의 작은 점·칩.** 무게를 나눈다.
3. **현재 위치는 하나만 강조.** RUNNING의 `last_event`가 속한 단계(또는 세부)만 “현재”.
4. **다건은 파이프라인을 복제하지 않는다.** 위는 집계 한 줄, 아래는 여정 목록(또는 선택 1건 상세).
5. 공정 전용 이름·IoT 노드명은 쓰지 않는다. Trace 이벤트 이름(`단계.세부`) 위에 한글 라벨만 얹는다.

---

## 3. 권장 레이아웃 (A안 · 채택 권고)

**가로 스테퍼 + 여정 목록.** 구현 부담 대비 읽기 비용이 가장 낮다.

```text
┌─ 단계 집계 칩 ─────────────────────────────────────────────┐
│ 받기 3  등록 1  후처리 2  임베딩 0  완료 20   [필터] [줌]   │
└────────────────────────────────────────────────────────────┘
┌─ 파이프라인 한 줄 (선택 여정 또는 RUNNING 대표) ────────────┐
│                                                             │
│  (받기)──►(등록)──►(후처리)──►(임베딩)──►(완료)             │
│   ●●○       ●○○      ◉ 진행      ○         ○               │
│  시작·검사·완료   …     run·속성·…                          │
│                                                             │
│  굵은 원 = 단계   작은 점 = 그 단계의 세부 이벤트            │
│  연결선 = 단계 사이만 (세부끼리는 단계 안 점선/점 나열)     │
│  활성 단계 = 링·배지「진행」·입자                           │
└────────────────────────────────────────────────────────────┘
┌─ 여정 목록 ──────────────────┬─ 선택 시 상세 ───────────────┐
│ 파일 · 상태 · 현재 단계 · 시각 │ 이벤트 워터폴 · GetQueue     │
│ …                            │                             │
└──────────────────────────────┴─────────────────────────────┘
```

### 3.1 단계 노드 (큰 원)

| 표시 | 의미 |
|------|------|
| 라벨 | 받기 / 등록 / 후처리 / 도구(있을 때만) / 임베딩 / 완료 |
| 채움 | idle 흐림 · 지나감(done) 액센트 · 현재 강조 · 실패 빨강 · 대기 주황 |
| 배지 | `현재` / `진행` / `대기` / `완료` / `실패` (idle은 없음) |
| 건수 | 집계 모드일 때만 단계 칩 또는 단계 원 옆 `N` |

### 3.2 세부 이벤트 (작은 점)

- 큰 원 **아래 또는 안쪽**에 `receive.started` 등을 작은 점으로 가로 나열.
- 점이 많으면(후처리) **접기**: 기본은 `run`·마지막 세부·실패만, “세부 N” 펼침.
- 세부끼리 세로로 길게 쌓지 않는다.

### 3.3 연결선

- **단계 ↔ 단계**만 본선.
- 선택된(또는 RUNNING) 여정이 지나온 단계만 강조 선 + 입자.
- 세부 점 사이는 짧은 가이드만 두거나 생략.

### 3.4 다건·선택

| 모드 | 그래프 | 목록 |
|------|--------|------|
| 집계(미선택) | RUNNING이 있으면 그 여정 경로, 없으면 “가장 최근 RUNNING/실패” 또는 빈 골격 + 칩 건수만 | 전체 Trace |
| 여정 선택 | 그 여정만 경로·현재 강조 | 선택 행 하이라이트 + 우측 상세 |

세로 열에 모든 여정을 색으로 겹치지 않는다.

## 4. 대안 (참고)

### B안 · 가로 스윔레인

여정마다 가로 레인 한 줄. 다건 비교에 강하나 높이·스크롤 비용이 크다. **다건 비교가 1차 KPI일 때만**.

### C안 · 타임라인 워터폴만

이벤트 `at` 순 세로 리스트. 구현은 쉽지만 “파이프라인” 한눈에 보기는 약하다. **상세 패널 전용**으로 두고 본화면은 A안.

**권고: A안 본화면 + C안 상세.** B안은 보류.

## 5. As-Is → To-Be

| | As-Is (세로 열) | To-Be (권장 A) |
|--|-----------------|----------------|
| 축 | 단계=가로 열, 세부=세로 스택 | 단계=가로 한 줄, 세부=단계 아래 점 |
| 연결 | 모든 세부 노드를 잇는 선 | 단계 사이 본선 + 거친 경로만 강조 |
| 무게 | 단계·세부·상태가 비슷한 원 | 단계 대 / 세부 소 / 상태 배지 |
| 다건 | 같은 골격에 색만 합침 | 한 줄 경로 + 목록 |
| 도구 열 | 데이터 없으면 숨김 | 동일(단계 칸 자체 숨김) |

## 6. 유지할 API·데이터

- `ListTraces` / `GetTrace` / 대기 시 `GetQueue` · 폴링 1~2초
- 이벤트 이름·단계 ID 변경 없음
- RUNNING · DONE · FAILED 포함, `tool`은 데이터 있을 때만

---

## 7. 확인 질문 (구현 전) — 확정

1. **A안(가로 스테퍼 + 목록)** 으로 본화면을 바꾼다. **스크롤은 최소**(스테퍼는 너비 분배, 목록만 세로 스크롤).
2. 미선택 시 **RUNNING만이 아니라** visibleTraces 합산으로 실패·진행·완료 등 **가능한 상태를 단계에 표시**.
3. 후처리 등 세부 이벤트 점은 **전부 표시**(접기 없음).
