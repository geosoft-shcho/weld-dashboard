# 파이프라인 세부 이벤트 명시 표기

## 목표
가로 스테퍼에서 세부 이벤트가 10px 점+툴팁으로만 보이지 않고, **한글 라벨(및 상태)이 화면에 바로 읽히게** `pipeline_trace_graph_view.dart`만 재구현한다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md` (가이드라인 저장소는 워킹 트리 밖에서 읽기만)
3. `lib/src/presentation/features/collection_monitoring/widgets/pipeline_trace_graph_view.dart`
4. `lib/src/domain/entities/pipeline_trace_graph.dart` (`pipelineEventLabel`, `pipelineNodeVisual`, `pipelineNodeStatusLabel`)
5. `docs/2026-11-17/파이프라인_그래프_UI_권장안.md` §3.2 (세부=단계 하위; 접기 요구는 이번 범위 밖)

## 현재 상태
- `_StageColumn`이 `stage.nodeIds`마다 `_DetailDot`(10×10 원)만 그린다.
- 이름은 `Tooltip`에만 있고, 탭·색·pulse·`pipelineNodeVisual`은 이미 있다.

## 바꿀 것
1. `_DetailDot`를 **라벨이 보이는** 위젯으로 바꾼다(이름 변경 가능). 표시: `pipelineEventLabel(nodeId)` + non-idle이면 `pipelineNodeStatusLabel`을 옆에 짧게.
2. 상태 색·live pulse·탭(`onDetailTap`)·`pipelineNodeVisual` 계산은 유지한다. 작은 상태 인디케이터(점/아이콘)는 라벨 **앞**에만 두고, 점만으로 요약하지 않는다.
3. `Wrap`으로 단계 열 안에 나열한다. compact면 글자만 조금 줄인다.
4. 새 카드 UI·새 파일을 만들지 않는다. 이 위젯 파일 안 교체만.
5. `./scripts/agent_check.sh` 통과.

## 유지할 것
- 큰 원·단계 연결선·집계 요약·선택/집계 visual 로직(도메인)
- ViewModel·GetTrace 폴링·상세 패널

## 이번 작업에서 만들지 않음
- 세부 접기/펼침
- 도메인·ViewModel·칩 탭 본문 구조 변경
- 새 디자인 시스템·상태관리

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
