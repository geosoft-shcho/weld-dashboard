# 트랙 메뉴 최초 로드 미동작

## 목표
Tracks 버튼의 selected/onPressed를 디버그로 확인하고, 최초 로드 직후 메뉴가 열리지 않는 원인을 고쳐 첫 탭부터 메뉴가 보이게 한다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md`
3. `timeline_board_toolbar.dart` Tracks 버튼
4. `video_multimodal_screen.dart` `_stageBoardKey` / `_StageBoardHost`
5. `video_multimodal_view_model.dart` `didTapToggleTrackMenu`

## 현재 상태
- Tracks `onPressed`는 `didTapToggleTrackMenu`만 호출하고, `selected`는 `isTrackMenuOpen` 표시용이다. 둘은 중복 실행되지 않는다.
- `didTapToggleTrackMenu`는 `_isTrackMenuOpen`을 뒤집고 `notifyListeners()`한다.
- `_StageBoardHost`는 `context.select(..., _stageBoardKey)`로만 보드를 다시 그린다.
- `_stageBoardKey`에 `isTrackMenuOpen`(및 트랙 가시성)이 없어, 토글만으로는 `MultimodalTimelineBoard`가 rebuild되지 않는다. 그래서 첫 탭에서 메뉴·selected가 안 바뀌는 것처럼 보인다.

## 바꿀 것
1. Tracks 버튼·토글에 `debugPrint`로 selected 값과 onPressed 진입/토글 후 상태를 남긴다.
2. `_stageBoardKey`에 `isTrackMenuOpen`을 넣어 토글 시 보드가 rebuild되게 한다.
3. 트랙 메뉴에서 가리기 토글도 바로 반영되도록 숨김 트랙 식별자를 `_stageBoardKey`에 포함한다(메뉴가 열린 뒤 체크가 안 바뀌는 같은 원인).

## 유지할 것
- `didTapToggleTrackMenu` 토글 의미
- `TimelineBoardTrackMenu` UI·위치
- select 키 방식(전체 listen으로 바꾸지 않음)

## 이번 작업에서 만들지 않음
- 새 상태관리·위젯 파일
- toolbar/selected 구조 리팩터
- 다른 host 키 전면 정리

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
