# 파이프라인 진행 상태 애니메이션 표기

## 목표
적재 파이프라인만 보고도 진행 상태를 알 수 있게 한다. 완료/진행 등 **상태 필터 버튼은 제거하고**, 실시간 애니메이션·상태 문구로 표기한다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md`
3. `lib/src/presentation/features/collection_monitoring/widgets/pipeline_trace_list.dart`
4. `lib/src/presentation/features/collection_monitoring/widgets/pipeline_trace_graph_view.dart`
5. `lib/src/presentation/features/collection_monitoring/widgets/pipeline_trace_tab_body.dart`

## 현재 상태
- 목록 상단에 전체/진행/완료/실패 **필터 버튼**이 있다.
- 스테퍼에 활성 펄스·배지는 있으나, 필터 UI에 의존하면 한눈에 상태가 안 읽힌다.

## 바꿀 것
1. 목록의 상태 필터 버튼(전체·진행·완료·실패)을 **제거**한다. 목록은 항상 전체 Trace를 보여 준다.
2. 스테퍼 영역(또는 바로 위)에 **상태 요약 한 줄**(진행/완료/실패 건수)을 두고, 진행·대기는 **실시간 펄스 점**으로 표시한다. 버튼·탭으로 나누지 않는다.
3. 스테퍼 단계·연결선의 활성 애니메이션을 유지·강화해, 파이프라인만 봐도 어디가 도는지 보이게 한다.
4. 목록 행은 상태 문구·색으로 표기하고, 진행 중 행은 작은 펄스 점으로 표시한다.
5. `./scripts/agent_check.sh` (+관련 테스트) 통과.

## 유지할 것
- 가로 스테퍼·단계 칩(열 보이기)·폴링·상세 패널·집계 visual

## 이번 작업에서 만들지 않음
- 새 필터 UX, 새 디자인 시스템, proto 변경

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.

- 스테퍼에서 진행 단계가 애니메이션되고, 진행/완료/실패 건수가 문구로 보인다
