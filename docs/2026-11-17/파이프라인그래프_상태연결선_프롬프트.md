# 파이프라인 그래프 UI 명시화

## 목표
적재 파이프라인 그래프에서 **단계(열) · 노드 · 상태**가 한눈에 구분되고, **실제로 거친 노드끼리만** 연결선이 보이며, 활성(RUNNING/현재 위치)이면 활성 시각이 분명히 보이게 한다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md` (가이드라인 저장소는 워킹 트리 밖에서 읽기만)
3. `lib/src/domain/entities/pipeline_trace_graph.dart`
4. `lib/src/presentation/features/collection_monitoring/widgets/pipeline_trace_graph_view.dart`
5. `docs/2026-11-17/수집모니터링_Trace파이프라인_화면검증.md` §6–7

## 현재 상태
- 모든 노드가 비슷한 원+아이콘+작은 라벨. `done`/`active`/`running`이 같은 열 액센트 색이라 상태가 잘 안 갈린다.
- `_PipelineEdgesPainter`가 **보이는 모든 노드를 순서대로** 회색 골격선으로 잇고, **선택(selected)이 있을 때만** 지나온 경로에 점선·입자를 그린다. 미선택 집계 모드에서는 활성 경로가 거의 안 보인다.
- 노드 visual은 `pipelineNodeVisual`이 계산한다(idle/done/active/queued/running/failed/skipped).

## 바꿀 것
1. **상태 명시**: 노드에 상태별 테두리·채움·배지(짧게: 대기/진행/완료/실패/건너뜀)를 두어 idle과 활성·완료가 구분되게 한다. active/running은 링·펄스(또는 두꺼운 테두리)로 강조. done은 체크 힌트, failed는 에러색.
2. **단계 명시**: 열 헤더를 단계 액센트 배경/하단 바로 더 분명히 하고, 노드 라벨은 `pipelineEventLabel`을 유지하되 가독성(대비·크기)만 올린다. 새 디자인 시스템/카드 UI는 도입하지 않는다.
3. **연결선 = 거친 경로만**:
   - 골격: 단계 열 사이·열 안 인접 노드의 **흐린 가이드**만(또는 최소화).
   - **실선(또는 강조 점선)**: 선택된 여정이 있으면 그 여정이 거친 노드 순서대로; 선택이 없으면 visibleTraces 중 RUNNING이 있으면 그 경로, 없으면 집계상 done/active인 인접 구간만 연결.
   - 활성 구간에만 입자/펄스.
4. 도메인에 경로 계산 헬퍼를 최소로 추가(예: `pipelinePathNodeIds(trace)` — events 순서 + lastEvent 기준, idle 제외). UI painter는 이 목록만 잇는다.
5. 기존 `test/pipeline_trace_graph_test.dart`에 경로·시각 기대를 보강하고 `./scripts/agent_check.sh` 통과.

## 유지할 것
- Trace 단계/노드 ID 목록·칩 필터·폴링·선택 패널 흐름
- AppTheme 다크 팔레트, Fluent 아이콘 매핑
- ListTraces 요청 방식, pollSignature로 불필요 리렌더 스킵

## 이번 작업에서 만들지 않음
- 새 상태관리·디자인 시스템·카드 UI
- proto/API 변경, 단계 ID 이름 변경
- IoT 레퍼런스 노드명 도입

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
