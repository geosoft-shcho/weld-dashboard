# 현장/수집 선행 단계 하드코딩

## 권장(채택)
- **받기 앞에** Trace API에 없는 골격 단계 `collect` / 라벨 `현장/수집`만 상수로 추가한다.
- 세부: `collect.field`(현장), `collect.capture`(수집) — 서버 이벤트와 무관.
- **시각**: Trace `last_event`가 받기 이후면 `_stageOrder`상 선행 단계라 자동 **완료(done)**. 별도 상태 API·플래그 없음.
- **건수**: Trace에 들어온 건(stageId 있음)만 현장/수집 통과 건수로 센다.
- proto/GetTrace 확장·가짜 Trace 주입은 하지 않는다(초기값·골격만).

## 목표
적재 파이프라인 스테퍼/칩에 「현장/수집」이 받기 왼쪽에 보이고, Trace 진행 건은 그 단계를 지나간 것으로 표시한다.

## 현재 상태
- `pipelineStages`가 `receive`부터 시작한다. Trace 이벤트는 receive 이후만 온다.

## 바꿀 것
1. `pipelineStages` 맨 앞에 collect 단계·라벨·nodeIds·`pipelineNodeLabels`·아이콘 키 추가.
2. `pipelineStageCounts`에서 collect는 Trace에 올라온 건(비어 있지 않은 stageId)을 통과 건수로 집계.
3. `pipelineStageAccent`에 collect 색.
4. 단위 테스트로 순서·통과 시 done·건수 고정.
5. `./scripts/agent_check.sh` (+테스트) 통과.

## 유지할 것
- Trace 폴링·매핑, receive 이후 단계 정의

## 이번 작업에서 만들지 않음
- proto 필드, Redis/live API, 실제 현장 수집 연동

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
