# 수집 날짜 조회 · 데이터 유형 FE 연동

## 목표
`수집 날짜 조회 · 데이터 유형 변경 안내.md`의 깨지는 변경과 수집 현황 KPI·트리 막대를 화면에 맞춘다. work·asset generated를 확인하고 필요하면 재생성한다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md`
3. `docs/2026-11-26/수집 날짜 조회 · 데이터 유형 변경 안내.md`
4. `docs/2026-11-26/README.md` (2026-11-26에 바뀐 것)
5. 수집 모니터링 레포·엔티티·KPI·VM

## 현재 상태
- proto·generated에 `from`/`to`, `data_type_coverage`, segment `job_id`·`pass_id`·`estimated`, `warnings` 존재
- FE는 `startOffsetNs`/`endOffsetNs`, `KindCoverage`, KPI 다섯 장 사용

## 바꿀 것
1. `flutter pub get` → `buf generate` (generated 직접 수정 금지)
2. ListCollectionNodes / GetCollectionSummary: KST 일자·시작·종료 → UTC `from`·`to`. offset 제거
3. `KindCoverage` → `DataTypeCoverage`. segment에 jobId·passId·estimated, 노드 warnings 매핑
4. KPI 네 장(수집량·작업량·커버리지·임베딩). traces 카드 제거 → 적재 탭 배지
5. estimated 막대 구분, 가능하면 축 밖 이어짐 표시
6. 작업 노드 「시각 확인」 배지

- ListAssetCounts 그래프 경로(별도)

## 이번 작업에서 만들지 않음

- 작업 아래 파일 노드 제거, PassWaveform warnings
- 파이프라인 개편

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
- generated 수동 편집 금지.
