# 내정보 UI · 로그아웃 확인

## 목표
`_MyAccountInfoDialog`를 읽기 전용 프로필처럼 보이게 한다. 설정 pane 「로그아웃」은 확인 다이얼로그에서 동의한 뒤에만 `signOut`한다.

## 먼저 읽을 것
1. `shell_screen.dart` — `_MyAccountInfoDialog`, 설정 `_navPaneAction` 로그아웃 onTap
2. 계정·토큰 관리 확인 ContentDialog(취소/실행) 패턴

## 현재 상태
- 내정보: `InfoLabel` + `Text`만 세로 나열, 권한은 `\n` 연결, 너비·계층 없음
- 로그아웃: pane 클릭 시 `isBusy`만 보고 바로 `auth.signOut()` — 확인 없음

## 바꿀 것 (같은 파일만)
`shell_screen.dart`:

### A. `_MyAccountInfoDialog`
1. `constraints: BoxConstraints(maxWidth: 440)`
2. 상단 헤더: 아이콘 + 표시 이름, 보조 줄에 로그인 아이디(secondary 12)
3. private `_MyAccountInfoRow`: 라벨(secondary)·값(`SelectableText`)
4. 역할: `roleName` + secondary `roleId`
5. 권한: `Wrap` + `Padding`/`Text`(12). 빈 목록 「없음」. Chip/카드·새 디자인 시스템 없음

### B. 로그아웃 확인
1. 로그아웃 `onTap` → `_didTapSignOut(context)` (바로 `signOut` 하지 않음)
2. `showDialog` + `ContentDialog`: 제목 「로그아웃」, 본문 「로그아웃할까요?」, 액션 「취소」/`Button` · 「로그아웃」/`FilledButton`
3. `true`일 때만 `AuthSessionViewModel.signOut()`. `isBusy`면 다이얼로그를 열지 않거나 확인 후에도 no-op
4. 토큰 폐기·역할 삭제와 같은 짧은 확인 문구 스타일 유지

## 유지할 것
- `AuthSessionViewModel.user` / `signOut` 본 동작
- 비밀번호 변경 다이얼로그·pane 인덱스(`PaneItemAction`)
- 비밀번호 변경 성공 후 강제 로그아웃 흐름(별도 확인 없음)

## 이번 작업에서 만들지 않음
- 계정 편집·역할 변경·ListPermissions
- 별도 위젯 파일·테마 토큰
- 로그아웃 후 라우트 수동 리셋(기존 `_AuthGate` 유지)

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
