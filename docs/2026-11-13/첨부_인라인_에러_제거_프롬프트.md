# 첨부 탭 인라인 에러 영역 제거

## 목표
`job_attachment_tab.dart`에서 `_run`이 예외를 탭 상단 빨간 텍스트로 넣던 UI를 없애, 그 영역이 레이아웃을 잡지 않게 한다. 실패 안내는 기존 떼기와 같이 ContentDialog로만 한다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md` (가이드라인 저장소는 워킹 트리 밖에서 읽기만)
3. `lib/src/presentation/features/job_lookup/widgets/job_attachment_tab.dart`
4. 없음

## 현재 상태
- `_error` 상태가 `_run` catch·붙이기 번호 검증에서 채워진다.
- `build`에 `if (_error.isNotEmpty) Text(_error, red)`가 있어 액션바 아래 세로 공간을 쓴다.
- `_didTapDetach`는 이미 ContentDialog만 쓰고 `_error`에는 넣지 않는다.

## 바꿀 것
1. `_error` 필드와 상단 빨간 `Text` 블록을 제거한다.
2. `_run` 실패 시 `_userFacingError`로 ContentDialog(제목: 요청을 처리할 수 없습니다, 닫기)를 띄운다. `_error`는 쓰지 않는다.
3. 붙이기 번호 검증(`에셋 번호를 숫자로 넣으세요.`)도 같은 ContentDialog로 바꾼다.
4. `_didTapDetach`에서 `_error = ''` 정리만 있던 부분은 함께 지운다.

## 유지할 것
- Detach ContentDialog·`_userFacingError`(ConnectException.message)
- 올리기 InfoBar(경고/실패 노트)
- ViewModel·Repository Detach/Attach 호출

## 이번 작업에서 만들지 않음
- 새 공통 에러 위젯/헬퍼 파일
- 다른 탭·화면의 인라인 에러 정리

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.

- `_run` 실패·번호 검증·Detach 실패는 ContentDialog로만 보인다
