# 품질 이슈 ListAssets 캐시 + 최초 로드 병렬

## 목표
패스 전환 시 `ListAssets` 재호출을 없애고, 최초 진입에서 서로 독립인 API와 `GetReportSet` N회를 병렬로 돌려 대기 시간을 줄인다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md`
3. `lib/src/presentation/features/quality_issue/quality_issue_view_model.dart`
4. `lib/src/data/repositories/remote_quality_job_media_repository.dart`
5. `lib/src/domain/repositories/quality_job_media_repository.dart`, `lib/src/domain/use_cases/list_quality_job_media_use_case.dart`
6. 계약·화면안: 없음

## 현재 상태
- `_loadJobMediaForPass`가 패스마다 `listJobMedia(jobId, passId)` → 리포는 이미 job `ListAssets` 후 pass 필터인데 **호출마다 ListAssets 재실행**
- `_loadCatalog`가 `ListQualityResults` → `GetReportSet` 순차 → `GetJob` 카탈로그 순차
- `_loadReportPdfs`가 reportSet마다 `await` 순차

## 바꿀 것

### A. ListAssets job 캐시 + pass 필터
1. 리포지토리: `passId`가 비면 pass 필터 없이 job의 PDF/video 전부 반환(각 항목 `passId` 유지). `jobId` 빈 경우만 `[]`
2. UseCase: `passId` 비어 있어도 job만 있으면 전체 목록 조회 허용
3. ViewModel: `_jobMediaCache` + `_jobMediaCacheJobId` (또는 null 센티널). `loadBoard` 시작 시 캐시 무효화
4. `_ensureJobMediaCache`: job당 1회 `execute(jobId:, passId: '')`
5. `_loadJobMediaForPass`: 캐시 확보 후 `passId`로 필터해 `_jobMedia` 설정 (네트워크 없음)

### B. 최초 로드 병렬 + GetReportSet 병렬
1. `_loadCatalog`에서 `ListQualityResults`와 `LoadPassWaveformCatalog`(GetJob+파형)를 `Future.wait`로 동시 시작
2. `_loadReportPdfs`: unique `reportSetId`에 대해 `Future.wait`로 `GetReportSet` 병렬 (실패 시 해당 슬롯 URL 빈 `QualityScanPdf` 유지)
3. 카탈로그 적용·pass 확정 후 미디어 캐시/비교잡은 기존처럼. PDF 목록 await와 미디어 로드는 가능하면 겹침: 카탈로그로 pass 확정 → `pdfsFuture`와 `_loadJobMediaForPass`를 함께 기다림

## 유지할 것
- 파형만 재로드(1+2) 동작
- UI 위젯·표시명 fileName
- 비교 job `ListJobs`는 catalog.context 의존 → 카탈로그 이후 유지

## 이번 작업에서 만들지 않음
- GetReportSet 응답에 URL 넣는 서버 계약 변경
- 새 추상 계층·캐시 프레임워크
- pass_profile 변경

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
