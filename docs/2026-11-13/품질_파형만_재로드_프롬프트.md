# 품질 이슈 패스 전환·불일치 시 파형만 재로드

## 목표
패스 탭 전환과 보드/파형 pass 불일치 시 `GetJob`·품질표·PDF·비교잡 재요청 없이 `GetPassWaveform`만 다시 받아, 차트만 갱신되게 한다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md`
3. `lib/src/presentation/features/quality_issue/quality_issue_view_model.dart`
4. `lib/src/data/repositories/remote_pass_waveform_repository.dart` (`loadCatalog` vs `loadWaveform`)
5. 계약·화면안: 없음

## 현재 상태
- `didSelectPass` / 링크 패스 변경 → `_reloadPassContent()` → `_loadCatalog(isPageLoad: false)` → 리포지토리 `loadCatalog`가 **`GetJob` + `GetPassWaveform`** 재호출
- `_loadCatalog` 말미 `boardPassId != loadedPassId`이면 `loadBoard()` 또는 `_reloadPassContent()`로 **전체/카탈로그 재로드** (품질 `ListQualityResults`·`GetReportSet`까지 다시 탐)
- 이미 `_reloadComparisonWaveformAt`은 `_loadPassWaveformUseCase`만 쓰고 카탈로그의 `waveformRows`만 교체함 (`pass_profile`과 같은 패턴)

## 바꿀 것
1. `quality_issue_view_model.dart`만 수정
2. **`_reloadPassContent`**: `_loadCatalog(isPageLoad: false)` 대신 기존 `_reloadComparisonWaveform()`(또는 동일 `loadWaveform` 경로)만 호출
3. **pass 불일치 분기**: `loadBoard()` / 전체 카탈로그 재호출 제거. `_passId = boardPassId` 후 **같은 로드 version 안에서** `_loadPassWaveformUseCase`로 파형만 받아 `_catalog.waveformRows` 갱신 → `_applyQuery()`. (바깥 `_loadVersion`을 올려 진행 중 페이지 로드를 무효화하지 않음)
4. `_loadCatalog`의 `isPageLoad: false` 전용 분기가 호출되지 않으면 제거(죽은 코드)
5. 확인 후 `docs/2026-11-13/품질_파형만_재로드_프롬프트.md` 저장 뒤 그 문서만 구현

## 유지할 것
- 최초 `loadBoard` / `isPageLoad: true` 순서 (품질표·PDF·GetJob·파형·ListAssets·ListJobs)
- 패스 전환 시 `_loadJobMediaForPass` 호출 (ListAssets 캐시는 이번 범위 밖)
- 비교 job 선택·정규화의 기존 `_reloadComparisonWaveformAt`
- UI 위젯·리포지토리 시그니처

## 이번 작업에서 만들지 않음
- ListAssets job 캐시, GetReportSet 병렬, 최초 로드 Future.wait
- 새 UseCase·추상 계층
- pass_profile 변경

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
