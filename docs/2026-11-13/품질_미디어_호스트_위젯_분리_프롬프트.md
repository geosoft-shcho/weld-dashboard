# 품질 미디어 호스트 위젯 분리

## 목표
`quality_media_host.dart`에 뭉쳐 있는 책임이 분명한 private 위젯을 같은 feature `widgets/` 폴더의 개별 파일로 분리해, 호스트는 조합만 남긴다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md`
3. `lib/src/presentation/features/quality_issue/widgets/quality_media_host.dart`
4. 기존 분리 예: `paper_scan_host.dart`, `quality_video_host.dart`, `quality_paper_meta.dart`
5. 계약·화면안: 없음

## 현재 상태
- 한 파일에 `QualityMediaHost`와 `_MediaEntry`, `_MediaStrip`, `_ReportPdfView`, `_MediaFiles`, `_MediaTabs`, `_MediaTab`이 함께 있다 (~700줄).

## 바꿀 것
1. `quality_media_strip.dart`: `QualityMediaEntry` + `QualityMediaStrip`(Flyout 선택·더보기·호스트 표시). `_MediaFlyoutSnapshot`은 이 파일 private 유지.
2. `quality_media_tabs.dart`: `QualityMediaTabs` (+ 탭 칩 private).
3. `quality_media_files.dart`: `QualityMediaFiles`.
4. `quality_report_pdf_view.dart`: `QualityReportPdfView`.
5. `quality_media_host.dart`: 위 파일을 import하고 public 타입으로 호출. 엔트리 조립·분기만 유지. 죽은 private 위젯 제거.

## 유지할 것
- 화면 동작·props·Flyout 더보기 동작
- `widgets/` 아래 feature 로컬 배치 (core로 올리지 않음)

## 이번 작업에서 만들지 않음
- 동작 변경·UI 리디자인
- ViewModel/Repository 변경
- 공용 core Flyout 추상화

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.

## 완료 확인
- `./scripts/agent_check.sh` 통과
- 호스트는 조합만, 분리 파일에 각 위젯이 있다
- 미디어 Flyout·탭·PDF/영상 표시 동작 유지

## 구현 순서
1. 프롬프트 저장
2. 분리 파일 작성 → 호스트 정리
3. `./scripts/agent_check.sh`
