# 첨부 해제 버튼 문구 사용자화

## 목표
첨부 탭 DetachAsset 버튼·실패 다이얼로그 문구를 DeleteAsset과 혼동되지 않는 사용자 말로 맞춘다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md` (가이드라인 저장소는 워킹 트리 밖에서 읽기만)
3. `lib/src/presentation/features/job_lookup/widgets/job_attachment_tab.dart`
4. `protos/mediatag/asset/v1/asset.proto` (DetachAsset vs DeleteAsset)

## 현재 상태
- 버튼 라벨이 `에셋 떼기`이다.
- 실패 다이얼로그 제목이 `에셋을 제거할 수 없습니다`이다.
- DetachAsset은 작업 첨부만 끊고 파일은 남긴다. DeleteAsset은 행·파일을 지운다.

## 바꿀 것
1. 버튼 `에셋 떼기` → `첨부 해제`
2. 실패 다이얼로그 제목 `에셋을 제거할 수 없습니다` → `첨부를 해제할 수 없습니다` (본문 서버 message 유지)

## 유지할 것
- `_didTapDetach` / DetachAsset 호출
- 「자세히 보기」라벨, DeleteAsset 화면 문구

## 이번 작업에서 만들지 않음
- DeleteAsset UX·다른 화면 일괄 문구 변경

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
