# 에셋 떼기 예외 다이얼로그

## 목표
작업 상세 첨부 탭에서 DetachAsset이 실패하면 ConnectException 메시지를 사용자용으로 정리해 ContentDialog로 보여 준다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md` (가이드라인 저장소는 워킹 트리 밖에서 읽기만)
3. `lib/src/presentation/features/job_lookup/widgets/job_attachment_tab.dart`
4. `lib/src/presentation/features/job_lookup/job_lookup_detail_view_model.dart` (`detachAsset`)
5. 계약: DetachAsset `failed_precondition` 예) `사용 중: 코멘트 20의 녹화 — DeleteComment 먼저`

## 현재 상태
- `job_attachment_tab.dart`: 에셋 떼기는 `_run(() => _viewModel.detachAsset(...))`를 쓴다. `_run`은 예외를 `error.toString()`으로 `_error`에 넣고 탭 상단 빨간 텍스트로만 보여 준다.
- `remote_job_admin_repository.dart`: DetachAsset 호출만 하고 ConnectException을 감싸지 않는다.
- `ConnectException.toString()`은 `[failed_precondition] …` 형태다. 사용자에게는 `message`가 적합하다.

## 바꿀 것
1. `job_attachment_tab.dart`: 에셋 떼기만 전용 핸들러로 분리한다. 실패 시 `ContentDialog`를 연다. 제목은「에셋을 뗄 수 없습니다」, 본문은 ConnectException이면 `message`(비면 toString), 아니면 `toString()`. 닫기 버튼만 둔다.
2. 성공 시 기존처럼 `detachAsset` → 첨부 재로드를 유지한다. 떼기 실패는 인라인 `_error`에 넣지 않는다.

## 유지할 것
- ViewModel·Repository의 DetachAsset 호출 흐름
- 붙이기·업로드·패스 변경의 `_run`과 인라인 `_error`
- 다른 화면의 DeleteAsset 예외 문구 매핑

## 이번 작업에서 만들지 않음
- 새 예외 타입·헬퍼 계층
- 저장소 전역 ConnectException 매핑
- 코멘트 삭제 유도 UX

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
