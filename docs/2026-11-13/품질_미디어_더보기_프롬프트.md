# 품질 미디어 ListAssets 더보기

## 목표
콤보에는 지금까지 받은 미디어를 모두 보여 주고, `next_page_token`이 있으면 **더보기**로 다음 `ListAssets` 페이지를 이어 받아 목록에 붙인다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md`
3. `lib/src/data/repositories/remote_quality_job_media_repository.dart`
4. `lib/src/presentation/features/quality_issue/quality_issue_view_model.dart`
5. `lib/src/presentation/features/quality_issue/widgets/quality_media_host.dart`
6. `protos/.../asset.proto` ListAssets
7. 계약·화면안: 없음

## 현재 상태
- `listJobMedia`가 첫 페이지만 요청하고 token을 버림
- ViewModel `_jobMediaCache`는 한 번 채우면 끝
- 콤보만 있고 더보기 UI 없음

## 바꿀 것
1. 도메인: `QualityJobMediaPage { items, nextPageToken }` 추가
2. Repository/UseCase: `pageToken` 인자, 반환을 `QualityJobMediaPage`로. `PAGE_SIZE = 50` 유지
3. ViewModel: 캐시 append, `didTapLoadMoreJobMedia`, `hasMoreJobMedia`, `isLoadingMoreJobMedia`
4. UI: 콤보 옆 더보기 버튼 + screen 연결
5. 더보기 표시 기준은 API `nextPageToken`(job 단위)

## 유지할 것
- 콤보 선택·PDF/영상 호스트
- pass 필터는 캐시 후 클라이언트
- pageSize 50

## 이번 작업에서 만들지 않음
- 자동 전체 페이지 루프
- 서버 kind 필터 추가
- 새 추상 캐시 계층

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
