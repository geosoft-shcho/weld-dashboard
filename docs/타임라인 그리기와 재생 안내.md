## 1. 시간축은 셋이다

| 축 | 0의 뜻 | 어디서 읽나 | 단위 |
|---|---|---|---|
| 타임라인 축 | 작업 시작(`job.started_at`) | `Clip.timeline_start_ns`·`timeline_end_ns` | ns |
| Asset 축 | 그 파일의 첫 프레임·첫 샘플(`Asset.recorded_at`) | `Clip.source.start_ns`·`end_ns`, `Asset.duration_ns` | ns |
| 파일 축 | 파일에 적힌 시각 그대로 | `video.currentTime`·`video.duration` | 초 |

타임라인 축과 Asset 축은 서버가 주는 값이고, 파일 축은 브라우저가 파일을 열어야 알 수 있는 값이다.
Asset 축과 파일 축은 대개 같지만 **같다고 가정하면 안 된다**(§5).

변환은 두 줄이다. `T`는 타임라인 위의 현재 시각(ns)이다.

```
클립 길이 = timeline_end_ns − timeline_start_ns
소스 길이 = source.end_ns − source.start_ns        (source 구간이 비면 0 ~ Asset.duration_ns)
클립 배속 = 소스 길이 / 클립 길이                   (두 길이가 같으면 1)

Asset 축 위치(ns) = source.start_ns + (T − timeline_start_ns) × 클립 배속
파일 축 위치(초)  = 파일 첫 시각(초) + Asset 축 위치 / 1e9
```

- `source.start_ns`·`end_ns`는 "파일의 어디부터 어디까지 쓰는가"다.
- **클립 배속은 사용자가 정하는 값이 아니다.** 클립 길이와 소스 길이에서 자동으로 정해지고, 저장하는 칸도 없다. 보통은 두 길이가 같아서 1이다(§3.2).
- 보는 사람이 고르는 **타임라인 배속(재생 속도)** 은 이것과 별개다(§6).

## 2. 서버 값과 파일 값 — 무엇을 어디서 읽나

**배치와 그리기는 서버 값만 쓴다. 파일 값은 재생할 때 그 영상 하나의 위치를 맞추는 데만 쓴다.**
이렇게 해야 파일을 열지 않고도 타임라인 전체를 그릴 수 있고, 영상이 여러 개여도 메타데이터가 뜨기를 기다리지 않는다.

| 알고 싶은 것 | 읽는 곳 | 쓰지 말 것 |
|---|---|---|
| 클립이 타임라인 어디에 있나 | `Clip.timeline_start_ns`·`timeline_end_ns` | – |
| 파일의 어느 구간을 쓰나 | `Clip.source.start_ns`·`end_ns`(비면 Asset 전체) | – |
| 소스 전체 길이 | `Clip.source.asset_duration_ns`(= `Asset.duration_ns`) | `video.duration` — 첫 시각이 0이 아니면 첫 시각만큼 길게 나온다 |
| 타임라인 전체 길이 | 모든 클립의 `timeline_end_ns` 중 가장 큰 값 | 영상 하나의 길이 |
| 프레임 간격 | 그 위치를 덮는 영상 클립의 `Asset.properties.fps` | 타임라인 고정 fps(없다) |
| 해상도·코덱 | `Asset.properties` | – |
| 실제 촬영 시각 | `Asset.recorded_at` + Asset 축 위치 | `collected_at`(적재 시각이다) |
| 파일 첫 시각 | `Clip.source.asset_start_time_ns`(= `Asset.properties.start_time_ns`, 영상·음성, §5) | `video.seekable`·첫 `currentTime`으로 짐작하기 |
| 파일 주소 | `Asset.content_url`(매번 응답에서 받는다. 저장은 `asset_id`로) | 저장해 둔 경로 |

**재생과 자르기에 필요한 값은 클립 하나에 다 들어 있다.**

| `Clip.source`의 칸 | 뜻 | 누가 쓰나 |
|---|---|---|
| `asset_id` | 가리키는 파일 | 화면이 보낸다 |
| `start_ns`·`end_ns` | 그 파일에서 쓰는 구간(Asset 축) | 화면이 보낸다 |
| `locator` | 쪽·영역 같은 위치(종류별) | 화면이 보낸다 |
| `asset_duration_ns` | 소스 전체 길이 — `start_ns`·`end_ns`의 한계 | 서버가 채운다(읽기 전용) |
| `asset_start_time_ns` | 파일에 적힌 첫 시각 | 서버가 채운다(읽기 전용) |

- 읽기 전용 두 칸은 요청에 넣어도 무시된다. `UpdateClip`에 `source`를 보낼 때 빼도 된다.
- 종류에 따라 비어 있다: 길이는 시간이 없는 소스(이미지·PDF·파일)에서, 첫 시각은 영상·음성이 아닌 소스(포즈·센서·자막)에서 비어 있다. 비어 있는 첫 시각은 0으로 본다.
- 아직 클립이 아닌 Asset(자료 목록에서 고른 것)은 같은 값을 `Asset.duration_ns`·`Asset.properties.start_time_ns`에서 읽는다.
- 해상도·fps·파일 주소(`content_url`)는 여전히 Asset에서 읽는다. 편집 화면은 `GetTimeline(include_assets=true)`로 연다.

ns 값은 JSON에서 문자열(int64)로 온다. 숫자로 바꿔 써도 된다(약 104일까지 오차 없음).

## 3. 배치

- **자동 배치**: 서버가 `recorded_at − job.started_at`을 `timeline_start_ns`로 놓는다. 화면은 받은 값을 그대로 쓴다.
  `recorded_at`이 없는 자료는 자동으로 놓이지 않으므로 사람이 위치를 잡는다(§3.4).
- **자동 배치는 겹치지 않게 놓는다.** 같은 트랙에서 겹치게 되면 지금처럼 `<트랙> (2)` 같은 옆 트랙으로 내린다. 겹침은 사람이 손으로 놓을 때 생긴다.
- **기본 클립 길이는 Asset 길이다.** 자동이든 손으로든 처음 놓을 때는 `클립 길이 = Asset.duration_ns`, 소스 구간은 Asset 전체로 놓는다(클립 배속 1).
- **클립 사이의 빈 구간은 정상이다.** 채우거나 당기지 않는다.
- **파생 클립(포즈·자막·영역)**: 대상 영상 클립과 같은 타임라인 구간·같은 소스 구간으로 놓인다(포즈). 그래서 대상 클립과 클립 배속이 같다. 대상은 `provenance.target_kind`·`target_id`로 찾고, 한 번에 받으려면 `GetClip(include_target=true)`를 쓴다.
- **패스로 열기**: `GetTimeline(pass_id)`가 주는 `window_start_ns`·`window_end_ns`로 확대해 연다.

### 3.1 같은 트랙에서 겹칠 수 있다

트랙은 "한 줄에 클립 하나"가 아니라 클립을 묶는 이름표다. 같은 트랙의 클립끼리 구간이 겹쳐도 된다.

- **줄 나누기**: 겹치는 클립은 트랙 안에서 줄을 나눠 쌓아 그린다. 줄 번호는 저장하지 않고 화면이 매번 계산한다.
  클립을 `timeline_start_ns` 순(같으면 `clip_id` 순)으로 훑으면서, 그 시작 시각에 비어 있는 가장 위 줄에 넣는다. 빈 줄이 없으면 줄을 하나 늘린다.
- **트랙 높이** = 줄 수 × 줄 높이. 겹침이 없으면 지금처럼 한 줄이다.
- 줄 번호는 계산값이라 클립을 넣거나 빼면 다른 클립의 줄이 바뀔 수 있다. 끌어 옮기는 동안에는 줄을 다시 계산하지 않고, 놓은 뒤에 한 번 계산한다.
- 맞닿는 것(앞 클립의 끝 = 뒤 클립의 시작)은 겹침이 아니다. 구간은 `[start, end)`다.
- **겹친 클립은 하나만 보인다.** 미리보기 칸이 하나이기 때문이다(§6). 사용자가 고른 클립을, 고른 것이 없으면 **나중에 만든 클립**(`clip_id`가 큰 것)을 보인다.
- 프레임 스냅처럼 기준이 하나여야 하는 계산도 같은 순서로 고른다(고른 클립 → 나중에 만든 클립).
- 화면 자리를 다투는 것은 일부 종류뿐이다(§3.3).

### 3.2 클립 길이와 소스 길이 — 다르면 자동으로 배속

**보통은 두 길이가 같다.** 클립 끝을 끌어 길이를 바꾸면 쓰는 소스 구간이 함께 바뀌기 때문이다(자르기, §3.5).

- 클립은 소스를 들여다보는 창이다. 창을 줄이면 소스의 일부만 쓰고, 다시 펴면 더 많이 쓴다.
- **`source.start_ns`가 항상 0인 것은 아니다.** Asset 전체를 놓으면 0이고, 앞을 자르면 자른 만큼 커진다.
  자동 배치도 패스 구간에 맞춰 앞뒤를 잘라 놓으므로, 처음부터 0이 아닌 클립이 있다(예: 소스 3.424초부터 쓰는 영상 클립).

**두 길이가 다르면 소스 구간 전체를 클립 길이에 맞춰 보여 준다. 그때의 속도가 클립 배속이다.**
사용자가 숫자로 정하는 것이 아니라 `소스 길이 / 클립 길이`로 저절로 정해진다.

두 길이가 달라지는 경우:

- **길이가 정해진 자리에 다른 길이의 소스를 붙일 때.** 클립 길이를 10초로 두었는데 15초짜리 소스를 붙이면, 클립은 10초 그대로이고 소스 15초 전체가 그 안에 들어간다(1.5배).
- **소스 구간은 그대로 두고 클립 길이만 바꿀 때**(§3.5의 "길이만 바꾸기").
- 옛 데이터나 화면이 아닌 다른 호출자가 그렇게 저장했을 때.

| 경우 | 클립 배속 | 화면 |
|---|---|---|
| 길이가 같다 | 1 | 그대로 재생 |
| 클립이 소스보다 짧다(10초 클립에 15초 소스) | 1.5 | 빠르게 재생 |
| 클립이 소스보다 길다(10초 클립에 5초 소스) | 0.5 | 느리게 재생 |
| 소스 길이가 0이다(한 시점) | 0 | 그 한 장면을 클립 길이 내내 보여 준다 |
| 소스에 시간이 없다(이미지·PDF·태그·관계) | – | 클립 길이 내내 같은 내용. 배속을 계산하지 않는다 |

예: 클립이 타임라인 25~35초(10초), 소스가 0~15초(15초)면 클립 배속은 1.5다. 타임라인 28초의 소스 위치는 `0 + (28 − 25) × 1.5 = 4.5초`다.

- 클립 배속이 1이 아닌 클립에는 배속을 표시한다(예: `x1.5`). 눈으로는 길이만 다른 클립과 구분되지 않는다.
- 소스의 일부만 실제 속도로 쓰고 싶으면 배속이 걸린 뒤에 "배속을 1로 되돌리기"나 자르기로 고친다(§3.5).

### 3.3 종류별로 무엇이 달라지나

겹침 허용과 클립 배속은 모든 종류의 클립에 똑같이 적용되는 규칙이다. 다만 화면에서 신경 쓸 일은 종류마다 다르다.

| 종류 | 겹쳤을 때 | 길이가 다를 때(클립 배속) |
|---|---|---|
| 영상 | 미리보기 자리를 다툰다 — 하나만 보인다(§3.1) | 적용. `playbackRate` |
| 이미지·PDF·포인트클라우드 | 영상과 같다(뷰어 자리를 다툰다) | 시간이 없으면 해당 없음 — 클립 길이 내내 같은 내용. 포인트클라우드가 스트림이면 영상처럼 적용 |
| 음성 | 자리는 안 다투지만 소리가 섞인다 — 하나만 내거나 함께 낸다 | 적용 |
| 자막 | 다투지 않는다 — 여러 줄로 함께 보인다(화자 겹침) | 적용. 자막 시각을 식으로 바꾼다 |
| 포즈·영역 | 다투지 않는다 — 대상 영상 위에 함께 그린다. 대상 영상이 안 보이면 그리지 않는다 | 적용. 대상 영상 클립과 같은 구간이라 같은 배속 |
| 센서(시계열) | 다투지 않는다 — 같은 그래프에 선을 함께 그린다 | 적용. 가로축을 식으로 바꾼다 |
| 태그·관계·파일 | 다투지 않는다 — 타임라인에 줄만 나뉜다 | 해당 없음(소스에 시간이 없다) |

정리하면 **"어느 것을 보일까"를 정해야 하는 것은 미리보기 자리를 혼자 쓰는 종류(영상·이미지·PDF·포인트클라우드)와 소리(음성)뿐**이고, 나머지는 겹쳐도 함께 보이면 된다.
타임라인에서 줄을 나눠 그리는 것(§3.1)은 모든 종류가 같다.

### 3.4 손으로 하나씩 놓을 때

1. **Asset을 트랙에 끌어다 놓는다.** 작업에 첨부되지 않은 Asset이면 서버가 `CreateClip`에서 자동으로 첨부한다.
2. **종류**: `Clip.kind`는 Asset의 종류에 맞춘다.
3. **위치(`timeline_start_ns`)**
   - Asset에 `recorded_at`이 있으면 `recorded_at − job.started_at`을 먼저 제안한다(그 자리에 붙게 한다). 사용자가 다른 곳에 놓으면 놓은 자리를 쓴다.
   - `recorded_at`이 없으면 놓은 자리를 쓴다.
4. **길이**: `timeline_end_ns = timeline_start_ns + Asset.duration_ns`. 기본은 Asset 전체를 실제 속도로 놓는다.
   - 시간이 있는 Asset은 `source.start_ns = 0`, `source.end_ns = Asset.duration_ns`를 채워 보낸다. 비워도 "Asset 전체"로 같은 뜻이지만, 채워 두면 뒤에 자를 때 계산이 한 가지로 끝난다.
   - `duration_ns`가 없는 Asset(이미지·PDF·파일)은 `source` 구간을 비우고, 화면이 정한 기본 길이(예: 5초)로 놓은 뒤 사용자가 늘인다.
   - 태그·관계는 Asset이 없으므로 사용자가 끌어서 구간을 정한다.
5. **겹침**: 손으로 놓을 때는 막지 않는다. 겹치면 줄이 나뉘어 보이고(§3.1) 그대로 저장한다.
6. **그 뒤 조정**: 옮기기·자르기·나누기(§3.5).

**길이가 정해진 자리에 놓을 때**는 4번이 다르다. 이미 있는 클립의 소스를 바꾸거나, 구간을 먼저 정해 두고 거기에 Asset을 붙이는 경우다.

- 타임라인 구간은 그대로 둔다.
- 소스 구간은 Asset 전체(`0 ~ Asset.duration_ns`)로 넣는다.
- 두 길이가 다르면 클립 배속이 자동으로 정해진다(10초 자리에 15초 소스 → 1.5배). 화면은 배속 표시만 붙이면 된다.
- 시간이 없는 Asset은 배속이 없으므로 그대로 붙인다.

처음 놓을 때 보내는 값(389.295초짜리 영상을 타임라인 10초 지점에 놓는 경우):

```
kind              = VIDEO
track_id          = (놓은 트랙)
timeline_start_ns = 10_000_000_000
timeline_end_ns   = 399_295_000_000      (= start + Asset.duration_ns)
source.asset_id   = (Asset)
source.start_ns   = 0
source.end_ns     = 389_295_000_000      (= Asset.duration_ns)
```

### 3.5 손으로 편집할 때 값을 정하는 규칙

값은 화면이 계산해서 보낸다. 아래 한계 가운데 소스 구간은 서버도 검사한다 — 어기면 INVALID_ARGUMENT이고, 끝이 반올림만큼(100ms 이내) 넘으면 서버가 Asset 길이로 맞춘다. 그래도 화면이 먼저 지켜서 요청이 거절되지 않게 한다.

**지켜야 할 한계**

```
0 ≤ source.start_ns ≤ source.end_ns ≤ Asset.duration_ns
timeline_start_ns < timeline_end_ns
```

- **소스 구간은 Asset 길이를 넘을 수 없다.** 파일에 없는 구간을 가리키게 된다.
- 타임라인 길이와 소스 길이는 같지 않아도 된다(다르면 클립 배속, §3.2).
- 클립 길이의 최솟값은 화면이 정한다(예: 영상 한 프레임 `1e9 ÷ fps` ns).
- `timeline_start_ns`는 0보다 작을 수 없다. 작업 시작 전의 자료는 앞을 잘라서 놓는다.

**끝을 끄는 기본 동작은 자르기다**

- 클립 끝을 그냥 끌면 자르기다. 쓰는 소스 구간이 바뀌고 클립 배속은 그대로다.
- 소스 구간을 두고 클립 길이만 바꾸는 동작("길이만 바꾸기")은 보조 키를 누르고 끌거나 따로 고르게 둔다. 실수로 속도가 바뀌면 안 된다.
- 자르다가 소스의 끝(`source.start_ns = 0` 또는 `source.end_ns = Asset.duration_ns`)에 닿으면 멈춘다. 더 끌어도 "길이만 바꾸기"로 넘어가지 않는다.

**동작별로 바뀌는 값**(`d`는 타임라인에서 끈 거리, 오른쪽이 +)

| 동작 | `timeline_start` | `timeline_end` | `source.start` | `source.end` | 클립 배속 |
|---|---|---|---|---|---|
| 옮기기(가운데를 끈다) | +d | +d | – | – | 그대로 |
| 앞 자르기(앞 끝을 끈다) | +d | – | +d × 배속 | – | 그대로 |
| 뒤 자르기(뒤 끝을 끈다) | – | +d | – | +d × 배속 | 그대로 |
| 소스 밀기(소스 막대에서 쓰는 구간을 끈다, §9.2) | – | – | +e | +e | 그대로 |
| 앞 길이만 바꾸기 | +d | – | – | – | 자동으로 바뀜 |
| 뒤 길이만 바꾸기 | – | +d | – | – | 자동으로 바뀜 |
| 소스 붙이기·바꾸기(자리 고정) | – | – | 0 | `Asset.duration_ns` | 자동으로 정해짐 |
| 배속을 1로 되돌리기 | – | start + 소스 길이 | – | – | 1 |

배속이 1인 보통 클립에서는 자르기가 "타임라인과 소스를 같은 만큼"이다.
소스 밀기의 `e`는 소스 막대에서 끈 거리다. 클립의 자리와 길이는 그대로 두고 소스의 어느 부분을 쓸지만 바꾼다.

**나누기**(클립 하나를 시각 `x`에서 둘로)

```
경계의 소스 위치 m = source.start_ns + (x − timeline_start_ns) × 클립 배속
앞 클립: 타임라인 start ~ x,  소스 source.start ~ m     (기존 클립을 고친다)
뒤 클립: 타임라인 x ~ end,    소스 m ~ source.end       (새로 만든다)
```

두 클립은 맞닿을 뿐 겹치지 않고, 클립 배속도 그대로다.

**반올림**

- 모든 값은 정수 ns다. 배속을 곱해 나온 소스 값은 가장 가까운 정수로 맞춘다.
- 영상을 자를 때는 소스 쪽을 프레임 경계(`k × 1e9 ÷ fps`)에 먼저 맞추고, 타임라인 쪽을 그에 맞춰 다시 계산한다. 반대로 하면 프레임 중간에서 잘린다.
- 클립 배속은 저장하지 않으므로 고칠 때마다 두 길이에서 다시 구한다. 화면에 들고 있던 값을 계속 곱해 쓰지 않는다(오차가 쌓인다).

**소스 구간이 비어 있는 클립**

- 자동 배치나 예전 데이터에는 `source` 구간이 빈 클립이 있을 수 있다. `0 ~ Asset.duration_ns`로 읽고, 처음 고칠 때 채워서 저장한다.

## 4. 그리기

- 가로 위치와 폭은 타임라인 축만으로 정한다.
  `x = (timeline_start_ns − 보이는 구간 시작) × 배율`, `폭 = (timeline_end_ns − timeline_start_ns) × 배율`.
- 세로는 `Track.order` 순이고, `visible=false`인 트랙은 그리지 않는다.
- 렌더러는 `Clip.kind`로 고른다.
- 썸네일·파형처럼 파일 내용이 필요한 그림은 Asset 축 위치로 요청한다(파일 축 위치는 §1의 둘째 줄로 바꾼다).
- 세로는 트랙 안에서 다시 줄로 나뉜다(§3.1).
- 프레임 단위로 붙이기(스냅)는 그 위치를 덮는 영상 클립을 기준으로 한다. 타임라인 위의 프레임 간격은 `1 ÷ (properties.fps × 클립 배속)`초다(배속 1.5면 간격이 2/3). 덮는 영상이 여러 개면 §3.1의 규칙으로 하나를 고르고, 없으면 스냅하지 않는다.

## 5. 파일 첫 시각이 0이 아닌 영상

긴 녹화에서 잘라 낸 영상은 원래 시각을 그대로 들고 있어서 첫 프레임 시각이 0이 아니다
(깊이 영상은 세션 시작부터, 액션캠은 원본 파일 위치부터). 업로드 문제가 아니라 파일이 그렇게 만들어진 것이다.

실측(Asset 5547 `depth_front_view.mp4`):

| 값 | 크기 |
|---|---|
| 첫 프레임 시각(파일 축) | 428.559초 |
| 실제 내용 길이 | 389.294초 (`Asset.duration_ns`와 같음) |
| 파일에 적힌 전체 길이(`video.duration`) | 817.854초 (= 앞의 둘을 더한 값) |

그래서 크롬은 7분 8초부터 재생한다. 화면은 이렇게 맞춘다.

- 길이는 `Asset.duration_ns`를 쓴다.
- 표시하는 현재 위치는 `video.currentTime − 파일 첫 시각`이다.
- 찾아갈 때는 `video.currentTime = 파일 첫 시각 + Asset 축 위치`로 넣는다.
- 그 영상의 끝은 `파일 첫 시각 + Asset.duration_ns`다. `ended` 이벤트를 기다리지 않는다(§6).

**파일 첫 시각을 아는 방법**

- `Asset.properties.start_time_ns`를 읽는다(ns). 영상·음성 Asset에 모두 들어 있고, 새로 올리는 파일은 업로드 후처리가 채운다. 칸이 없으면 0으로 본다.
- 드문 경우가 아니다. 운영 DB의 영상 6,658개 가운데 3,843개(58%)가 0이 아니다(5.0초~428.6초). 깊이 영상(`depth_*_view`·`color`)의 85~90%, 액션캠의 59%가 해당한다. 포즈를 겹쳐 그린 영상(`skeleton2d_overlay`)은 모두 0이다.

파일을 0부터 시작하게 다시 만드는 것은 하지 않는다. 원본의 sha256이 바뀐다.

### 5.1 예시 — 7초부터 시작하는 영상의 일부를 놓을 때

타임라인 5~15초 구간에, 파일 첫 시각이 7초인 영상의 10~30초를 소스로 놓는다.

**저장하는 값** — 소스 구간은 Asset 축(첫 프레임이 0)이다. 파일 첫 시각은 넣지 않는다.

| 값 | 크기 |
|---|---|
| 타임라인 구간 | 5~15초 (10초) |
| 소스 구간 | 10~30초 (20초) |
| 클립 배속 | 20 ÷ 10 = 2.0 (자동) |

**재생할 때** — 첫 시각 7초는 마지막에 한 번만 더한다.

```
Asset 축 위치 = 10 + (T − 5) × 2.0
파일 축 위치  = 7 + Asset 축 위치
```

| 타임라인 `T` | Asset 축 위치 | 영상에 넣는 `currentTime` |
|---|---|---|
| 5초(클립 시작) | 10초 | 17초 |
| 10초 | 20초 | 27초 |
| 15초(클립 끝) | 30초 | 37초 |

`playbackRate`는 2.0이다(타임라인 배속 1일 때). 파일에서는 17~37초가 재생된다.

**구간을 고를 때 조심할 것**

- "10초에서 30초"가 첫 프레임부터 센 값이면 위 그대로다.
- 플레이어의 `video.currentTime`이 10~30초였다면 파일 축 값이다. 저장하기 전에 7초를 빼서 소스 3~23초로 넣는다. 빼지 않으면 의도한 곳보다 7초 뒤가 재생된다.
- 그래서 플레이어는 처음부터 `currentTime − 파일 첫 시각`을 보여 주고, 구간을 고를 때도 그 값을 쓴다. 사용자는 0부터 시작하는 시각만 본다.
- 소스 끝이 Asset 길이 안인지는 `Asset.duration_ns`와 비교한다. `video.duration`은 첫 시각만큼 길게 나온다 — 내용이 25초인 영상이면 32초로 나와서, 그것과 비교하면 30초가 통과되지만 실제로는 5초가 넘친다.

### 5.2 브라우저가 재생하지 못하는 파일 — 깊이 원본(mkv)

**mkv 파일은 브라우저에서 재생할 수 없다. 같은 폴더의 mp4를 쓴다.**

운영 DB 실측(2026-10-13):

| 파일 | 종류 | 코덱 | 개수 | 브라우저 재생 |
|---|---|---|---|---|
| `depth_*_raw16.mkv` | 포인트클라우드 | FFV1, 16비트 회색(`gray16le`) | 1,809개(약 9.4TB) | 불가 |
| `*.mp4` | 영상 | H.264 | 6,658개 | 가능 |

- 재생이 안 되는 이유는 mkv라는 그릇이 아니라 안에 든 코덱이다. FFV1을 풀 수 있는 브라우저가 없고, 16비트 깊이값(mm)은 그대로는 화면에 그릴 수도 없다.
- mkv는 깊이값을 손실 없이 담은 분석용 원본이다. 화면에서는 내려받기만 제공한다.
- 볼 수 있는 영상은 이미 따로 있다. 같은 적재 폴더에 `depth_front_view.mp4`·`depth_back_view.mp4`(깊이를 눈에 보이게 그린 것)와 `depth_*_color.mp4`(컬러)가 H.264로 함께 들어 있다.
- 지금 mkv를 가리키는 클립은 없다. 자동 배치는 mp4 쪽을 놓는다.
- mkv에서 만든 파생 Asset으로 기록된 것은 없다(`parent_asset_id`가 mkv인 Asset 0개). mkv와 `view.mp4`는 같은 폴더·같은 이름 규칙(`depth_front_*`)으로만 짝이 지어진다.
- 사용자가 mkv를 손으로 놓으면 미리보기에는 "이 파일은 재생할 수 없음"과 짝이 되는 mp4를 안내한다. mkv를 서버에서 다시 인코딩해 보여 주는 것은 하지 않는다 — 같은 내용의 mp4가 이미 있다.

## 6. 재생 — 시계는 하나, 미리보기도 하나

**타임라인 시각 `T` 하나가 기준이다. 미리보기 칸은 하나이고, 고른 트랙에서 그 시각에 걸린 클립을 보인다.**
영상은 `T`를 따라가는 쪽이다. 영상마다 길이·시작 위치·첫 시각이 다르고 중간에 빈 구간도 있어서, 영상을 기준으로 삼으면 그 영상이 끝나거나 다른 영상으로 바꾸는 순간 시각이 끊긴다.

**시계**
- 재생 중에는 화면 갱신 주기마다 `T`를 실제 흐른 시간 × 타임라인 배속만큼 늘린다.
- `T`가 타임라인 전체 길이에 닿으면 멈춘다.
- **타임라인에는 고정 fps가 없다.** 시계는 실제 시간으로 흐르고, 화면은 모니터 갱신 주기마다 다시 그린다. 영상은 각자 자기 fps로 재생된다.
  30fps 영상, 24fps 포즈, 수백 Hz 센서가 한 타임라인에 놓이므로 fps 하나로 맞추면 나머지를 전부 반올림해야 한다.
  프레임 단위가 필요한 곳(한 프레임씩 넘기기, 스냅)은 보이는 클립의 fps를 쓴다(§4). 타임라인을 영상 파일로 내보내는 기능이 생기면 그때 출력 fps를 정한다.

**무엇이 보이나**
- **고른 트랙**이 하나 있다. 기본은 맨 위 트랙이고, 사용자가 트랙이나 그 트랙의 클립을 눌러 바꾼다. 트랙에 "영상 트랙" 같은 종류는 없다 — 어떤 트랙이든 고를 수 있다.
- 보이는 클립은 고른 트랙에서 `T`를 덮는 클립이다(`timeline_start_ns ≤ T < timeline_end_ns`). 겹쳐서 둘 이상이면 §3.1의 순서로 하나를 고른다.
- 그 클립을 종류(`Clip.kind`)에 맞게 보인다.

  | 클립 종류 | 미리보기 |
  |---|---|
  | 영상 | 재생한다 |
  | 이미지·PDF·포인트클라우드 | 그 종류의 뷰어로 보인다 |
  | 포즈·영역 | 대상 영상 클립을 재생하고 그 위에 그린다(대상은 `provenance.target_*`) |
  | 음성·자막·센서·태그·관계·파일 | 미리보기에 보일 것이 없다. 직전 화면을 그대로 둔다 |
- 덮는 클립이 없으면 빈 화면이다. 다른 트랙의 영상으로 알아서 넘어가지 않는다.
- 고르지 않은 트랙의 영상은 재생하지 않는다.

**주기마다 하는 일**
1. 보이는 클립을 정한다.
2. 있으면 §1의 식으로 그 영상의 목표 위치를 구한다. 실제 위치와 0.1초 넘게 벌어졌으면 `currentTime`을 다시 넣고, 아니면 그냥 재생하게 둔다.
3. 없으면 영상을 멈추고 빈 화면으로 둔다. 시계는 계속 간다.
4. 보이는 클립이 바뀌었으면(같은 트랙의 다음 클립으로 넘어감, 겹친 클립이 시작됨) §6.1과 같은 방법으로 바꾼다.

**찾아가기**
- `T`를 바꾸고 보이는 영상에 목표 위치를 넣는다. `seeked`가 된 뒤 재생을 잇는다.

**버퍼링**
- 보이는 영상이 기다리는 중(`waiting`)이면 시계를 멈춘다. 준비되면 잇는다.

**소리와 배속**
- 소리는 보이는 영상의 것을 낸다. 음성 클립은 화면 자리를 쓰지 않으므로 고른 트랙과 상관없이 `T`에 걸리면 낸다.
- 배속은 둘이다.
  - **타임라인 배속**(재생 속도): 보는 사람이 고르는 값 하나(빨리 보기·느리게 보기). 시계가 흐르는 속도이고 저장하지 않는다. 기본 1.
  - **클립 배속**: 클립마다 두 길이에서 자동으로 정해지는 값(§3.2). 대부분 1.
- 영상에는 `playbackRate = 타임라인 배속 × 클립 배속`을 넣는다. 보이는 클립이 바뀌면 값도 바뀔 수 있다.
- 브라우저가 받는 범위를 벗어나면(크롬은 대략 0.0625~16) 재생시키지 않고 주기마다 `currentTime`을 직접 넣어 장면만 바꾼다. 클립 배속 0(한 시점)도 같은 방식이다. 이때 그 영상의 소리는 끈다.
- 속도가 1이 아닐 때 소리는 음높이를 유지한다(`preservesPitch`, 기본값).

**영상 요소**
- 한 번에 재생하는 영상은 하나다. 4K 영상(액션캠 3840×2160)이 있어도 동시에 여러 개를 풀지 않는다.
- 요소는 보이는 것 하나와, 곧 쓸 것 하나만 둔다. 같은 트랙의 다음 클립이 1~2초 안에 시작하면 목표 위치를 미리 넣어 둔다.
- 방금까지 보이던 영상의 요소는 바로 버리지 않고 멈춘 채 둔다. 트랙을 오갈 때 다시 쓴다(§6.1).
- 파일은 `content_url`로 구간 요청(Range)해서 받는다. 색인이 파일 끝에 있는 영상도 있어 첫 재생이 조금 늦을 수 있다.

**영상이 아닌 클립(포즈·자막·센서)**
- 같은 `T`에서 Asset 축 위치를 구해 그 데이터 안에서 찾는다. 클립 배속이 있어도 §1의 식 하나로 같다.
- 포즈·영역은 보이는 클립이 그 대상일 때만 영상 위에 그린다.
- 포즈 결과는 시각(초)으로 찾는다. **프레임 번호로 영상과 맞추지 않는다** — 포즈 결과는 24fps, 원본 영상은 30fps인 경우가 있다.
- 센서 CSV의 `t_ns`는 Asset 축과 같은 기준이다(첫 행 0). 그래프·자막·태그는 고른 트랙과 상관없이 `T`를 따라간다.

### 6.1 트랙을 바꿀 때 — 재생 영상 변경

**트랙을 바꿔도 `T`는 그대로다. 바뀌는 것은 고른 트랙뿐이고, 새 영상은 `T`에서 자기 위치를 새로 계산한다.**
앞 영상의 위치(`currentTime`)를 새 영상에 넘기지 않는다. 영상마다 놓인 자리·쓰는 소스 구간·첫 시각·클립 배속이 달라서 같은 숫자가 다른 시각을 뜻한다.

순서:

1. 재생 중이었으면 시계를 멈춘다(`T` 고정).
2. 새 트랙에서 `T`를 덮는 클립을 찾는다.
3. 있으면 §1의 식으로 위치를 구해 그 영상에 `currentTime`과 `playbackRate`를 넣는다.
4. `seeked`가 될 때까지는 앞 영상의 마지막 장면을 그대로 둔다(검은 화면이 끼지 않게). 준비되면 화면을 바꾸고 앞 영상을 멈춘다.
5. 재생 중이었으면 시계를 다시 돌린다.
6. 덮는 클립이 없으면 바로 빈 화면으로 바꾼다. 재생 중이었으면 시계는 멈추지 않고 계속 간다.

함께 바뀌는 것:

- 소리: 새 영상의 소리로 바뀐다.
- 포즈·영역: 새로 보이는 클립이 대상인 것만 그린다.
- 프레임 간격: 한 프레임씩 넘기기와 스냅은 보이는 클립 기준이라, 트랙을 바꾸면 간격이 달라질 수 있다(`1 ÷ (fps × 클립 배속)`).

바뀌지 않는 것:

- `T`, 타임라인의 재생 위치 표시, 센서 그래프·자막·태그.

다시 원래 트랙으로 돌아와도 같은 방법이다. 그동안 시계가 흐른 만큼 앞선 위치에서 보인다.

### 6.2 화면을 오갈 때

**화면 사이에서 주고받는 시각도 `T`(ns) 하나다.** 파일 축 값(`video.currentTime`)과 프레임 번호는 넘기지 않는다.

- 한 화면 안에서는 `T`를 담는 곳을 하나만 둔다. `T`를 쓰는 곳은 재생 시계, 사용자의 찾아가기(눈금·클립·그래프를 누름), 다른 화면에서 받은 시각 셋뿐이다. 영상 요소가 알려 주는 위치(`timeupdate`)로 `T`를 덮어쓰지 않는다.
- 다른 화면으로 갈 때는 `job_id`와 `T`를 주소에 싣는다(예: `?job=123&t=28000000000`). 고른 트랙·클립도 이어야 하면 `track=`·`clip=`을 함께 넘긴다.
- 타임라인이 없는 화면(클립 하나만 보는 뷰어)에서 돌아올 때는 `clip_id`와 Asset 축 위치로 되찾는다.

```
T = timeline_start_ns + (Asset 축 위치 − source.start_ns) ÷ 클립 배속      (클립 배속이 0이면 timeline_start_ns)
```

- 다른 작업이나 대시보드와는 절대 시각으로 맞춘다: `절대 시각 = job.started_at + T`. Asset만 아는 화면은 `Asset.recorded_at + Asset 축 위치`로 넘긴다.

## 7. 서버 반영 상태

이 문서의 규칙 가운데 서버가 바뀌어야 했던 셋은 2026-10-13에 서버와 운영 DB에 반영했다.

| 항목 | 상태 | 내용 |
|---|---|---|
| 같은 트랙 겹침 허용(§3.1) | 반영 | `tacit.clip`의 겹침 금지 제약을 없앴다(이관 14, `clip_track_span_idx`로 조회). `CreateClip`·`UpdateClip`은 겹쳐도 받는다 |
| 소스 구간 검사(§3.5) | 반영 | `CreateClip`·`UpdateClip`이 `0 ≤ start ≤ end ≤ Asset 길이`를 본다. 끝이 100ms 이내로 넘으면 길이로 맞추고, 길이를 모르는 Asset은 끝을 검사하지 않는다 |
| 파일 첫 시각(§5) | 반영 | `Asset.properties.start_time_ns`. 기존 영상 6,658개·음성 8개에 채웠고, 새 파일은 업로드 후처리가 채운다 |
| 클립에 소스 길이·첫 시각(§2) | 반영 | `Clip.source.asset_duration_ns`·`asset_start_time_ns`(읽기 전용). `include_assets` 없이도 온다 |
| 클립 배속(§3.2) | 원래 됨 | 서버는 두 길이가 같은지 검사하지 않는다. 보낸 대로 저장한다 |

**자동 배치는 그대로 겹치지 않게 놓는다.** DB 제약 대신 서버가 놓기 전에 겹침을 조회한다.

- 적재기의 자동 배치: 겹치면 `<트랙> (2)`·`(3)`… 트랙으로 내린다.
- tacit-tag 이관: 겹치면 `<트랙> (겹침 N)` 트랙으로 내린다.
- 도구 결과(포즈·자막): 그 트랙에 이미 겹치는 클립이 있으면(같은 입력을 다시 돌린 경우 등) `<트랙> run<실행 번호>` 트랙에 놓는다. 건너뛰지 않는다.
- 자막은 항목끼리 겹치면 앞 항목의 끝을 잘라 맞춘다.

**남은 것**

- `엔티티.md` §5.3("한 Track 안의 Clip은 절대 겹치지 않는다")과 §5.4("배속 없는 일반 배치에서는 같다"), 스키마 지도의 `tacit.clip` 설명이 아직 옛 내용이다.
- `/clips/{clip_id}/content`는 소스 구간(`source.start_ns`~`end_ns`)을 그대로 잘라 준다. 클립 배속은 적용하지 않는다(받는 쪽이 적용).
- 이미 저장된 클립 가운데 소스 끝이 Asset 길이를 18,000ns 넘는 것이 6개 있다(반올림 차이). 재생에는 영향이 없고, 화면이 그 클립의 소스를 다시 저장하면 서버가 길이로 맞춘다.

## 8. 화면 예시 — 한 작업으로 끝까지

아래 그림은 1칸이 1초다. 정렬이 흐트러지지 않게 그림 안은 영문·숫자만 쓰고 설명은 줄 끝에 붙였다.

### 8.1 놓인 자료

| Asset | 종류 | 길이(`duration_ns`) | 파일 첫 시각 | fps |
|---|---|---|---|---|
| V1 | 영상(깊이 카메라) | 40초 | 428.559초 | 30 |
| V2 | 영상(액션캠) | 20초 | 0초 | 30 |
| V3 | 영상(액션캠) | 15초 | 0초 | 30 |
| P1 | 포즈(V1의 결과) | 40초 | – | – |
| S1 | 센서 CSV | 50초 | – | – |

| 클립 | `clip_id` | 트랙 | Asset | 타임라인 구간 | 소스 구간 | 클립 배속 |
|---|---|---|---|---|---|---|
| A | 101 | 깊이 카메라 | V1 | 0~40초 | 0~40초 | 1.0 |
| E | 102 | 액션캠 | V2 | 10~30초 | 0~20초 | 1.0 |
| B | 103 | 액션캠 | V3 | 25~35초(10초) | 0~15초(15초) | 1.5 (자동: 15 ÷ 10) |
| D | 104 | 액션캠 | V3 | 45~55초 | 5~15초 | 1.0 (V3의 뒤쪽 10초만 씀) |
| P | 105 | 포즈 | P1 | 0~40초 | 0~40초 | 1.0 |
| S | 106 | 센서 | S1 | 5~55초 | 0~50초 | 1.0 |
| T1 | 107 | 태그 | – | 10~35초 | – | – |
| T2 | 108 | 태그 | – | 32~36초 | – | – |

B와 D는 같은 15초짜리 영상을 10초 자리에 놓은 두 가지 방법이다. B는 전체를 10초에 맞췄고(1.5배), D는 10초만 잘라 썼다(실제 속도).
타임라인 전체 길이는 가장 늦은 끝인 **55초**다.

### 8.2 타임라인 그림

```
     0         10        20        30        40        50        60
     |.........|.........|.........|.........|.........|.........|
V1   [A ====================================]                       깊이 카메라 트랙
V2             [E ================]               [D ======]        액션캠 트랙 · 줄 1
                              [B x1.5 =]                            액션캠 트랙 · 줄 2 (E와 25~30초 겹침)
P    [P ====================================]                       포즈 트랙 (A의 포즈)
S         [S ==============================================]        센서 트랙
T              [T1 ====================]                            태그 트랙 · 줄 1 (용접 중)
                                     [T2]                           태그 트랙 · 줄 2 (이상)
                                 ^ T = 28
```

- 액션캠 트랙은 E와 B가 25~30초에 겹쳐서 줄이 둘이다. 줄은 시작 시각 순으로 넣는다: E(10초)가 줄 1, B(25초)는 줄 1이 차 있어 줄 2, D(45초)는 줄 1이 비어 줄 1.
- 트랙은 여전히 하나다. 사람이 겹치게 놓았을 때 늘어나는 것은 줄이지 트랙이 아니다.
- 태그 트랙도 같은 방법으로 T1이 줄 1, T2가 줄 2다.
- 40~45초는 영상이 없는 빈 구간이다. 정상이다.
- B에는 배속 표시(`x1.5`)를 붙인다. 배속이 1인 클립에는 붙이지 않는다.

### 8.3 `T` = 28초일 때 각 클립의 위치

| 클립 | 걸렸나 | Asset 축 위치 | 파일 축 위치(`currentTime`) | `playbackRate`(타임라인 배속 1일 때) |
|---|---|---|---|---|
| A | 예 | 0 + (28 − 0) × 1.0 = 28초 | 428.559 + 28 = 456.559초 | 1.0 |
| E | 예 | 0 + (28 − 10) × 1.0 = 18초 | 0 + 18 = 18초 | 1.0 |
| B | 예 | 0 + (28 − 25) × 1.5 = 4.5초 | 0 + 4.5 = 4.5초 | 1.5 |
| D | 아니오(45초부터) | – | – | – |
| P | 예 | 28초 | 포즈 결과에서 시각 28.0초를 찾는다 | – |
| S | 예 | 0 + (28 − 5) = 23초 | CSV에서 `t_ns` = 23,000,000,000을 찾는다 | – |
| T1 | 예 | – | "용접 중" 표시 | – |
| T2 | 아니오(32초부터) | – | – | – |

영상 A·E·B의 값은 "그 클립이 보인다면" 넣을 값이다. 미리보기 칸이 하나라 실제로 재생하는 영상은 이 가운데 하나다(§8.4).
타임라인 배속을 2로 올리면 `playbackRate`는 A·E가 2.0, B가 3.0이 된다.

세 시간축을 나란히 놓으면 이렇다.

```
A (V1)     timeline   0 ---------------- 28 ---------- 40
           asset      0 ---------------- 28 ---------- 40      (x1.0)
           file     428.559 --------- 456.559 ----- 468.559

B (V3)     timeline  25 ---------------- 28 ---------- 35      (10s)
           asset      0 ---------------- 4.5 --------- 15      (15s -> x1.5)
           file       0 ---------------- 4.5 --------- 15
```

A는 `video.duration`이 468.559초로 나오지만 쓰지 않는다. 길이는 `duration_ns` 40초다.

### 8.4 미리보기 — 트랙을 바꿔 가며

미리보기 칸은 하나다. 아래는 같은 재생 중에 트랙을 오가는 순서다.

**① `T` = 28초, 고른 트랙 = 깊이 카메라.** A가 보이고 그 위에 포즈를 그린다.

```
+----------------------------------+
| track: V1 (depth)   clip: A      |
|                                  |
|   + P (pose overlay)             |
|                                  |
| file 456.559s   rate x1.0        |
| T 00:28 / 00:55                  |
+----------------------------------+
```

**② 같은 시각에 액션캠 트랙으로 바꾼다.** `T`는 28초 그대로다. 액션캠 트랙에서 28초를 덮는 클립은 E와 B이고, 나중에 만든 B(`clip_id` 103)를 보인다.
B의 위치는 A의 위치(456.559초)와 무관하게 `0 + (28 − 25) × 1.5 = 4.5초`로 새로 계산한다. 포즈는 A의 것이라 그리지 않는다.

```
+----------------------------------+
| track: V2 (action)  clip: B      |
|                                  |
|   (E is behind, no pose)         |
|                                  |
| file 4.500s     rate x1.5        |
| T 00:28 / 00:55                  |
+----------------------------------+
```

**③ 타임라인에서 클립 E를 직접 누른다.** 고른 클립이 먼저이므로 E가 보인다. `0 + (28 − 10) = 18초`.

```
+----------------------------------+
| track: V2 (action)  clip: E      |
|                                  |
|   (picked by user)               |
|                                  |
| file 18.000s    rate x1.0        |
| T 00:28 / 00:55                  |
+----------------------------------+
```

**④ 깊이 카메라 트랙으로 돌아와 계속 재생해 `T` = 42초.** A는 40초에 끝났으므로 빈 화면이다. 시계는 계속 가고 센서 그래프도 계속 간다(Asset 축 37초).
액션캠 트랙도 이 시각에는 비어 있지만, 비어 있지 않더라도 알아서 넘어가지 않는다.

```
+----------------------------------+
| track: V1 (depth)   clip: -      |
|                                  |
|   (empty)                        |
|                                  |
|                                  |
| T 00:42 / 00:55                  |
+----------------------------------+
```

**⑤ `T` = 50초에 액션캠 트랙으로 바꾼다.** D는 소스 5초부터 쓰는 클립이라 `5 + (50 − 45) = 10초`다.
D는 B와 같은 Asset(V3)이라 ②에서 쓰던 영상 요소를 다시 쓴다. 위치를 10초로 옮기고 속도를 1.0으로 되돌린다.

```
+----------------------------------+
| track: V2 (action)  clip: D      |
|                                  |
|                                  |
|                                  |
| file 10.000s    rate x1.0        |
| T 00:50 / 00:55                  |
+----------------------------------+
```

트랙을 바꾼 순간마다 넣는 값을 모으면 이렇다.

| 순서 | `T` | 바꾼 뒤 보이는 클립 | 새 영상에 넣는 `currentTime` | `playbackRate` | 앞 영상의 위치(쓰지 않음) |
|---|---|---|---|---|---|
| ① → ② | 28초 | B | 4.5초 | 1.5 | A 456.559초 |
| ② → ③ | 28초 | E | 18초 | 1.0 | B 4.5초 |
| ③ → ④ | 28초 | A | 456.559초 | 1.0 | E 18초 |
| ④ → ⑤ | 50초 | D | 10초 | 1.0 | (빈 화면) |

### 8.5 길이가 정해진 자리에 붙이기 — 클립 B가 만들어지는 과정

10초로 정해 둔 자리(25~35초)에 15초짜리 V3를 붙인다.

```
                              [(10s)===]                            1. 길이가 정해진 자리   타임라인 25~35 (10초)
                              [B x1.5==]                            2. 15초 소스를 붙임     타임라인 25~35 · 소스 0~15 · x1.5 (자동)
     |.........|.........|.........|.........|.........|.........|
     0         10        20        30        40        50        60
```

타임라인 구간은 그대로 두고 소스 구간에 Asset 전체(0~15초)를 넣는다. 배속을 따로 보내지 않는다. 두 길이가 15초와 10초라 1.5배가 저절로 정해진다.

### 8.6 편집 — 클립 B를 옮기고, 자르고, 길이만 바꾸기

```
                              [B ======]                            처음              타임라인 25~35 · 소스 0~15 · x1.5
                                   [B ======]                       옮기기 +5초        타임라인 30~40 · 소스 0~15 · x1.5
                              [B ====]                              뒤 자르기 2초      타임라인 25~33 · 소스 0~12 · x1.5
                              [B ===========]                       길이만 바꾸기 +5초  타임라인 25~40 · 소스 0~15 · x1.0
     |.........|.........|.........|.........|.........|.........|
     0         10        20        30        40        50        60
```

- 옮기기: 타임라인 구간만 민다. 소스 구간과 배속은 그대로다.
- 뒤 자르기: 타임라인을 2초 줄이면 소스는 `2초 × 1.5 = 3초` 줄인다. 배속은 그대로다.
- 길이만 바꾸기: 타임라인만 5초 늘린다. 소스 15초를 15초에 걸쳐 보이게 되어 배속이 1.0이 된다. 배속 표시가 사라진다.

### 8.7 손으로 놓기 — 클립 D가 만들어지는 과정

Asset V3(15초)를 액션캠 트랙 40초 지점에 끌어다 놓고 앞을 5초 자른다. 실제 속도로 10초만 쓰는 방법이다.

```
                                             [D ===========]        1. 놓기          타임라인 40~55 · 소스 0~15 · x1.0
                                                  [D ======]        2. 앞 자르기 5초  타임라인 45~55 · 소스 5~15 · x1.0
     |.........|.........|.........|.........|.........|.........|
     0         10        20        30        40        50        60
```

1단계에서 보내는 값은 §3.4의 예시와 같은 모양이다(`timeline 40~55초`, `source 0~15초`).

### 8.8 화면 사이에서 시각을 넘기는 예

| 상황 | 넘기는 값 | 받는 쪽 계산 |
|---|---|---|
| 타임라인 화면에서 `T` = 28초에 다른 화면으로 | `job`, `t=28000000000` | 그대로 `T`로 쓴다 |
| 클립 B를 단독 뷰어로 열어 Asset 축 12초까지 본 뒤 돌아옴 | `clip=103`, Asset 축 12초 | `T = 25 + (12 − 0) ÷ 1.5 = 33초` |
| 클립 D를 단독 뷰어로 열어 Asset 축 8초에서 돌아옴 | `clip=104`, Asset 축 8초 | `T = 45 + (8 − 5) ÷ 1.0 = 48초` |
| 대시보드로 넘어감(작업 시작이 09:00:00) | 절대 시각 09:00:28 | 대시보드가 자기 기준으로 바꾼다 |

## 9. 화면 구성

기존 tacit-tag 편집 화면(프로젝트 → 레이어 → 구간)과 같은 틀에, 이 문서의 규칙이 보이도록 다섯 영역으로 나눈다.
그림 안은 영문·숫자만 썼다.

```
+----------------------------------------------------------------------+
| (1) job / pass / status                                   save state |
+----------------+-------------------------------+---------------------+
| (2) assets     | (3) preview (one pane)        | (5) properties      |
|                |                               |                     |
|  video         |      track: V2   clip: B      |  kind               |
|  sensor        |                               |  timeline 25 ~ 35   |
|  pose          |                               |  source    0 ~ 15   |
|  pdf ...       |  |<  <  play  >  >|  x1  T    |  speed x1.5 (auto)  |
|                |  source 0s |--[#####]----| 15s|                     |
+----------------+-------------------------------+---------------------+
| (4) timeline   0        10        20        30        40        50   |
|   pass         [ pass 1          ]          [ pass 2            ]    |
|   V1 depth     [A ===============================]                   |
| > V2 action         [E ===========]               [D ======]         |
|                                [B x1.5 =]                            |
|   pose         [P ===============================]                   |
|   sensor       ~~~~~~~~~~~~ (waveform) ~~~~~~~~~~~~~~~~~~~~~~        |
|   tag               [T1 ===================]                         |
+----------------------------------------------------------------------+
```

### 9.1 영역

**(1) 상단 바**
- 공사·작업 이름, 패스 선택, 타임라인 상태를 둔다.
- 패스를 고르면 `GetTimeline(pass_id)`가 주는 구간으로 타임라인을 확대한다.

**(2) 자료 목록**
- 그 작업에 첨부된 Asset을 종류별로 보여 준다(`ListJobAssets`).
- 타임라인에 놓인 것과 아직 안 놓인 것을 구분해 표시한다.
- 트랙으로 끌어다 놓으면 클립이 만들어진다(§3.4). 고르기만 하면 소스 보기로 전체를 본다(§9.2).

**(3) 미리보기와 재생 조작**
- 칸은 하나다. 고른 트랙에서 그 시각에 걸린 클립이 종류에 맞게 보이고(§6), 덮는 클립이 없으면 빈 화면에 그 사실을 적는다.
- 지금 어느 트랙·어느 클립을 보고 있는지 칸 위에 적는다. 트랙을 오가면 화면이 바뀌므로 없으면 헷갈린다.
- 조작부: 재생·정지, 한 프레임 앞뒤, 타임라인 배속, 현재 시각과 전체 길이.
- 시각은 타임라인 시각으로 표시한다. 파일 자체의 시각(`video.currentTime`)은 보여 주지 않는다.
- 조작부 아래에 소스 막대를 둔다(§9.2).

**(4) 타임라인**
- 맨 위에 눈금, 그 아래에 패스 구간을 띠로 깐다.
- 트랙 머리(왼쪽): 이름, 보이기 토글, 고른 트랙 표시(`>`). 트랙 머리를 누르면 고른 트랙이 바뀌고 미리보기가 따라 바뀐다(§6.1).
- 한 트랙 안에서 겹친 클립은 줄을 나눠 쌓는다. 트랙 높이가 줄 수만큼 늘어난다(§3.1).
- 클립 배속이 1이 아닌 클립에만 배속 표시(`x1.5`)를 붙인다.
- 센서는 트랙 안에 파형으로 그린다. 같은 가로축이라 별도 그래프 창보다 시각을 맞추기 쉽다.
- 재생 위치 선은 모든 트랙을 가로지르는 세로선 하나다.

**(5) 속성 패널**
- 고른 클립의 종류, 타임라인 구간, 소스 구간, 라벨, 설명을 보여 주고 숫자로 고칠 수 있게 한다.
- 소스 구간은 0부터 세는 시각으로 표시하고, Asset 길이를 넘는 값은 입력 단계에서 막는다(§3.5).
- 클립 배속은 읽기 전용이다. 두 길이에서 자동으로 정해지는 값이라 입력칸을 두지 않는다.
- 도구가 만든 클립이면 만든 도구, 실행 대상, 검수 여부를 함께 보여 준다.

### 9.2 소스 막대와 소스 보기 — 소스 구간을 정하는 방법

타임라인 미리보기는 클립이 쓰는 구간만 보여 준다. 소스의 어디를 쓸지 정하려면 그 밖의 부분도 볼 수 있어야 한다.

**소스 막대**는 고른 클립(또는 고른 Asset)의 소스 전체를 0부터 끝까지 그린 막대다. 길이는 `Asset.duration_ns`라 파일을 열지 않고도 그릴 수 있다. 쓰는 구간을 그 안에 표시한다.

```
source: V3   0s                                    15s
             |----[################]--------------|
                  ^ start 3s       ^ end 13s
```

| 조작 | 결과 |
|---|---|
| 양쪽 손잡이를 끈다 | 소스 시작·끝을 바꾼다. 끄는 동안 미리보기가 그 위치의 장면을 보인다 |
| 표시된 구간의 가운데를 끈다 | 소스 밀기 — 쓰는 구간을 통째로 민다. 클립의 타임라인 자리와 길이는 그대로다 |
| 막대의 아무 곳이나 누른다 | 그 위치의 장면을 본다. 쓰는 구간 밖도 볼 수 있다 |
| 소스 재생을 누른다 | 소스를 처음부터 끝까지 재생한다 |

- 막대의 양 끝이 곧 한계(0과 Asset 길이)다. 손잡이가 그 밖으로 나가지 못하게 하면 §3.5의 한계가 지켜진다.
- 손잡이로 소스 구간을 바꿨을 때 타임라인 구간을 어떻게 할지는 §3.5와 같다. 기본은 자르기(타임라인도 함께 바뀜)다.
- 막대와 소스 보기의 시각은 첫 프레임을 0으로 센 값이다. 파일이 7초부터 시작해도 사용자는 0부터 보고, 화면이 재생할 때만 첫 시각을 더한다(§5.1).
- 센서는 막대에 파형을, 포즈는 검출 구간을 깔아 준다. 길이가 없는 소스(이미지·PDF)는 막대가 없다.

**미리보기 칸은 하나로 두고 보기만 둘로 나눈다.**

| 보기 | 무엇을 재생하나 | 움직이는 시각 |
|---|---|---|
| 타임라인 보기(기본) | 고른 트랙에서 `T`에 걸린 클립 | 타임라인 시각 `T` |
| 소스 보기 | 고른 클립 또는 고른 Asset의 소스 전체 | 소스 위치(Asset 축) |

- 소스 막대를 만지면 소스 보기로 바뀌고, 타임라인을 누르거나 타임라인 재생을 누르면 타임라인 보기로 돌아온다.
- 소스 보기에 있는 동안 `T`는 바뀌지 않는다. 돌아오면 원래 자리다.
- 소스 위치가 쓰는 구간 안에 있으면 타임라인에 대응하는 자리(§6.2의 식)를 흐린 선으로 보여 줄 수 있다.
- 지금 어느 보기인지 칸에 표시한다.

**아직 놓지 않은 Asset**

- 자료 목록에서 Asset을 고르면 소스 보기로 전체를 본다.
- 소스 막대에서 시작·끝을 먼저 정한 뒤 타임라인으로 끌어다 놓으면 그 구간만 쓰는 클립이 만들어진다.
- 구간을 정하지 않고 놓으면 전체가 놓인다(§3.4).

### 9.3 조작과 규칙의 대응

| 조작 | 결과 | 규칙 |
|---|---|---|
| 클립 가운데를 끈다 | 옮기기 | §3.5 |
| 클립 끝을 끈다 | 자르기(소스 끝에 닿으면 멈춤) | §3.5 |
| 보조 키 + 클립 끝을 끈다 | 길이만 바꾸기(클립 배속이 바뀜) | §3.2, §3.5 |
| 소스 막대에서 구간 가운데를 끈다 | 소스 밀기 | §9.2 |
| 클립을 누른다 | 그 클립을 고른다. 겹친 구간에서 미리보기에 먼저 보인다 | §3.1 |
| 트랙 머리를 누른다 | 고른 트랙을 바꾼다. `T`는 그대로 | §6.1 |
| 눈금을 누르거나 끈다 | 그 시각으로 이동 | §6 |
| 자료를 트랙에 끌어다 놓는다 | 클립 만들기 | §3.4 |

### 9.4 만드는 순서

- 먼저: 타임라인 그리기(줄 나누기 포함), 미리보기 하나, 트랙 전환, 옮기기·자르기, 소스 막대(보기와 손잡이).
- 나중: 길이만 바꾸기, 소스 밀기, 나누기, 속성 패널의 숫자 입력, 패스 간격 접기, 화면 나눠 보기.

## 10. 저장·실패 처리·되돌리기·참조 — 서버 동작 점검

mediatag 서버 코드(`compose_repository_impl.go`·`compose_handler.go`·`db_errors.go`)와 `tacit-db/init.sql`을 읽고 확인한 것이다(2026-10-13).

### 10.1 저장 시점

- **끄는 동안에는 저장하지 않는다. 놓았을 때 `UpdateClip`을 한 번 보낸다.**
- 화면은 먼저 바꿔 보이고(기다리지 않음), 응답이 오면 응답의 `clip`으로 바꿔 끼운다. 실패하면 원래 값으로 되돌린다(§10.2).
- `update_mask`에는 바꾼 칸만 넣는다. 비우면 INVALID_ARGUMENT다.

| 동작 | `update_mask` | 주의 |
|---|---|---|
| 옮기기 | `timeline_start_ns`, `timeline_end_ns` | |
| 다른 트랙으로 옮기기 | `track_id`(+ 위의 둘) | 같은 작업의 트랙만. 다른 작업이면 INVALID_ARGUMENT |
| 자르기 | `timeline_start_ns`, `timeline_end_ns`, `source` | |
| 길이만 바꾸기 | `timeline_start_ns`, `timeline_end_ns` | |
| 소스 밀기 | `source` | |
| 소스 붙이기·바꾸기 | `source` | 그 Asset이 작업에 첨부돼 있지 않으면 서버가 자동으로 첨부한다 |
| 라벨·설명 | `label_value_id` / `description` | |
| 검수 표시 | `provenance.reviewed` | 도구가 만든 클립만. 사람이 놓은 클립이면 INVALID_ARGUMENT |

- **`source`는 통째로 바뀐다.** `asset_id`·`start_ns`·`end_ns`·`locator` 넷이 한 묶음이라, 구간만 고칠 때도 넷을 모두 채워 보낸다. 빼먹은 칸은 지워진다(예: PDF 쪽 위치 `locator`).
- 서버는 고친 뒤의 전체 모양을 검사하고, 어기면 그 요청 전체를 취소한다. 일부만 저장되는 일은 없다.
- 여러 클립을 한꺼번에 옮겨도 요청은 클립마다 따로다. 중간에 하나가 실패하면 앞의 것은 이미 저장돼 있으므로, 실패한 것만 되돌리고 알린다.

### 10.2 실패 처리

| 응답 | 뜻 | 화면이 할 일 |
|---|---|---|
| INVALID_ARGUMENT | 값이 틀림(구간이 뒤집힘, 소스 구간이 Asset 길이를 넘음, 없는 트랙·라벨, 종류에 안 맞는 `locator` 등) | 원래 값으로 되돌린다. 화면 쪽 계산 잘못이므로 기록을 남긴다 |
| FAILED_PRECONDITION | 쓰이는 중이라 지울 수 없음(클립이 쓰는 첨부, 첨부된 Asset 등) | 되돌리고 이유를 알린다 |
| NOT_FOUND | 그 클립이 이미 없음(다른 사람이 지움) | 화면에서 그 클립을 빼고 타임라인을 다시 조회한다 |
| 그 밖(연결 끊김, INTERNAL) | 저장됐는지 알 수 없음 | 되돌리지 말고 `GetClip`으로 실제 값을 다시 읽어 맞춘다 |

- **충돌 검사가 없다.** 두 사람이 같은 클립을 고치면 나중에 저장한 쪽이 덮어쓴다. 오류도 나지 않는다.
  다른 사람의 변경은 다시 조회해야 보인다. 타임라인 상태만 `ChangeTimelineStatus(from_status)`로 충돌을 잡는다.
- 같은 트랙에서 겹치게 놓거나 옮겨도 오류가 나지 않는다(§3.1).

### 10.3 되돌리기

되돌리기는 화면이 한다. 서버에 되돌리기 기능은 없다.

| 한 일 | 되돌리는 방법 | 완전히 돌아오나 |
|---|---|---|
| 옮기기·자르기·길이만 바꾸기·소스 변경·라벨·설명 | 바꾸기 전 값을 `UpdateClip`으로 다시 보낸다 | 예 |
| 클립 만들기 | `DeleteClip` | 거의. 자동으로 붙은 첨부(`job_asset`)는 남는다 |
| 클립 지우기 | `CreateClip`으로 다시 만든다 | **아니오**(아래) |
| 트랙 지우기 | 트랙과 그 클립을 다시 만든다 | 아니오(클립 지우기와 같은 문제가 클립 수만큼) |
| 타임라인 초기화 | – | 되돌릴 수 없다 |

**지운 클립을 다시 만들어도 돌아오지 않는 것**

- **번호가 바뀐다.** 새 `clip_id`가 붙는다. 화면이 들고 있던 선택·되돌리기 기록의 번호를 새 번호로 바꿔야 한다.
- **도구가 만든 클립이라는 기록이 사라진다.** `CreateClip`은 `provenance`(만든 도구·실행·신뢰도·검수 여부)를 저장하지 않는다. 다시 만든 클립은 사람이 놓은 클립이 된다.
- **그 클립을 잇던 관계 클립이 함께 지워져 있다.** 따로 다시 만들어야 하고, 그것도 새 번호다.
- **그 클립을 대상으로 돈 실행의 대상이 끊긴다.** 실행 기록은 남지만 대상 칸이 비고, 그 실행이 만든 포즈·자막 클립의 `provenance.target_kind`가 UNSPECIFIED가 된다. 다시 이을 방법이 없다.

그래서:

- 사람이 놓았고 관계가 걸리지 않은 클립은 지우기를 되돌릴 수 있다고 봐도 된다.
- 도구가 만든 클립, 관계가 걸린 클립, 다른 클립의 실행 대상인 클립, 트랙, 타임라인 초기화는 **지우기 전에 확인을 받는다.**
- 안(미정): 클립 지우기를 실제 삭제가 아니라 가리기(`delete_time`)로 바꾸면 되돌리기가 "되살리기" 한 번으로 끝나고 위 네 가지가 모두 보존된다.
  `삭제 정책.md`는 클립을 완전 삭제로 정했는데, "실수 복구는 화면의 되돌리기로"라는 그 근거가 도구가 만든 클립에는 성립하지 않는다.

### 10.4 참조 — 무엇이 무엇을 가리키고, 지우면 어떻게 되나

| 가리키는 쪽 → 대상 | 대상을 지우면 |
|---|---|
| 클립 → 트랙 | 트랙을 지우면 그 클립도 지워진다 |
| 트랙 → 타임라인 | 타임라인을 지우면(초기화) 트랙·클립이 모두 지워진다 |
| 관계 클립 → 잇는 두 클립 | 둘 중 하나를 지우면 관계 클립도 지워진다 |
| 클립의 `provenance` → 클립 | 클립과 함께 지워진다 |
| 도구 실행의 대상 → 클립 | 실행 기록은 남고 대상 칸만 비워진다 |
| 클립 → 작업 첨부(`job_asset`) | 클립이 쓰는 첨부는 뗄 수 없다(FAILED_PRECONDITION). 클립을 먼저 지운다 |
| 작업 첨부 → Asset | 첨부된 Asset은 지울 수 없다(FAILED_PRECONDITION) |

- **첨부는 자동으로 생기지만 자동으로 사라지지 않는다.** 클립을 만들거나 소스를 바꾸면 그 Asset이 작업에 첨부되고, 클립을 지워도 첨부는 남는다. 자료 목록(§9.1)에 "놓이지 않은 첨부"로 보이게 된다.
- 클립은 작업에 첨부된 Asset만 가리킬 수 있다. 이 검사는 DB가 한다.
- 관계 클립의 두 끝(`from_clip_id`·`to_clip_id`)은 만든 뒤에 바꿀 수 없다(`update_mask`에 없다). 바꾸려면 지우고 다시 만든다.
- 클립이 가리키는 라벨 값을 지웠을 때의 동작은 확인하지 않았다.
