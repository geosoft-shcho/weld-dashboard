# 파형 없음 배너 공간 축소

## 목표
차트 위 `명장/작업자/로봇 파형 없음` 등 배너가 InfoBar마다 큰 세로 영역을 쓰지 않도록, **한 줄 압축 텍스트**로 바꾼다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md`
3. `lib/src/presentation/features/pass_profile/pass_profile_screen.dart` (`_PassChartPane` banners → InfoBar)
4. `lib/src/domain/use_cases/query_pass_profile_use_case.dart` (79–87 banners 생성)

## 현재 상태
- UseCase가 빈 시리즈마다 배너 문자열을 추가.
- 화면이 `for (banner in banners) InfoBar(...)`로 **배너당 InfoBar 1개**를 쌓아 세로를 많이 씀.

## 바꿀 것
1. `pass_profile_screen.dart`의 `_PassChartPane`만 수정.
2. banners가 비어 있지 않으면 InfoBar 루프 대신 **한 블록**으로 표시:
   - `Text(banners.join(' · '), style: fontSize 12, color: STATUS_OFF)` 수준의 한 줄(필요 시 wrap)
   - 패딩은 상하 4~6 정도로 얇게
3. 시리즈 로딩 에러 InfoBar는 그대로 유지.
4. UseCase의 배너 문구·생성 로직은 변경하지 않음(표시만 압축).

## 유지할 것
- `PassProfileBoard.banners` 계약
- 차트·툴바·비교 지표
- quality_issue 화면

## 이번 작업에서 만들지 않음
- 배너 dismiss / 토글
- UseCase에서 배너 제거·문구 변경
- 새 공용 InfoBar 컴포넌트

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
