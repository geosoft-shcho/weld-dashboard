# 첨부 해제 확인 다이얼로그

## 목표
첨부 해제 버튼을 누르면 확인 다이얼로그를 띄우고, 확인을 누른 뒤에만 첨부를 해제한다. 취소면 아무 것도 하지 않는다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md` (가이드라인 저장소는 워킹 트리 밖에서 읽기만)
3. `lib/src/presentation/features/job_lookup/widgets/job_attachment_tab.dart` (`_didTapDetach`)
4. 같은 feature 확인 패턴: `job_pass_tab.dart` / `job_info_tab.dart`

## 현재 상태
- `_didTapDetach(assetId)`: `_isWorking`을 켠 뒤 즉시 `_viewModel.detachAsset`을 호출한다.
- 에셋 붙이기·패스 삭제·작업 삭제는 이미 `showDialog<bool>` + `confirmed != true`면 return 한다.

## 바꿀 것
1. `_didTapDetach`에서 먼저 `ContentDialog`를 띄운다.
   - 제목: `첨부를 해제할까요?`
   - 본문: `이 작업에서만 떼어냅니다. 에셋 자체는 남습니다.`
   - 액션: 취소 / 확인(또는 해제)
2. 확인(`true`)일 때만 기존과 같이 `detachAsset`을 실행한다.
3. 취소·닫기면 return한다. 요청과 `_isWorking`을 시작하지 않는다.

## 유지할 것
- `detachAsset` ViewModel/UseCase API
- 실패 시 기존 오류 다이얼로그
- 테이블·올리기·붙이기 UI

## 이번 작업에서 만들지 않음
- 새 위젯 파일·추상 계층
- 해제 문구/API 동작 변경
- 다른 탭 확인 다이얼로그 리팩터

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
