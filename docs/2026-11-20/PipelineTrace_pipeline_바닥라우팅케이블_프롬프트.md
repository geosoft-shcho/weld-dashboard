# PipelineTrace pipeline 바닥 라우팅 케이블 입체 구조

## 목표

`docs/2026-11-20/PipelineTrace_pipeline_입체연결구조_프롬프트.md`를 기반으로, 첨부 레퍼런스처럼 **바닥을 따라 직각(필렛) 라우팅되는 가는 발광 케이블 번들**로 Stage를 잇는 입체 구조를 `pipeline.glb`에 구현한다. 오브젝트(모니터·네트워크·체인·DB)는 바닥 위에 떠 있고, 케이블은 바닥으로 내려와 ㄱ자 경로로 흐른 뒤 각 오브젝트로 상승한다. 연결선은 Node와 완전 분리한다.

## 레퍼런스 구성

| 위치 | 오브젝트 | Stage |
|------|----------|-------|
| 왼쪽 앞(낮음) | 모니터(채팅 버블) | collect |
| 모니터 옆 | 소형 수신 | receive |
| 중앙(높음) | 초록 네트워크 그래프 | embed |
| 중앙 바닥 | 소형 도구 | tool |
| 중앙 오른쪽 | 보라 체인 링 | postprocess |
| 오른쪽 뒤(높음) | 하늘색 DB 디스크 | register |
| DB 옆 | 소형 완료 | done |

- 케이블: 바닥(y≈0.05) 평행 2선 번들, 직각 모서리는 둥근 필렛
- 각 Stage는 바닥 접합점으로 내려오는 라이저 + 중앙 플로어 버스로 연결
- 색: 라이저=Stage색, 버스 세그먼트=흐름 Stage색(초록·보라·시안)

## 먼저 읽을 것

1. 첨부 레퍼런스 이미지
2. `docs/2026-11-20/PipelineTrace_pipeline_입체연결구조_프롬프트.md`
3. `scripts/generate_pipeline_full_glb.mjs`
4. `pipeline_o3d_full_bridge.dart`

## 바꿀 것

1. `generate_pipeline_full_glb.mjs` + `pipeline.glb` — 바닥 라우팅 케이블(라이저+버스+로컬), 떠 있는 오브젝트, Stage/Node 이름 유지
2. 카메라 프리셋을 레퍼런스 구도(좌하 모니터→우상 DB 대각)로
3. pipe 이름 맵이 바뀌면 `pipeline_o3d_full_bridge.dart` 소량 수정

## 유지할 것

- `stage__*` / `node__*` / `mat__*` / `pipe__*` 분리 계약, Trace 상태 연동
- o3d 단일 뷰, 2D 모드

## 이번 작업에서 만들지 않음

- Blender 수동 파일, Hotspot UI, 새 Provider

## 복잡한 코드 제거 및 금지

- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
