# 화면 코멘트 2차

## 목표
품질 이슈와 패스별 파라미터에서 웹캠 녹화를 올리면 `CreateComment`가 한 번 나간다. 비디오 멀티모달·품질 이슈·패스별 파라미터가 그 작업의 코멘트를 같은 목록으로 보여 준다. 줄에는 글(없으면 말만)과 자막 상태만 있다.

## 현재 상태
- 멀티모달만 `capturesScreenComment: true`로 업로드·배치 성공 후 `CreateComment`를 부른다. context는 탐색·재생·패널·선택 클립이 바뀔 때 줄이 쌓인다.
- 품질·패스는 `CameraRecordingScope`가 녹화 카드만 연다. `onRecordingPlaced`는 빈 함수이고, 코멘트를 만들지 않는다. 업로드가 끝나면 벡터 저장 안내를 띄운다.
- 목록은 녹화 카드 안 `_ScreenCommentList`다. 카메라 VM이 `prepare`될 때 `ListComments{jobId}`로 최대 8건, 글 또는 "말만"과 자막 상태를 보여 준다.
- `CreateComment` 요청에 `pass_id`를 넣지 않는다. 목록 응답의 자막은 `subtitle_asset_id`뿐이고 문장은 없다.
- 품질·패스 화면에는 차트 구간 선택과 검사 행의 표 이름·행 id가 없다.

## 바꿀 것
1. 품질·패스 `CameraRecordingScope`도 `capturesScreenComment: true`로 연다. 녹화 카드의 글 입력은 그대로 두고, 음성 업로드와 배치 콜백이 성공하면 `CreateComment` 1회. 배치 콜백은 지금처럼 빈 함수라 타임라인에는 놓지 않는다.
2. 그 코멘트의 `pass_id`는 녹화를 연 순간의 선택 패스다. 패스가 없으면 비운다(작업 전체). context는 한 줄만 보낸다. `t_ms: 0`, `screen`은 `quality` 또는 `pass`, `job_id`, 패스가 있으면 `pass_id`. 미디어·범례·비교·채널·구간·검사 행은 적지 않는다.
3. 목록 위젯을 녹화 카드 밖으로 빼서 품질 이슈, 패스별 파라미터, 비디오 멀티모달 본문에 둔다. 카드를 열지 않아도 `ListComments{jobId}`로 그 작업 코멘트가 보인다. 패스나 탭으로 거르지 않는다. 업로드로 코멘트가 생긴 뒤 세 화면 목록이 다시 불러온다.
4. 목록 줄은 지금과 같다. 글이 없으면 "말만", 옆에 자막 상태(처리 중·완료·말소리 없음·맡기지 못함·실패·취소). 자막 파일은 받지 않는다.

## 유지할 것
- 멀티모달의 클립 배치, context 줄 쌓기, `refreshAfterRecordingUpload`, 벡터 안내 억제
- 품질·패스의 벡터 저장 안내와 타임라인에 놓지 않는 업로드
- 좋아요·싫어요·근거 영상 `tag` 클립
- 글 입력은 `LookupSearchField`

## 이번 작업에서 만들지 않음
- 미디어 탭·쪽·범례·비교 패스·채널·차트 구간·검사 행 context (3차)
- 자막 문장 표시, 재생으로 화면 되살리기 (3차)
- 녹화 버튼을 공통 헤더로 옮기기
- `UpdateComment`·`DeleteComment`, 화면에서 `StartRun`
- proto 재생성

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
