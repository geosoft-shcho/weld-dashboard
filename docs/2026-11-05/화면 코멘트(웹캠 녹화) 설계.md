# 화면 코멘트(웹캠 녹화) 설계

어느 화면에서든 사람이 화면을 보며 웹캠 녹화로 코멘트를 남기고, 그때 보던 화면과 함께 저장하는 구조를 정한다.
타임라인 시각과는 관계없다.

**범위(2026-11-04)**: 웹캠 녹화 기준이다. 글(`body`)은 녹화에 덧붙이는 설명으로만 받는다. 비디오 멀티모달의
좋아요 · 싫어요 · 근거 영상 코멘트는 지금처럼 `tag` 클립으로 두고 이 표로 옮기지 않는다(§6).

## 1. 배경

- 운영 화면(`tks.faivv.ai/#/quality?jobId=…&passId=…`, 2026-11-03 확인)은 작업 정보 · 패스 탭 · 미디어 탭(성적서 PDF, 액션캠 · 깊이 영상) ·
  전류 · 전압 · 속도 · 회전수 차트 · 검사 표로 되어 있고, 오른쪽 위에 녹화 버튼이 있다.
- 녹화는 지금 작업 · 패스에 첨부만 된다(`POST /assets {jobId, passId}`, `웹캠 녹화 업로드와 STT 안내.md`). 무엇을 보며 말했는지
  (어느 화면 · 어느 미디어 탭 · 성적서 몇 쪽 · 어느 검사 행)는 남지 않는다.
- 녹화 시각은 대개 작업 구간 밖이라 타임라인에 놓이지 않는다. 성적서 검사 결과에도 시각이 없다(`doc.welding_inspection`은 항목별
  판정, UT · MT 표는 확인번호와 판정뿐). 그래서 시각을 전제로 한 Clip(`tag` · `relation`)으로는 엮을 수 없다.
- 녹화하는 순간 화면은 자기가 무엇을 보여 주는지 다 안다. 그것을 그대로 저장하면 된다.
- 이 기록은 학습 자료가 된다. `docs/자료/암묵지_시나리오_AI학습관점_V0.4_20261014.xlsx`의 9번(명장 판단근거 멀티모달, Triplet: Context +
  Intent/Reasoning(발화 STT) + Action)에서 코멘트 음성의 STT가 Reasoning, 그때 보던 자료의 구간이 Context다. 그래서 보던 화면은
  학습 쪽이 바로 풀 수 있는 모양으로 적는다(§2 `context`).

## 2. 구조

```
tacit.comment ── 코멘트 1건 = 웹캠 녹화 1회
  │  job_id · pass_id     어디에 단 코멘트인가(시작한 화면의 작업 · 패스)
  │  body                 글
  │  audio_asset_id ──►   tacit.asset  코멘트를 만든 웹캠 녹화(음성, 필수)
  │  video_asset_id ──►   tacit.asset  〃 (영상, 선택)
  │  context              보던 페이지 상태 [{t_ms, screen, job_id, pass_id, media, range, selected, view}]
```

```sql
-- 화면 코멘트 = 웹캠 녹화 1회. 음성이 코멘트 자체라 필수, 영상 · 글은 선택. 타임라인 시각과 관계없다.
CREATE TABLE tacit.comment (
  comment_id     bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY, -- 시스템이 매기는 번호
  job_id         bigint REFERENCES tacit.job ON DELETE CASCADE, -- 어느 작업의 코멘트. 작업 없는 화면(공사 · 작업자 관리 등)이면 비움
  pass_id        bigint,                         -- 어느 패스. 비면 작업 전체
  body           text,                           -- 녹화에 덧붙인 글(제목 · 요약). 없으면 비움
  audio_asset_id bigint NOT NULL REFERENCES tacit.asset, -- 코멘트를 만든 웹캠 녹화(음성). 음성이 없으면 코멘트가 아니다
  video_asset_id bigint REFERENCES tacit.asset,  -- 〃 (영상). 음성만 녹화했으면 비움
  context        jsonb NOT NULL,                 -- 보던 페이지 상태의 줄들(§2 context). 서버는 모양만 본다
  started_at     timestamptz NOT NULL,           -- 녹화 시작(= 파일들의 timeOrigin)
  stt_run_id     bigint REFERENCES tacit.tool_run ON DELETE SET NULL, -- 만들 때 건 STT 실행. 못 맡겼으면 비움
  created_at     timestamptz NOT NULL DEFAULT now(),
  updated_at     timestamptz NOT NULL DEFAULT now(),
  -- 패스를 지우면 작업 전체 코멘트가 된다(pass_id만 NULL)
  FOREIGN KEY (job_id, pass_id) REFERENCES tacit.pass (job_id, pass_id) ON DELETE SET NULL (pass_id),
  -- 작업이 있으면 녹화는 그 작업의 첨부여야 한다(작업이 비면 검사하지 않음). 녹화를 떼려면 코멘트를 먼저 지운다.
  FOREIGN KEY (job_id, audio_asset_id) REFERENCES tacit.job_asset (job_id, asset_id),
  FOREIGN KEY (job_id, video_asset_id) REFERENCES tacit.job_asset (job_id, asset_id)
);
-- 정본은 sub-services/tacit-db/init.sql(이관 37). 위는 요점만.
-- "이 에셋(성적서 · 영상)을 보며 남긴 코멘트": context @> '[{"media":{"asset_id":20801}}]'
CREATE INDEX ON tacit.comment USING gin (context jsonb_path_ops);
CREATE INDEX ON tacit.comment (job_id, pass_id);
```

### 칸마다

| 칸 | 역할 | 비어 있으면 |
|---|---|---|
| `job_id` · `pass_id` | 화면이 "이 작업 · 패스의 코멘트"를 바로 뽑는다(파일 첨부를 거꾸로 찾지 않는다) | 작업이 없는 화면에서 단 코멘트 |
| `body` | 녹화에 덧붙인 글 | 말만 한 코멘트 |
| `audio_asset_id` | 코멘트 자체(말). 필수 | — |
| `video_asset_id` | 웹캠 영상 | 음성만 녹화 |
| `context` | 코멘트를 남길 때 보던 페이지 상태. 다시 열기와 학습에 쓴다. 필수(첫 줄은 늘 있다) | — |
| `started_at` | 녹화의 실제 시각. 필수 | — |

### `context`

녹화 중 **페이지 상태가 바뀔 때마다 한 줄**씩 쌓인다. 첫 줄은 녹화 시작(`t_ms: 0`)이다.

**보이는 것 전부가 아니라 페이지 상태를 적는다.** 한 페이지에는 정보가 많이 뜨지만(품질 이슈만 해도 작업 정보 · 패스 탭 · 미디어 탭 ·
차트 4개 · 검사 표), 대부분은 작업 · 패스가 정해지면 DB에서 그대로 다시 나온다. 순간마다 다른 것은 사용자가 고른 것뿐이라 그것만 적는다.

| 품질 이슈 화면에 뜨는 것 | 무엇으로 정해지나 | 적는 칸 |
|---|---|---|
| 작업 정보 · 검사 표 · 미디어 목록 | 작업 | `job_id` |
| 차트 4개 | 패스(패스 구간의 센서) | `pass_id` |
| 연 미디어 탭과 그 위치(PDF 3쪽, 영상 12:34) | 사용자가 고름 | `media` |
| 차트에서 고른 구간 | 사용자가 고름 | `range` |
| 고른 검사 행 | 사용자가 고름 | `selected` |
| 비교 작업 · 범례 · 파형 기준 | 사용자가 고름 | `view` |

#### 칸(모든 페이지 같음)

| 칸 | 뜻 | 모양 |
|---|---|---|
| `t_ms` | 녹화 기준 시각(0 = 녹화 시작). 필수 | 정수 |
| `screen` | 어느 페이지. 필수 | `quality` · `pass` · `multimodal` (페이지가 늘면 더한다) |
| `job_id` · `pass_id` | 작업 · 패스 | 숫자. 없으면 뺀다 |
| `media` | 연 파일과 그 안의 위치 | `{asset_id, locator}`. `locator`는 Clip `source_locator`와 같은 모양(`엔티티.md` §5.1a) — PDF `{page}` 또는 `{page,x,y,width,height}`, 영상 · 센서 `{start_ns,end_ns}`(파일 자체 시간축) |
| `range` | 작업 시간축(타임라인)의 구간 | `{start_ns, end_ns}`. 재생 바처럼 한 점이면 시작 = 끝 |
| `selected` | 고른 행 · 클립 | 배열. 원소는 `{clip_id}` 또는 `{inspection:{table, id}}`(`doc.*` 표 이름 + 행 `id`. "취부" 같은 화면 글자는 바뀔 수 있어 쓰지 않는다) |
| `view` | 보여 준 방식. 다시 열 때만 쓰는 보조 | 아래 키 목록에서만 고른다 |

`view` 키 목록 — 같은 뜻은 페이지가 달라도 같은 키를 쓴다. 키를 더할 때는 이 표에 먼저 적는다.

| 키 | 뜻 | 쓰는 페이지 |
|---|---|---|
| `compare_pass_id` | 비교 작업(패스) | 품질 이슈 · 패스별 파라미터 |
| `series` | 켠 범례(`master` · `worker` · `robot`) | 품질 이슈 · 패스별 파라미터 |
| `basis` | 파형 기준(`raw` · 표준화) | 품질 이슈 · 패스별 파라미터 |
| `channels` | 보이는 차트 채널(`current` · `voltage` · `speed` · `rpm`) | 품질 이슈 · 패스별 파라미터 |
| `tracks` | 켜 둔 트랙 id 목록 — 플레이어 화면이 이것으로 정해진다 | 비디오 멀티모달 |
| `playing` · `speed` | 재생 중인지, 재생 속도 | 비디오 멀티모달 |
| `panel` | 오른쪽 패널 탭(`assets` · `properties` · `labels`) | 비디오 멀티모달 |

- 서버는 `t_ms` · `screen`이 있는지, `media.locator`가 Clip과 같은 규칙에 맞는지만 본다. id가 실제로 있는지와 `view`는 검사하지 않는다.
- 학습은 `job_id` · `pass_id` · `media` · `range` · `selected`만 본다. `range`가 있으면 그 시각의 다른 센서 · 영상까지 꺼낼 수 있다.
  `media`의 위치는 파일 시간축이라, 에셋에 `recorded_at`이 있으면 작업 시간축으로 바꿀 수 있다.
- **한계**: 다시 꺼낼 때는 지금 DB 내용이 나온다. 뒤에 작업에 파일이 더 붙거나 성적서를 다시 추출하면 그때 보였던 것과 조금 다를 수 있다.
  사용자가 고른 것(`media` · `selected`)은 id라 바뀌지 않는다.

```json
{ "t_ms": 5000, "screen": "multimodal", "job_id": 388, "pass_id": 818,
  "range":    { "start_ns": 754200000000, "end_ns": 754200000000 },
  "selected": [ { "clip_id": 18452 } ],
  "view":     { "tracks": [17598, 17538, 18507], "playing": false, "speed": 1 } }
```

| 칸 | 품질 이슈 | 패스별 파라미터 | 비디오 멀티모달 |
|---|---|---|---|
| `media` | PDF 쪽 · 영상 위치 | — | 근거 영상 · 에셋 미리보기(플레이어가 파일 하나를 틀 때만) |
| `range` | 차트에서 구간을 골랐으면 | 차트 구간 | 재생 바 |
| `selected` | 검사 행 | — | 클립 |
| `view` | 범례 · 비교 작업 · 파형 기준 | 채널 · 비교 작업 · 파형 기준 | 켜 둔 트랙 · 재생 · 패널 |

- 비디오 멀티모달은 재생 중에 줄을 쌓지 않는다. 재생 · 정지 · 탐색 때만 남기고, 재생 중 위치는 `직전 줄의 range + (t_ms 차이 × speed)`로 셈한다.
- 비디오 멀티모달의 **질문(영상 질의)**은 담지 않는다. 열어 본 근거 영상은 `media`로 남지만 질문 · 답은 남길 곳이 없다(질의 기록 저장 여부 미확인, §7).

## 3. 흐름

```
① 녹화 시작     시작 시각과 첫 줄(t_ms 0의 페이지 상태)을 적어 둔다            (서버 요청 없음)
② 녹화 중       페이지 상태가 바뀌면 context에 줄을 쌓는다                    (서버 요청 없음)
③ 녹화 끝       POST /assets {jobId, passId, timeOrigin} × 음성 · 영상        (지금과 같음)
④              CreateComment{jobId, passId, startedAt, audioAssetId, videoAssetId, body, context} → comment_id, runId
⑤ (서버)        코멘트를 저장하고 음성에 STT(1번 faster-whisper)를 건다 — StartRun{target:{asset_id: audioAssetId}}와 같음
⑥              화면은 기다리지 않는다. 목록에 "자막 처리 중"으로 두고, GetRun(runId)이 끝나면 자막을 보인다
```

- 코멘트는 음성 업로드가 끝난 뒤 한 번에 만든다. 음성이 없으면 코멘트가 아니므로, 업로드가 실패하면 남길 코멘트도 없다.
  업로드가 실패하면 화면이 녹화와 `context`를 들고 있다가 다시 올린다.
- 글만 있는 코멘트는 받지 않는다(`audio_asset_id` 필수).
- 첨부는 녹화를 **시작한** 화면의 작업 · 패스로 한다. 녹화 중 다른 작업으로 넘어가도 기록은 `context`에 남는다.
- 업로드 뒤 후처리(길이 · 파형 · 자동 배치)는 지금과 같다. 녹화 시각이 작업 구간 밖이면 타임라인에 놓이지 않고 경고만 뜬다 — 코멘트는
  타임라인과 관계없으니 그대로 둔다.
- **STT는 서버가 코멘트를 만든 직후 건다.** 화면이 따로 걸지 않는다. 코멘트가 먼저 저장된 뒤라 아래 성공 판단(코멘트 음성인가)이 늘 맞는다.
  - 도구는 실제 STT인 **1번 "STT faster-whisper"**로 고정한다(13번 "STT 빠른 처리"는 목업이라 쓰지 않는다). 1번은 `tool_code`가 비어 있어
    서버 설정에 도구 번호로 둔다(예: `MEDIATAG_COMMENT_STT_TOOL_ID=1`). 2 · 3 · 4번(GPU · edge-cpu · ORIN)은 꺼져 있다(2026-11-04 DB 확인).
  - STT를 맡기지 못해도(도구 꺼짐 등) 코멘트는 만든다. 응답의 `runId`가 비고, 나중에 화면이나 사람이 `StartRun`으로 다시 건다.
  - 말소리가 없으면 지금처럼 실패(`no_speech`)다. 코멘트는 남기고 목록에 "말소리 없음"으로 보인다.
  - 코멘트 녹화는 대개 타임라인에 놓이지 않아 자막 Clip을 놓을 자리가 없다. 서버는 **입력 음성이 코멘트의 `audio_asset_id`면 Clip이
    0개여도(`no_place`) 성공**으로 둔다(`internal/ingest/external.go`의 STT 결과 처리, `SELECT EXISTS (… tacit.comment WHERE audio_asset_id = $1)`).
    `no_speech` · `place_failed`, 코멘트가 아닌 음성은 지금처럼 실패다. 비디오 멀티모달의 녹화는 타임라인에 놓여 있어 자막 Clip까지 생긴다.
  - 자막은 음성의 자식 에셋(`parent_asset_id`, kind `subtitle`)이다. 코멘트에 자막 칸은 두지 않는다.
- **STT는 다른 일을 막지 않는다.** STT는 외부 도구라 STT 서버마다 대기열이 따로다(`laneKey`) — 업로드 후처리(`postprocess`) · 무거운 작업(`work`)과
  섞이지 않아 다음 녹화 · 화면 이동에 영향이 없다. 다만 디스패처가 STT 서버마다 한 번에 한 건만 보내므로(`ClaimQueued`) STT끼리는 차례를
  기다린다. 비디오 멀티모달에서 사람이 건 긴 STT가 돌면 코멘트 자막이 뒤로 밀리고, 반대도 그렇다. 지금 사용량이면 그대로 두고, 밀림이 문제가
  되면 코멘트 STT를 앞에 세우는 우선순위를 더한다.
- 서버는 `audioAssetId` · `videoAssetId`가 각각 `audio` · `video` 에셋이고 같은 작업에 첨부됐는지, `pass_id`가 그 작업의 패스인지 본다.

### API(mediatag, 제안)

| RPC | 하는 일 |
|---|---|
| `CreateComment` | 업로드한 녹화로 코멘트를 만들고 음성에 STT를 건다. 응답에 `comment_id` · `run_id`(STT를 못 맡겼으면 비움) |

| `ListComments{asset_id}` | 그 에셋을 `media`로 열어 두고 남긴 코멘트(성적서 · 영상 탭마다 코멘트 보이기) |
| `DeleteComment` | 코멘트를 지운다. 녹화 에셋은 남는다(첨부된 파일이라) |

## 4. 화면에서 쓰는 법

**탭마다 같다.** 코멘트에는 어느 탭에서 만들었는지를 따로 적지 않는다. 탭마다 다른 것은 `context` 줄의 어느 칸이 채워지느냐뿐이다(§2).

- **목록** — 품질 이슈 · 패스별 파라미터 · 비디오 멀티모달이 같은 `ListComments{jobId, passId}`로 띄운다. 세 탭에서 남긴 코멘트가 모두 나온다.
  미디어 탭마다 보이려면 `ListComments{assetId}`.
- **재생** — 녹화를 틀면서 재생 위치가 `t_ms`를 지날 때마다 그 줄의 `screen`으로 옆 화면을 옮기고 `media` · `range` · `selected` · `view`를
  되살린다. "이 말을 할 때 보던 성적서 3쪽"이 같이 뜬다.
- **STT** — 서버가 코멘트를 만들 때 건다(§3). 목록은 자막을 `body` 대신 보여 줄 수 있고, 처리 중 · 말소리 없음도 표시한다.
- **비디오 멀티모달의 녹화** — 지금처럼 `녹화 영상` · `녹화 음성` 트랙의 재생 바 자리에 클립으로 놓고(`웹캠 녹화 업로드와 STT 안내.md` §4),
  그 뒤에 `CreateComment`를 한 번 더 부른다. 코멘트는 파일을 가리키고 클립은 그 파일을 타임라인에 놓은 것이라 둘이 함께 있어도 된다.
  STT는 다른 탭과 같이 서버가 건다. 이 녹화는 타임라인에 놓여 있어 자막 Clip까지 생긴다.

## 5. 프론트가 할 일

1. 녹화 버튼을 화면 공통 머리(헤더)로 옮겨 모든 화면에서 녹화할 수 있게 한다(지금은 품질 이슈 · 비디오 멀티모달 화면에 따로 있다).
2. 녹화 중 페이지 상태(미디어 탭 · 그 위치, 차트 구간 · 재생 바, 고른 검사 행 · 클립, `view` 키)가 바뀔 때마다 `context`에 한 줄 쌓는다.
   세 페이지가 같은 칸 이름을 쓴다(§2).
3. 품질 이슈 · 패스별 파라미터 · 비디오 멀티모달 화면에 **같은 컴포넌트 하나**로 코멘트 목록을 둔다. 탭으로 거르지 않고 작업 · 패스로만 부른다.
4. 재생할 때 `context` 줄로 화면을 되살린다.
5. 코멘트에 STT를 따로 걸지 않는다. `CreateComment` 뒤 `GetRun`을 기다리느라 화면을 멈추지 않고, 목록에 처리 상태를 보인다.

## 7. 보류

1. **공사 · 작업자로 찾기**(2026-11-04 넘어감). 작업자 화면에서 단 코멘트를 "이 작업자의 코멘트"로 찾아야 하면 `worker_id` ·
   `project_id` 칸을 더한다(또는 `context`에 칸을 더한다). 그전까지는 작업 없는 화면의 코멘트는 `screen`으로만 남는다.
2. **비디오 멀티모달의 질문(영상 질의)**(2026-11-04 넘어감). 질의 기록이 저장되면 그 id를 `selected`에 넣을 수 있다. 그전까지 뺀다.

정한 것

- 작성자는 기록하지 않는다(2026-11-04). 작성자는 로그인한 사람이지만 권한 · 계정 관리가 아직 없고 서버는 로그인을 모른다.
  계정 관리가 생기면 `account_id`를 더한다. 그 전에 남긴 코멘트의 작성자는 채울 수 없다.
- 코멘트가 가리키는 자료 표(`comment_target`)는 두지 않는다(2026-11-04). `context`의 `media.asset_id`를 GIN 인덱스로 찾는다.
- 검사 행은 `doc.*` 표 이름 + 행 `id`로 적는다(2026-11-04).
- 코멘트 음성 STT는 서버가 코멘트를 만들 때 faster-whisper로 바로 걸고, 자막 Clip을 못 놓아도 성공으로 둔다(2026-11-04, §3).

## 8. 검토했다가 버린 안

| 안 | 버린 이유 |
|---|---|
| 품질 이슈를 `tag` 클립 + 성적서 `pdf` 클립 + `relation` 클립으로 | Clip은 시각이 필수인데 녹화 · 검사 결과에는 타임라인 시각이 없다. 가짜 시각을 붙이게 된다 |
| 검사 결과 ↔ 에셋 표(`doc.inspection_asset`) | 성적서에만 묶여, 파라미터 차트를 보며 남긴 코멘트를 받지 못한다 |
| 메모 + 근거 에셋 표(`note` · `note_asset`) | 녹화 · 글 · 맥락을 따로 다뤄야 했다. 코멘트 하나로 합쳤다 |
| 녹화 표(`recording`) | 코멘트와 같은 것이다. 화면에서 부르는 이름(코멘트)으로 둔다 |
| 에셋에 `context` · `comment_id` 칸 | 녹화는 파일이 둘이라 맥락을 두 번 적고, 에셋 표에 코멘트에만 쓰는 칸이 생긴다 |
| 패스 안의 위치 칸(`location`: 각도 · 시작부) | 화면에 그런 입력이 없다 |
| `context`에 화면 주소(`route`)를 그대로 | 프론트 표기라 학습 쪽이 풀려면 프론트 규칙을 알아야 하고, 주소 체계가 바뀌면 옛 기록의 뜻이 흐려진다 |
| `context`에 그 순간 보이는 것 전부 | 한 페이지에 정보가 많아 줄이 길어지고, 위젯이 늘 때마다 적는 규칙이 는다. 대부분 작업 · 패스로 다시 나온다 |
| 코멘트가 가리키는 자료 표(`comment_target`) | `context`의 `media`와 같은 내용을 두 번 적는다. GIN 조회로 된다 |
