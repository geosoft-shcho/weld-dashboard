# 멀티모달 화면 코멘트 (1차)

## 목표
비디오 멀티모달에서 웹캠 녹화를 올리고 클립을 놓은 뒤, 음성 asset이 있으면 `CreateComment`로 화면 코멘트를 남긴다. 글은 선택, context는 `screen: multimodal` 한 줄 이상. 같은 카드 아래에 이 작업의 코멘트 목록과 STT 상태만 보여 준다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md` (가이드라인 저장소는 워킹 트리 밖에서 읽기만)
3. `protos/mediatag/asset/v1/asset.proto` `Comment` · `CreateComment` · `ListComments`
4. `lib/src/presentation/features/video_multimodal/widgets/camera_recording_dialog.dart`
5. `lib/src/presentation/features/video_multimodal/camera_recording_view_model.dart`
6. `docs/2026-11-05/화면 코멘트(웹캠 녹화) 설계.md` §3·§4
7. `docs/2026-11-05/README.md` 2026-11-04 화면 코멘트 절

## 현재 상태
- proto와 생성 Dart에 `CreateComment` · `ListComments`가 있다. 앱 domain/repository는 호출하지 않는다.
- 녹화 UI는 `CameraRecordingOverlay` 340px 카드다. 멀티모달 화면이 연다.
- `CameraRecordingScope`는 품질·패스 스텁이라 이번 연동 대상이 아니다.
- 업로드 뒤 `onRecordingPlaced`로 클립을 놓고 `onUploaded`로 가볍게 갱신한다. STT는 화면이 따로 걸 수 있다.

## 바꿀 것
1. domain: `ScreenComment`와 `CreateScreenComment` / `ListScreenComments` use case. context는 `List<Map>`을 proto `ListValue`로 넘긴다.
2. `AssetUploadRepository`에 create/list만 추가. 생성 코드는 수정하지 않는다.
3. `CameraRecordingViewModel`: `capturesScreenComment`일 때만, 시작 시 context 첫 줄, 업로드·배치 성공 후 음성 asset으로 `CreateComment` 1회. 실패는 업로드 성공 문구에 덧붙인다. `GetRun`으로 STT를 기다리지 않는다. Scope(플래그 false)는 코멘트를 만들지 않는다.
4. 멀티모달 VM이 스냅샷을 넘긴다. `screen: multimodal`, `job_id`, 재생 바 `range`, 선택 클립 `selected`, `view`(`tracks`·`playing`·`speed`·`panel`). 녹화 중 탐색·재생/정지·패널·선택 클립이 바뀔 때만 줄을 추가한다.
5. 카드에 글 입력과 `ListComments{jobId}` 목록. STT 문구: 처리 중 / 완료 / 말소리 없음 / 맡기지 못함.
6. locator와 업로드 저장소 가짜, 코멘트 테스트를 연결한다.

## 유지할 것
- 업로드 → 후처리 → `didPlaceUploadedRecording` → `refreshAfterRecordingUpload`
- 트랙별 배치, vector 안내 억제
- tag 클립(좋아요·싫어요·근거)

## 이번 작업에서 만들지 않음
- proto 재생성
- 공통 헤더로 녹화 버튼 이동
- 품질 이슈·패스별 파라미터 코멘트·context 되살리기
- `UpdateComment` · `DeleteComment` UI
- 화면이 `StartRun`으로 STT를 다시 거는 것

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
