# 코멘트에서 클립·영상을 재생하기 위한 서버 요구

화면은 코멘트를 펼쳤을 때, 그 코멘트가 가리키는 타임라인 클립 또는 녹화 영상을 플레이어에 튼다. 목록 API를 새로 만들지 않는다. `ListComments`가 이미 주는 값을 재생에 쓸 수 있게 보장한다.

## 화면이 하는 일

코멘트 하나마다 재생 대상을 하나만 고른다.

1. `context` 줄에 `selected[].clip_id`가 있으면 그 클립을 튼다. 시각은 같은 줄의 `range`다.
2. 클립이 없으면 `videoAssetId` 영상을 파일 처음부터 튼다.
3. `videoAssetId`도 없으면 재생 버튼을 두지 않는다. 음성만 있는 코멘트다.

작업 번호는 코멘트의 `jobId`를 쓴다. `context`의 `job_id`는 녹화할 때 보던 작업이라, 코멘트 `jobId`와 다를 수 있다. 재생은 코멘트의 `jobId` 타임라인과 그 작업에 첨부된 에셋만 본다.

## 이미 내려오는 값

`ListComments`는 아래를 코멘트마다 빠뜨리지 않는다. 새 필드를 추가하지 않는다.

| 필드 | 재생에 쓰는 뜻 |
|---|---|
| `jobId` | 타임라인을 열 작업 |
| `videoAssetId` | 웹캠 영상. `0`이거나 없으면 영상 없음 |
| `audioAssetId` | 웹캠 음성. 재생 대상이 아니라 코멘트가 성립하는 조건 |
| `context[].screen` | `multimodal`이면 타임라인 클립, `quality`·`pass`이면 보통 녹화 파일 |
| `context[].range.start_ns` `end_ns` | 작업 시간축 나노초. 한 점이면 시작과 끝이 같다 |
| `context[].selected[].clip_id` | 그 작업 타임라인의 클립 번호 |
| `context[].t_ms` | 녹화 파일 안의 시각. 이번 재생 이동에는 쓰지 않는다 |

예시처럼 멀티모달 코멘트는 클립 `18664`, 구간 시작=끝 `284782016000000`이다. 품질 코멘트는 클립과 구간이 없고 영상은 `videoAssetId` `23579`다.

## 서버가 보장할 것

1. `selected[].clip_id`는 그 코멘트 `jobId`의 타임라인 클립이다. `GetTimeline`에 같은 `clip_id`가 있고, 그 클립의 영상 에셋은 `GetAsset`의 `content_url`로 받을 수 있다. `content_url`은 Range 요청으로 구간 재생이 된다.
2. 클립이 나중에 지워져도 `ListComments`의 `context`는 저장 당시 그대로 둔다. 화면은 타임라인에 클립이 없으면 재생하지 않고, 녹화 영상(`videoAssetId`)이 있으면 그 파일을 튼다.
3. `range`는 작업 시간축이다. 파일 안 시각이 아니다. 시작과 끝이 같으면 그 시각으로 이동한다. 시작이 끝보다 크면 그 줄은 재생에 쓰지 않는다.
4. `videoAssetId`가 있으면 `kind = video`이고 같은 작업에 첨부되어 있다. `GetAsset`의 `content_url`로 파일 전체를 재생할 수 있다. 타임라인에 클립이 없어도 된다.
5. `audioAssetId`는 `kind = audio`이다. 이번 재생 버튼은 영상을 틀므로, 음성만으로 플레이어를 열지 않는다.
6. `subtitleAssetId`와 `stt`는 재생을 시작하지 않는다. 자막이 없어도 클립·영상 재생은 된다.

## 확인 방법

- 코멘트 3: 작업 `1219` 타임라인에서 클립 `18664`를 고르고, 재생 위치를 `284782016000000` ns로 옮긴다.
- 코멘트 3의 클립이 타임라인에 없으면 영상 `23582`의 `content_url`을 파일 처음부터 튼다.
- 코멘트 2: 클립이 없으므로 영상 `23579`의 `content_url`을 파일 처음부터 튼다.
- `videoAssetId`가 없고 클립도 없으면 재생하지 않는다.
