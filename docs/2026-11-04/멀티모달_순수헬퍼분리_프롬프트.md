# 순수 헬퍼 파일 분리

## 목표
`video_multimodal_view_model.dart`에서 인스턴스 필드/`notifyListeners`를 쓰지 않는 계산만 별도 파일 top-level 함수로 옮긴다. 공개 API·로드/재생 동작은 그대로다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md`
3. VM 해당 private 메서드, `video_playback_rate.dart`, `video_multimodal_models.dart`
4. 없음

## 현재 상태
- 순수 계산이 VM private로 남아 있다.
- 이미 같은 패턴의 유틸이 있다 (`video_playback_rate`, `video_overlay_clock`, `pose_playback_log`).
- `_trackName`·`_writeFailureMessage`·`_labelName` 등은 `_timeline`/`_timelineHint`/`_labelRoots`에 묶여 이번 범위 밖.

## 바꿀 것
1. `timeline_clip_helpers.dart` (신규): `doTimelineIntervalsOverlap`, `doesClipCoverSeconds`, `compareTimelineClipId`, `overlaySeekStartNs`, `clipPlaybackInputFrom`, `timelineClipKindLabel`
2. `attachment_bar_helpers.dart` (신규): `isDepthVideoFileName`, `chainAttachmentBars` (`PROVISIONAL_BAR_SECONDS`는 인자 또는 파일 상수)
3. `timeline_playhead_clock.dart`에 `formatPlayheadClock` 추가
4. VM에서 위 9개 private 본문 삭제, top-level 호출로 교체
5. `_citationFeedbackText`는 호출부에 인라인하거나 VM 유지 (추출하지 않음)

## 유지할 것
- ViewModel 단일 클래스·DI·화면
- 상태 의존 private / public API
- mixin·part·Base 분리

## 이번 작업에서 만들지 않음
- 상태 의존 메서드 파일 분리
- 이름 대정리·로직 변경
- 테스트/로그 개편

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
