# 녹화 업로드마다 별도 트랙 생성

## 목표
실시간 녹화 영상·음성 업로드 시마다 같은 `녹화 영상`/`녹화 음성` 트랙에 클립을 쌓지 않고, 업로드마다 각각 별개 트랙에 배치한다. 이름은 첫 번째 `녹화 영상`/`녹화 음성`, 이후 `녹화 영상 2`/`녹화 음성 2` … 이다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md` (가이드라인 저장소는 워킹 트리 밖에서 읽기만)
3. `lib/src/presentation/features/video_multimodal/video_multimodal_view_model.dart` (`didPlaceUploadedRecording`, `_ensureRecordingTrackId`, `_ensureSpeechToTextClipSelected`, `RECORDING_*_TRACK_NAME`)
4. `test/ask_question_test.dart` (녹화 배치 관련 테스트)
5. `docs/2026-10-30/녹화업로드_녹화트랙클립보장_프롬프트.md` (이전 동작 배경)
6. 없음 (별도 계약·화면안 없음)

## 현재 상태
- `_ensureRecordingTrackId`는 `녹화 영상`/`녹화 음성` 고정 이름을 `_trackIdByName`으로 찾아 재사용한다.
- 없으면 `- · video`/`- · audio` 플레이스홀더를 그 이름으로 바꾼 뒤, 그래도 없으면 CreateTrack한다.
- `didPlaceUploadedRecording`은 확보한 한 트랙에 클립을 만들거나 옮긴다.
- `_ensureSpeechToTextClipSelected`는 이름 정확히 `녹화 음성`인 트랙만 우선 선택한다.
- 테스트는 단일 `녹화 영상`/`녹화 음성` 트랙 재사용을 가정한다.

## 바꿀 것
1. `_ensureRecordingTrackId`를 “고정 이름 재사용”에서 “이번 업로드용 고유 트랙 확보”로 바꾼다.
   - 같은 `assetId` 클립이 이미 있으면 그 클립의 `trackId`를 그대로 쓴다(새 트랙·중복 클립 없음).
   - 새 배치면 사용 중이지 않은 이름을 고른다: 기본 `녹화 영상`/`녹화 음성`, 이미 있으면 `녹화 영상 2`, `녹화 음성 2` … (`n`을 올려 가며 `_trackIdByName`이 null인 첫 이름).
   - 해당 종류 녹화 트랙이 아직 없고 플레이스홀더(`- · video`/`- · audio`)만 있으면 그 트랙을 고른 이름으로 바꾼다. 이미 녹화 트랙이 있으면 플레이스홀더를 건드리지 않고 CreateTrack한다.
2. `didPlaceUploadedRecording`은 위 헬퍼가 돌려 준 `trackId`에 기존처럼 create/move/playhead 맞추기를 한다. 업로드 API·콜백·길이 공식은 유지한다.
3. `_ensureSpeechToTextClipSelected`는 이름이 `녹화 음성`이거나 `녹화 음성 `으로 시작하는 트랙을 우선해 음성 클립을 고른다. 없으면 기존처럼 아무 음성 클립.
4. `test/ask_question_test.dart`를 맞춘다.
   - 빈 타임라인 1회 업로드 → `녹화 영상`/`녹화 음성` (기존).
   - 같은 종류를 두 번(다른 assetId) 업로드 → 트랙 2개(`녹화 영상`, `녹화 영상 2` 등), 클립 각 1개.
   - 이미 같은 asset이 녹화 트랙에 있으면 추가 CreateTrack 없음(기존 유지).
   - 다른 트랙에만 있던 asset → 새(또는 배정) 녹화 트랙으로 이동.
   - 플레이스홀더 rename 케이스는 “아직 녹화 트랙이 없을 때”로 유지.

## 유지할 것
- `RECORDING_VIDEO_TRACK_NAME` / `RECORDING_AUDIO_TRACK_NAME` 상수 문자열(기본 이름)
- `onRecordingPlaced` → `didPlaceUploadedRecording` 연결
- playhead·duration(없으면 5초) 신규 클립 공식
- 수동 드롭·인용 피드백 트랙 로직
- CreateTrack/UpdateTrack/CreateClip/UpdateClip use case 자체

## 이번 작업에서 만들지 않음
- 트랙 UI·라벨 디자인 개편
- proto/서버 자동 배치 변경
- 시각(timestamp) 접미사 이름
- ViewModel part 분리·대규모 리팩터
- `login_screen.dart` 변경

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
