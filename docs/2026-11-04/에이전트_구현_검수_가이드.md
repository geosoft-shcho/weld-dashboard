# 에이전트 구현 검수 가이드

기능 구현 요청 이후, **에이전트가 이미 해야 할 검수**와 **사용자가 보면 되는 검수**를 나눈다.  
구현 파이프 자체는 [`docs/2026-11-03/Cursor_에이전트_기능구현_방식.md`](../2026-11-03/Cursor_에이전트_기능구현_방식.md)와 [`AGENTS.md`](../../AGENTS.md)를 따른다.

---

## 한 줄

- **사용자:** Plan(스펙)이 맞는지, 그 스펙의 **완료 확인**이 앱에서 되는지.
- **에이전트:** `agent_check`·범위·금지·API 일치 등 **게이트**를 구현 직후 통과했는지 보고.

---

## 1. 사용자가 하는 검수 (권장 순서)

### 1.1 Plan 단계 (코드 나오기 전)

에이전트가 올린 작업 프롬프트에서만 확인한다.

| 볼 것 | 통과 기준 |
|--------|-----------|
| 목표 | 내가 원하는 사용자 동작인가 |
| 바꿀 것 | 필요한 만큼만인가. 과한 범위 없는지 |
| 유지할 것 / 만들지 않음 | 내가 지키려는 것과 맞는지 |
| 애매한 부분 | 가정이 아니라 **질문**으로 왔는지 |

여기서 “확인”하면 그게 곧 계약이다. 이후 구현은 이 문서 기준이다.

### 1.2 구현 직후 — 문서와 diff 대조

저장 파일: `docs/<날짜>/<작업>_프롬프트.md`

| 볼 것 | 통과 기준 |
|--------|-----------|
| 범위 | 바뀐 파일이 「바꿀 것」과 맞음. 밖은 거의 없어야 함 |
| 금지 | 새 추상 계층·카드 UI·범위 밖 리팩터 없음 |
| 완료 확인 | 프롬프트에 적은 UX·동작이 실제로 됨 |
| 검증 보고 | 에이전트가 `./scripts/agent_check.sh`를 돌렸다고 보고했는지. 실패면 미완료 |

Cursor의 diff / Source Control로 **파일 목록만** 먼저 훑고, 의심스러운 파일만 연다.

### 1.3 앱에서 동작 확인

`flutter run` 등으로 프롬프트 **완료 확인**에 적힌 시나리오만 재현한다.  
전체 회귀가 아니라 **그 작업의 완료 확인 bullet**이 사용자의 동작 체크리스트다.

### 1.4 (선택) 커밋 전

“커밋해줘”는 위 검수가 끝난 뒤에 요청한다.  
에이전트는 기능 구현이면 `agent_check` 통과 전에는 커밋하지 않아야 한다.

### 1.5 사용자용 짧은 루틴

```text
1) Plan 프롬프트 OK? → 확인
2) *_프롬프트.md 의 「바꿀 것」 vs 실제 변경 파일
3) agent_check 통과 보고가 있는가
4) 완료 확인에 적힌 화면/동작만 손으로 확인
5) 문제 없으면 (원하면) 커밋 요청
```

## 2. 에이전트가 이미 해야 할 검수

구현 직후, 사용자 검수 **전에** 에이전트가 수행하고 결과에 반영한다.  
보고에 아래가 없으면 사용자는 되묻거나 **미완료**로 보면 된다.

### 2.1 검증 스크립트

```bash
./scripts/agent_check.sh
./scripts/agent_check.sh test/<관련>_test.dart
```

- 인자 없음 → `dart analyze`
- 인자 있음 → analyze 후 해당 `flutter test`
- **실패하면 완료로 치지 않는다.** 고친 뒤 다시 돌린다.

### 2.2 구현 후 검수 체크리스트

| 항목 | 기준 |
|------|------|
| 범위 | 「바꿀 것」 밖 파일이 바뀌지 않았다 |
| 금지 | 「복잡한 코드 제거 및 금지」를 어기지 않았다 |
| 계약 | import·API·proto 필드가 실제 코드/계약과 일치한다 |
| 검증 | `agent_check`가 실패하지 않았다 |
| 범위 부족 | 프롬프트 문서를 고친 뒤 재구현한다. 프롬프트만 반복해 우회하지 않는다 |

상세: `.cursor/skills/work-prompt/SKILL.md`의 「구현 후 검수」.

### 2.3 회고 (해당할 때만)

오판·거절한 diff·반복 실수가 있으면:

- 프롬프트 말미 또는 `docs/<날짜>/회고_<작업>.md`에 짧게 남긴다
- 같은 실수가 반복되면 `.cursor/rules` 또는 스킬 금지·완료 확인으로 **승격**한다

### 2.4 커밋 요청을 받았을 때

기능 구현 직후 커밋이면:

- 이번 대화에서 `./scripts/agent_check.sh`를 실행해 **통과한 뒤에만** 커밋한다
- 미실행·실패면 커밋하지 않고 알린다
- `.env`·자격 증명·키·시크릿은 커밋하지 않는다

상세: `.cursor/skills/git-commit-push/SKILL.md`

## 3. 역할 한눈에

| 단계 | 에이전트 | 사용자 |
|------|----------|--------|
| Plan | 프롬프트 초안 (범위·금지·완료 확인 포함) | 스펙 확인 / 질문 답변 |
| 저장 | `*_프롬프트.md` 저장 | (필요 시) 경로·제목만 확인 |
| 구현 | 문서만 구현 + guidelines | — |
| 게이트 | `agent_check` + 구현 후 검수 (+ 회고) | 보고에 게이트가 있는지 확인 |
| 수용 | — | diff 범위 + 완료 확인 UX |
| 커밋 | 요청 시에만, check 통과 후 | 커밋 요청 여부 결정 |
