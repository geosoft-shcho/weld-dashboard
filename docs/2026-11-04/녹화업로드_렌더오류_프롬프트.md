# 녹화 업로드 렌더 오류 수정

## 목표
실시간 녹화 업로드·타임라인 배치 중에 Navigator `!_debugLocked` / go_router “last page popped” 가 나지 않게 한다. 업로드 후에도 보드·Assets는 최신으로 맞춘다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md` (가이드라인 저장소는 워킹 트리 밖에서 읽기만)
3. `lib/src/presentation/features/video_multimodal/video_multimodal_view_model.dart` (`didPlaceUploadedRecording`, `_commitServerWrite`, `openTimeline`)
4. `lib/src/presentation/features/video_multimodal/video_multimodal_screen.dart` (`onUploaded`, `_VectorSaveNoticeListener`)
5. `lib/src/presentation/features/video_multimodal/widgets/vector_db_saved_dialog.dart`
6. `test/ask_question_test.dart` (녹화 배치 관련 테스트)
7. 없음 (별도 계약·화면안 없음)

## 현재 상태
- 배치 경로: `CameraRecordingViewModel` → `didPlaceUploadedRecording` → `_commitServerWrite`(CreateTrack/CreateClip) → `_vectorSaveTrackCount` 설정 → `_VectorSaveNoticeListener`가 `showVectorDbSavedDialog` 표시
- 업로드 완료 후 `onUploaded: viewModel.openTimeline`이 `_isLoading = true`로 스테이지를 ProgressRing으로 바꿔 플레이어/트리를 걷어 냄
- 트랙을 업로드마다 새로 만들면서 CreateTrack/CreateClip 알림이 더 자주 뜨고, 다이얼로그 push와 `openTimeline` 리빌드가 겹치면 Navigator dispose / go_router 빈 스택 assertion으로 이어짐
- 배치는 이미 `_replaceTimelineFromServer`로 타임라인을 갱신함. 완료 후 전체 `openTimeline`은 중복이고 UI를 과도하게 흔듦

## 바꿀 것
1. `_commitServerWrite`에 `announceVectorSave` (기본 `true`)를 두고, false면 `_vectorSaveTrackCount`를 세팅하지 않는다.
2. `didPlaceUploadedRecording`이 쓰는 create/update track·clip 경로에서 `announceVectorSave: false`로 호출한다(헬퍼/`createTimelineTrack` 등에 넘기거나, 배치 전용으로만 false).
3. `refreshAfterRecordingUpload`를 ViewModel에 추가: `_isLoading`을 켜지 않고, `_side = none`으로 리셋하지 않으며, `_replaceTimelineFromServer` + Assets/첨부 쪽 `_loadSideAssets`(또는 동등한 가벼운 재조회)만 한다. 카메라 오버레이는 유지.
4. `video_multimodal_screen.dart`의 `CameraRecordingOverlay.onUploaded`를 `openTimeline` 대신 위 메서드로 바꾼다.
5. `vector_db_saved_dialog.dart` 확인 버튼: `Navigator.of(context).canPop()`일 때만 `pop` (잘못된 루트 pop 방지).
6. 관련 단위 테스트: 녹화 배치 후 `vectorSaveNoticeTrackCount == null` 유지; 가능하면 새 refresh 메서드가 `_isLoading`을 true로 두지 않음을 확인 (`test/ask_question_test.dart`).

## 유지할 것
- 업로드 → postprocess → `didPlaceUploadedRecording` → (완료 시) 새로고침 순서
- 수동 타임라인 편집의 vector DB 저장 안내 다이얼로그
- 트랙별도생성(`녹화 영상 2` …) 동작
- `login_screen.dart` 로컬 변경 제외

## 이번 작업에서 만들지 않음
- go_router 구조 개편, Fluent Navigator 교체
- 카메라 UI/업로드 API 변경
- analyze 기존 warning 일괄 정리

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
