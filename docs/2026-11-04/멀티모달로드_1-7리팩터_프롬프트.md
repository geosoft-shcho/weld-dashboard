# 멀티모달 페이지 로드 1~7 리팩터

## 목표
멀티모달 진입 시 타임라인을 먼저 보여 주고, ListAssets·ListLabels·ListRuns·GetJob·ReadContent는 지연·병렬·캐시로 줄여 체감 로드를 짧게 한다. `[MM-LOAD]`로 블로킹/백그라운드를 구분한다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md`
3. `lib/src/presentation/features/video_multimodal/video_multimodal_view_model.dart` `loadAttachments` 및 하위 로드
4. `lib/src/presentation/features/video_multimodal/video_multimodal_screen.dart`
5. `lib/src/presentation/features/video_multimodal/multimodal_load_api_log.dart`
6. `lib/src/domain/use_cases/list_history_work_attachments_use_case.dart`, `lib/src/data/repositories/remote_work_detail_repository.dart` `listAttachments`
7. 계약·화면안: 없음

## 현재 상태
- `loadAttachments`가 GetTimeline → ListAssets → GetJob → ReadContent → ListLabels → ListRuns를 **직렬·블로킹**으로 끝낸 뒤에야 `_isLoading=false`.
- 실측: ListAssets ~3.3s, ListLabels ~3.0s가 total ~7.4s의 대부분.
- 첨부 사이드를 처음부터 `assets`로 연다.

## 바꿀 것 (1~7 대응)

### 1. 첫 페인트에 필수만
- `openJob()`: **블로킹**은 `GetTimeline`까지. 성공 시 `_isLoading=false` + notifyListeners.
- 이후 백그라운드: overlay ReadContent, ListAssets, ListLabels(캐시 미스 시), ListRuns 복원, GetJob(projectId).

### 2. 독립 호출 병렬
- 백그라운드 `Future.wait`: ListAssets · GetJob · ListLabels(미스) · ListRuns.
- ReadContent는 Timeline 직후 URL별 병렬 GET.

### 3. ListAssets 비용
- `listAttachments` pageSize 200 → 50.
- 첫 페인트 뒤로. `_isLoadingAttachments` 플래그.

### 4. ListLabels 세션 캐시
- `label_roots_session_cache.dart` 프로세스 내 캐시.
- 히트 시 네트워크 없음. 생성/이름변경/폐기 시 갱신/무효화.

### 5. GetJob 지연
- 진입 블로킹에서 제외. 백그라운드 또는 Ask 필요 시.

### 6. ReadContent 병렬
- `_loadOverlayBodies`를 `Future.wait`로.

### 7. 책임 분리 + 로그
- `openJob` / `loadAttachments`→`openJob` 위임.
- MM-LOAD phase=blocking|background, blocking_done / background_done.

## 유지할 것

- 타임라인/포즈/STT 동작
- MM-LOAD 디버그(확장만)

## 이번 작업에서 만들지 않음
- Timeline assets로 ListAssets 완전 대체
- 전역 HTTP 인터셉터·Shell 라벨 DI 대공사
- proto/서버 변경
- pageSize를 job별로 동적 페이징 UI

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
