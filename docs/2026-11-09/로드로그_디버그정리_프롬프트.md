# 로드 log?/디버그 헬퍼 정리

## 목표
`log?.step` 등 조사 전용 로드 로그와 print 헬퍼를 걷어, 기능 동작은 그대로 두고 소스를 가볍게 한다. 실제 재생 실패 `debugPrint`만 남긴다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `lib/src/presentation/features/video_multimodal/video_multimodal_view_model.dart` (`_loadApiLog`, `log?.`, `_posePlaybackLog`)
3. `lib/src/presentation/features/video_multimodal/multimodal_load_api_log.dart`
4. `lib/src/presentation/features/video_multimodal/pose_playback_log.dart`
5. `lib/src/presentation/features/video_multimodal/playhead_covering_log.dart`
6. `lib/src/data/repositories/remote_asset_lookup_repository.dart` (`[AssetLookup]` debugPrint)
7. 계약·화면안: 없음

## 현재 상태
- 진입 로드마다 `MultimodalLoadApiLog` + `log?.step` / `log?.stepDone` / `log?.backgroundDone`이 `[MM-LOAD]`를 print한다.
- `PosePlaybackLog`·`PlayheadCoveringLog`는 성공/진행 경로까지 print한다.
- `_logTimeseries`·`_logCitationClipMatch`는 kDebugMode debugPrint 헬퍼다.
- AssetLookup 저장소도 요청/응답을 debugPrint한다.
- 비디오/오디오 플레이어의 `playback … failed` debugPrint는 실패 진단용이다.

## 바꿀 것
1. 제거 `MultimodalLoadApiLog` 파일과 ViewModel의 `_loadApiLog`·모든 `log?.…`·`log.step` 인자. `_fetchGetTimeline` 등은 로그 파라미터 없이 로드만 수행.
2. 제거 `PosePlaybackLog` 파일과 `_posePlaybackLog` 필드·호출. `_failPose`의 `_clipDetailMessage` 설정은 유지.
3. 제거 `PlayheadCoveringLog` 파일과 호출부.
4. 제거 `_logTimeseries`·`_logCitationClipMatch` 및 호출.
5. 제거 `remote_asset_lookup_repository.dart`의 `[AssetLookup]` debugPrint 두 곳.
6. 유지 `multimodal_video_player` / `multimodal_timeline_audio_player`의 실패용 `debugPrint('[VIDEO|AUDIO] … failed')`.

## 유지할 것
- GetClip 큐·pending 가드·Properties 요약 로딩 UI·Assets 자동 오픈 제거
- 로드 API 호출 자체(GetTimeline/List*)

- 새 로깅 프레임워크, 로그 레벨 스위치
- 프롬프트 밖 리팩터

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
