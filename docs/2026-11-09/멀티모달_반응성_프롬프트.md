# 멀티모달 클립·툴바 반응성

## 목표
멀티모달에서 클립 선택과 툴바 사이드 전환이 덜 멈추게 한다. 같은 자막·포즈 본문을 여러 번 받지 않고, Properties는 GetClip 직후 보이며, 재생 틱·사이드 전환이 타임라인·툴바 전체를 같이 다시 그리지 않는다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md` (가이드라인 저장소는 워킹 트리 밖에서 읽기만)
3. `lib/src/presentation/features/video_multimodal/video_multimodal_view_model.dart`
4. `lib/src/presentation/features/video_multimodal/video_multimodal_screen.dart`
5. `lib/src/presentation/features/video_multimodal/clip_detail_cache.dart`
6. 계약·화면안: 없음

## 현재 상태
- `video_multimodal_view_model.dart`: `_ensureSubtitleCues`·`_ensurePoseFrames`는 결과 맵만 보고, 진행 중 요청을 합치지 않는다. 클립 선택 시 `_applyLoadedClipDetail`이 자막 ReadContent를 기다린 뒤에야 Properties 로딩을 끝낸다. 플레이헤드 틱(32ms)마다 `notifyListeners`한다.
- `video_multimodal_screen.dart`: `_VideoMultimodalBody`가 `context.watch`로 ViewModel 전체를 구독해, 틱·사이드 전환마다 툴바·스테이지·보드·사이드가 같이 다시 그려진다.
- `clip_detail_cache.dart`: GetClip만 inflight를 합친다. 자막·포즈 ReadContent에는 같은 패턴이 없다.

## 바꿀 것
1. 자막·포즈 `readContent`에 assetId 기준 inflight를 두어, 같은 본문 요청이 겹치면 하나만 받게 한다. 캐시 clear 때 inflight도 비운다.
2. GetClip(또는 캐시)으로 `_clipDetail`이 채워지면 Properties 로딩을 바로 끝내고 `notifyListeners`한다. 영상·자막 오버레이 본문 prefetch는 속성 표시를 막지 않게 백그라운드로 돌린다. 포즈 프레임은 재생 전에 그대로 기다린다.
3. `video_multimodal_screen.dart`에서 전체 `watch`를 없애고, 이미 쓰는 `context.select`로 툴바·에러·안내·사이드·녹화창과 스테이지·보드 구독을 나눈다. 재생 틱은 스테이지·보드만 다시 그리게 한다. 새 상태관리 패키지는 쓰지 않는다.

## 유지할 것
- GetClip 캐시(`ClipDetailCache`)와 클립 선택 시 Properties 사이드 열기
- 재생·시크·차트 로드 동작
- 사이드 패널 `_side` 토글 UX
- generated proto·로그인 화면·다른 feature 화면

## 이번 작업에서 만들지 않음
- IndexedStack 패널 유지
- 플레이헤드 틱 간격 변경
- ListLabels/ListAssets 서버 지연 자체 개선
- 타임라인 보드 가상 스크롤·CustomPainter 재작성
- Assets 자동 오픈 정책 변경

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
