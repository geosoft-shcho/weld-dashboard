# 디버그 로그 제거

## 목표
콘솔에 찍히던 성능/반응성 디버그(`[MM-REACT]`, `[VIDEO] open/initialize/seek`)를 제거하고, GetClip 상한·pending 가드·Properties 부분 로딩 등 기능 코드는 유지한다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `lib/src/presentation/features/video_multimodal/multimodal_reactivity_log.dart`
3. `lib/src/presentation/features/video_multimodal/video_multimodal_view_model.dart` (`MultimodalReactivityLog` 호출)
4. `lib/src/presentation/features/video_multimodal/video_multimodal_screen.dart`
5. `lib/src/presentation/features/video_multimodal/widgets/multimodal_video_player.dart` (`[VIDEO] open_*` / `initialize_done` / `seek_done` print)
6. 계약·화면안: 없음

## 현재 상태
- `MultimodalReactivityLog`가 clip/overlay/rebuild를 `print('[MM-REACT]…')`로 남긴다.
- `multimodal_video_player`가 open/initialize/seek 성공 경로를 `print('[VIDEO]…')`로 남긴다.
- GetClip 큐·캐시 가드·Properties 요약 UI는 이 로그와 무관한 기능이다.

## 바꿀 것
1. `MultimodalReactivityLog` 호출을 ViewModel·Screen에서 모두 제거한다.
2. `multimodal_reactivity_log.dart` 파일을 삭제한다.
3. `multimodal_video_player.dart`에서 조사 목적 `print('[VIDEO] open_start|open_fail|open_stale|initialize_done|seek_done…')`만 제거한다. 실제 실패용 `debugPrint('[VIDEO] playback…')` 등은 유지한다.

## 유지할 것
- GetClip 동시 1·pending latest·캐시 시 pending clear·selectedClipId apply 가드
- Properties 타임라인 요약 + GetClip 부분 로딩
- Assets 진입 자동 오픈 제거
- `PosePlaybackLog`, `MultimodalLoadApiLog`(`[MM-LOAD]`) — 이번 제거 범위 밖

## 이번 작업에서 만들지 않음
- MM-LOAD / POSE 로그 제거
- GetClip·프록시·prefetch 추가 변경

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
