# 에셋 후처리 필터·상세 재시도

## 목표
에셋 관리 목록에서 마지막 후처리 상태로 거르고, 상세에서 `Asset.postprocess`를 보여 주며 FAILED면 `RetryPostprocess`로 다시 건 뒤 `GetRun`으로 진행을 이어 보이게 한다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md`
3. `protos/mediatag/asset/v1/asset.proto` (`Asset.postprocess`, `ListAssetsRequest.postprocess_status`, `RetryPostprocess`)
4. `docs/2026-11-03/README.md` 「후처리 다시 걸기 · STT」
5. `lib/src/data/repositories/remote_asset_lookup_repository.dart`, `lib/src/presentation/features/asset_lookup/asset_lookup_screen.dart`, `lib/src/presentation/features/asset_lookup/asset_lookup_detail_screen.dart`, `lib/src/domain/repositories/asset_upload_repository.dart` (`retryPostprocess`)

## 현재 상태
- generated에 `PostprocessStatus` · `ListAssetsRequest.postprocessStatus` · `Asset.postprocess` · `retryPostprocess` 있음.
- 목록 `ListAssets`는 kind/query/equipment/job만 넣고 `postprocessStatus` 미설정(UNSPECIFIED = 전체).
- `AssetLookupRow`에 후처리 필드 없음. `_rowFrom`이 `postprocess`를 매핑하지 않음.
- 상세는 주제·상황·정보·작업만. 후처리 표시·재시도 버튼 없음.
- 업로드 다이얼로그용 `AssetUploadRepository.retryPostprocess`는 이미 있음.

## 바꿀 것
1. **도메인**: `AssetLookupRow`에 마지막 후처리 요약 추가(`runId`, `statusCode`, `errorMessage`). 상태 코드는 proto와 맞춘 짧은 문자열(예: `failed`, `succeeded`, …). 없으면 빈 값.
2. **목록 요청**: `AssetLookupRepository.listAssets` / `ListAssetLookupPageUseCase` / ViewModel에 `postprocessStatusCode`(빈 문자열 = 전체) 전달. `RemoteAssetLookupRepository`에서 비어 있지 않으면 `ListAssetsRequest.postprocessStatus` 설정.
3. **목록 UI**: 기존 필터 줄에 ComboBox **후처리** — 전체 · 대기 · 처리 중 · 완료 · 실패 · 취소. 선택 시 목록 다시 조회. 기존 `상태` 열(첨부 여부)은 유지.
4. **매핑**: `_rowFrom`에서 `asset.hasPostprocess()`면 요약 채움(목록·상세 공통).
5. **상세 UI**: `Asset.postprocess` 구역 — 상태 라벨, `runId`, FAILED면 `errorMessage`. FAILED일 때만 **후처리 다시 걸기** 버튼.
6. **상세 재시도**: 기존 `AssetUploadRepository.retryPostprocess`를 쓰는 UseCase(또는 Detail ViewModel이 쓰는 얇은 UseCase)로 `runId` 받고, 이미 있는 `_waitReplaceRun`과 같이 `ToolRunUseCase.getRun`으로 끝날 때까지 대기 후 `load()`로 `Asset.postprocess` 갱신. `StartRun` 금지. 재시도 중 버튼 비활성·오류 표시.
7. **DI**: Detail ViewModel에 재시도 UseCase 주입.
8. **테스트**: repository 요청에 `postprocessStatus` 세팅, 상세 재시도가 RetryPostprocess → GetRun 경로인 단위 테스트(가능하면 기존 패턴).

## 유지할 것
- 업로드 다이얼로그 재시도 흐름
- 목록 `상태` 열의 첨부/작업 미지정 의미
- `login_screen.dart` 로컬 임시값
- proto 재생성 없음(이미 반영됨)

## 이번 작업에서 만들지 않음
- 대기열(`ToolRun.queue`) 표시, 웹캠 STT UX
- 목록 행에 후처리 열 추가·첨부 상태 열 교체
- 에셋 상세 외 화면의 일반 재시도
- FAILED 외 상태(취소 등)에서의 재시도 버튼

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
