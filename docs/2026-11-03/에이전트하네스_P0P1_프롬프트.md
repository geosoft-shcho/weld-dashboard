# 에이전트 하네스 P0~P1 반영

## 목표
기능 구현 시 에이전트가 **기본 검증·구현 후 검수·도구 중립 지시·짧은 회고 승격**을 따르게 한다. Ask→Plan→프롬프트 md→Agent 순서는 유지한다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md` (가이드라인 저장소는 워킹 트리 밖에서 읽기만)
3. `.cursor/skills/work-prompt/SKILL.md`
4. `.cursor/skills/git-commit-push/SKILL.md`
5. 계약·화면안: 없음

## 현재 상태
- `.cursor/skills/work-prompt/SKILL.md`: 완료 확인이 자유 기입. analyze/test 기본 강제 없음. 구현 후 검수·회고 절 없음
- 루트 `AGENTS.md` 없음. Cursor 전용 rules/skills만 존재
- `docs/2026-11-03/Cursor_에이전트_기능구현_방식.md`는 삭제된 상태 → 보완 내용을 넣어 재작성
- CI/hooks/`scripts/agent_check.sh` 없음. `dart analyze`·`test/`는 프로젝트에 존재
- git-commit-push: `.env` 제외는 있음. 검증 실패 시 커밋 금지·시크릿 붙여넣기 금지는 약함

## 바꿀 것
1. `work-prompt` 스킬·규칙: 완료 확인 기본(`./scripts/agent_check.sh`, 관련 테스트, UX), 구현 후 검수, 회고(선택)·rule 승격, Agent 단계에 검증 실행 명시
2. 루트 `AGENTS.md` 신규 (~100줄 이하): A축, 목적, 스택, 검증 명령, 파이프, guidelines, 상세 링크
3. `scripts/agent_check.sh` 신규: 인자 없으면 `dart analyze`, 있으면 analyze 후 `flutter test` 경로
4. `docs/2026-11-03/Cursor_에이전트_기능구현_방식.md` 재작성: 흐름 + 하네스 층 표 + 검증·검수·회고 + 산출물 표 + 체크리스트
5. `git-commit-push` 스킬: 기능 구현 직후 커밋 시 agent_check 미통과·미실행이면 커밋 금지; 시크릿·자격증명 보강
6. `README.md`: 목적 근처에서 `AGENTS.md`·방식 문서로 안내

## 유지할 것
- Ask→Plan→확인→프롬프트 md→Agent 순서
- apply-guidelines·dashboard-purpose·document-export 역할
- 「복잡한 코드 제거 및 금지」 고정 조항 전문
- 사용자 요청 없는 커밋·푸시 금지
- Flutter `lib/**` 제품 기능 코드는 이 작업에서 변경하지 않음

## 이번 작업에서 만들지 않음
- GitHub Actions CI, Cursor hooks
- MCP 서버 연동
- 병렬/서브에이전트 절차
- 채용공고 조사 md·정합성 보완 md 복구
- 전수 `flutter test`를 매 작업 기본으로 강제(관련 경로만)

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
