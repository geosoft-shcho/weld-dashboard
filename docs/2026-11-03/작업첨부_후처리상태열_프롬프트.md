# 작업 첨부 탭 후처리 상태 열

## 목표
작업 상세 첨부 탭에서 ListAssets로 받은 첨부의 마지막 후처리 상태를 표에 보이게 한다. 헤더에 **후처리** 열을 두고, 행마다 상태 라벨·(실패 시) 사유 Tooltip·색 강조로 읽기 쉽게 한다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md`
3. `lib/src/presentation/features/job_lookup/widgets/job_attachment_tab.dart` (`_JobAttachmentTableHeader`, 행 Row)
4. `lib/src/domain/entities/asset_lookup_row.dart` (`AssetPostprocessSummary`, `AssetPostprocessStatusOption`)
5. `lib/src/presentation/features/job_lookup/job_lookup_detail_view_model.dart` `_loadAttachments` (이미 `ListAssetLookupPageUseCase` → `postprocess` 매핑됨)

## 현재 상태
- 첨부 목록은 `ListAssets(job)`이고 `_rowFrom`이 `Asset.postprocess`를 채운다. 탭 UI는 번호·종류·파일·패스·떼기만 그린다.
- `_JobAttachmentTableHeader`에 후처리 열 없음. 상태 표시·실패 사유 UI 없음.

## 바꿀 것
1. **헤더**: `_JobAttachmentTableHeader`에 **후처리** 열 추가(파일과 패스 사이, 고정 너비 약 110~120). 행 Row와 너비·순서를 맞춘다.
2. **행 셀**: `row.postprocess` 기준
   - 비어 있음 → `—`
   - 있으면 `AssetPostprocessStatusOption.labelOf(statusCode)`
   - `failed`(및 취소): 라벨을 warning/error 톤으로, `errorMessage`가 있으면 `Tooltip`으로 사유 표시. 짧은 `Icon`(예: `FluentIcons.warning` / `error_badge`)을 라벨 옆에 둘 수 있음.
   - 대기·처리 중·완료: 일반 본문 색 라벨만.
3. **표시 헬퍼**: 탭 파일 안 private 위젯/함수로 셀만 그린다. 새 디자인 시스템·카드·전역 상태 위젯 파일은 만들지 않는다.
4. **데이터**: 조회 RPC·필터 파라미터는 바꾸지 않는다(이미 매핑됨). 이 탭에서 인라인 RetryPostprocess 버튼은 넣지 않는다(상세·업로드 다이얼로그에 있음).

## 유지할 것
- 패스 콤보·떼기·올리기/붙이기 흐름
- 에셋 관리 목록 필터·상세 재시도 알림
- `login_screen.dart` 임시값

## 이번 작업에서 만들지 않음
- 첨부 탭 후처리 필터 ComboBox
- 첨부 행에서 RetryPostprocess 호출
- 에셋 관리 목록 상태 열 변경
- 대기열(`ToolRun.queue`) 표시

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
