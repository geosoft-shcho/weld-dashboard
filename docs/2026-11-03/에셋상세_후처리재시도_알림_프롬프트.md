# 상세 후처리 재시도 결과 알림

## 목표
에셋 상세에서 **후처리 다시 걸기**가 `RetryPostprocess` → `GetRun` → 재조회까지 끝난 뒤, GetRun 종료 상태와 다시 받은 `Asset.postprocess`를 `displayInfoBar`로 보여 준다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md`
3. `lib/src/presentation/features/asset_lookup/asset_lookup_detail_view_model.dart` (`retryPostprocess`, `_waitPostprocessRun`)
4. `lib/src/presentation/features/asset_lookup/asset_lookup_detail_screen.dart`
5. 기존 알림 패턴: `lib/src/presentation/features/asset_lookup/asset_lookup_screen.dart` `displayInfoBar` (올리기 완료)

## 현재 상태
- 재시도는 GetRun 종료 후 `load()`만 하고, 성공/재실패를 별도 알리지 않는다.
- RPC 예외만 후처리 구역 sticky `InfoBar`(error)로 보인다.
- 앱 다른 곳(업로드 완료)은 `displayInfoBar`로 한 번 띄운다.

## 바꿀 것
1. **ViewModel**: `_waitPostprocessRun`이 `ToolRunSnapshot`을 반환. `retryPostprocess`는 종료 스냅샷 + 재조회된 `asset.postprocess`로 알림 문구를 만들고 반환한다(또는 동일 내용의 작은 결과 객체).
   - 완료: severity success — 실행 번호 · 상태 완료
   - 실패/취소: severity error — 실행 번호 · GetRun `errorMessage`(없으면 재조회 `postprocess.errorMessage`) · 재조회 상태 라벨
   - RPC/`load` 예외: severity error — 예외 문구(기존 sticky와 중복되지 않게 sticky error는 제거하거나 알림만 사용)
2. **Screen**: 후처리 다시 걸기 `onPressed`에서 `await viewModel.retryPostprocess()` 후 `context.mounted`이면 `displayInfoBar`로 title/content/severity 표시(`onClose` 포함). 업로드 완료 알림과 같은 호출 형태.
3. **테스트**: 재시도 성공·GetRun 실패 경로에서 반환 알림 문구/severity가 맞는지 단위 테스트 보강.

## 유지할 것
- RetryPostprocess → GetRun → load 순서, StartRun 미사용
- 목록 후처리 필터, 업로드 다이얼로그 재시도
- `login_screen.dart` 임시값

## 이번 작업에서 만들지 않음
- 목록·업로드 다이얼로그 알림 변경
- 토스트 라이브러리·새 디자인 시스템 도입
- 대기열/STT UX

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
