# 첨부 탭에서 에셋 상세 열기

## 목표
작업 상세 첨부 테이블에서 에셋 번호로 에셋 상세 화면으로 이동할 수 있게 한다.

## 권장 입력 (선택)
**행 끝 IconButton(열기)** 을 쓴다. 에셋 목록·장비 상세는 행 탭이지만, 첨부 행에는 패스 `ComboBox`와 떼기 버튼이 있어 행 전체 더블클릭/싱글탭은 패스 조작과 겹친다. 떼기와 같은 `Tooltip`+`IconButton` 패턴이 발견·충돌 모두에 낫다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md`
3. `lib/src/presentation/features/job_lookup/widgets/job_attachment_tab.dart`
4. `lib/src/presentation/navigation/app_coordinator.dart` `didTapOpenAssetDetail`
5. 참고: `lib/src/presentation/features/asset_lookup/asset_lookup_screen.dart` / `lib/src/presentation/features/equipment_lookup/equipment_lookup_detail_screen.dart` 행 탭 → 상세

## 현재 상태
- 첨부 행에 상세 이동 없음. 떼기만 있음.
- `AppCoordinator.didTapOpenAssetDetail(assetId)`가 에셋 상세 라우트를 연다.

## 바꿀 것
1. `job_attachment_tab.dart`: 떼기 버튼 옆에 `Tooltip(message: '에셋 상세')` + `IconButton`(예: `FluentIcons.open_file` 또는 `navigate_external`) 추가. `assetId`가 비어 있거나 `_isWorking`이면 비활성.
2. `onPressed`에서 `context.read<AppCoordinator>().didTapOpenAssetDetail(row.assetId)` 호출. `provider` / `AppCoordinator` import 추가.
3. 헤더 오른쪽 빈 `SizedBox` 너비를 버튼 두 개에 맞게 늘린다(행과 정렬).
4. 행 더블클릭·행 전체 탭은 넣지 않는다.

## 유지할 것
- 패스 변경·떼기·올리기·후처리 상태 열
- Coordinator 라우팅 구현 자체

## 이번 작업에서 만들지 않음
- 첨부 탭 인라인 RetryPostprocess
- 에셋 목록 쪽 네비 변경

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
