# 로그인·세션·작성자 1차 (1-C + 2-B)

## 목표
하드코드 로그인(`geosoft`/`user`)을 `AuthService` 세션으로 바꾸고, 앱 기동·RPC 401 시 로그인 화면으로 돌린다. 공사·작업자·장비·작업·파일 상세에 `created_by`/`updated_by` 표시명을 넣는다. `account.manage`·계정/역할/토큰 화면·전면 권한 숨김은 이번엔 만들지 않고, 끝나면 남은 작업 문서로 남긴다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md` (가이드라인 저장소는 워킹 트리 밖에서 읽기만)
3. `docs/2026-11-23/README.md` §2·§3, `protos/mediatag/auth/v1/auth.proto`
4. `lib/main.dart`(`_AuthGate`), `lib/src/presentation/features/auth/*`, `lib/src/data/repositories/hardcoded_auth_repository.dart`, `lib/src/data/datasources/remote/media_tag_data_source.dart`, `lib/src/data/datasources/remote/dashboard_http_client_web.dart`, lookup 상세·매핑 repos

## 현재 상태
- 로그인: `HardcodedAuthRepository` + prefs `auth.session.user_id`만. `AuthService` 미호출.
- `MediaTagDataSource`: Work/Asset/…만 연결. Auth 클라이언트·Bearer·401 interceptor 없음. Web HTTP는 `credentials: "same-origin"` 기본.
- 셸: ID 표시 + 로컬 `signOut`. 계정/역할/토큰 메뉴 없음.
- 멀티모달: `AuthUser.canAccessVideoMultimodal`(`geosoft`만 true).
- 작성자: proto/생성 코드에만 있고 domain·UI 미표시.

## 바꿀 것

### A. 세션 · AuthService
1. `MediaTagDataSource`에 `AuthServiceClient` 추가. Transport에 interceptor 2개:
   - 저장된 세션 토큰이 있으면 `Authorization: Bearer <token>` 부착
   - 응답 `ConnectException` `Code.unauthenticated` → 세션 클리어 콜백(로그인 화면). Login RPC 자체 401은 콜백하지 않음
2. Web: `dashboard_http_client_web.dart`에서 `createHttpClient(credentials: "include")` (교차 출처 쿠키). IO는 기존 유지 + Bearer로 보완.
3. `HardcodedAuthRepository` 제거·교체. 새 remote auth repository가:
   - `signIn` → `AuthService.Login` → Account + token 저장(prefs: login_name + token)
   - `restoreSession` → token 있으면 Bearer로 `GetCurrentAccount`; 성공 시 Account로 `AuthUser` 구성, 401이면 clear
   - `signOut` → `Logout` 시도 후 local clear
4. `AuthUser`를 서버 Account에 맞게 확장: `accountId`, `loginName`, `displayName`, `permissions`. `userId` getter는 `loginName` 유지(셸 표시).
5. `canAccessVideoMultimodal`: **최소 매핑** `permissions.contains('timeline.edit')`. 그 외 편집/삭제 버튼 숨김은 하지 않음.
6. `hasAccountManage`(`account.manage`) getter만 세션에 둔다. **메뉴·관리 화면은 추가하지 않음**(2-B 준비만).
7. `LoginViewModel`/`AuthSessionViewModel` 오류 문구: 아이디·비번 구분 없이 동일 실패 메시지, ResourceExhausted(5회 잠금) 안내. `geosoft`/`user` 하드코드 문구·비밀번호 상수 제거.
8. 셸 `_AuthSessionActions`: `displayName`(없으면 loginName) + 로그아웃. 비밀번호 변경 UI는 이번 범위 밖.

### B. 작성자 표시
1. domain에 작은 `AuthorRef`(accountId, displayName) 또는 nullable `createdByDisplayName`/`updatedByDisplayName` 추가 — 기존 엔티티에 필드만 붙인다(새 추상 계층 금지).
2. 매핑: `remote_project_lookup_repository` / `project_filter_mapping`, `remote_worker_lookup_repository`, `remote_equipment_lookup_repository`, `remote_job_admin_repository`, `remote_asset_lookup_repository`에서 `hasCreatedBy`/`hasUpdatedBy` → displayName.
3. UI: 공사·작업자·장비 상세 `PassContextBar.entries`에 `작성자`/`수정자` 행. 작업 `job_info_tab`·파일 `LookupDetailKvGrid`에 동일. 값이 비면 **「시스템」** (사람 아님/로그인 전 행).
4. Pass·Clip·Comment·Timeline 등은 이번 표시 대상에서 제외(남은 작업).

### C. 구현 후 남은 작업 문서
`docs/2026-11-23/로그인_권한_남은작업.md`에 체크리스트로 정리:
- `ChangePassword` UI
- 계정·역할·서버 연동 토큰 관리 화면 + `account.manage`로 셸 메뉴 노출
- `work.edit`/`asset.edit`/`delete`/… 권한별 버튼·액션 숨김
- Pass/Clip 등 나머지 엔티티 작성자 표시
- 교차 출처 개발용 동일 출처 프록시(영상 태그 Bearer 불가) 안내·적용
- 서버 로그인 검사 켜는 날 맞추기·하드코드 잔여 점검

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
