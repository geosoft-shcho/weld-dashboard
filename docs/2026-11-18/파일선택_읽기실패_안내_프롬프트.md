# 파일 선택 읽기 실패 안내

## 목표
웹에서 파일 고른 직후 `arrayBuffer`가 실패해도 **파일 단위로** 처리한다. 읽힌 파일은 업로드 목록에 넣고, 못 읽은 파일만 한국어 안내를 보여 준다. Chrome `NotReadableError` 원문을 그대로 노출하지 않는다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md` (가이드라인은 워킹 트리 밖 읽기만)
3. `lib/src/data/datasources/asset_file_picker_web.dart` / stub
4. `lib/src/domain/entities/camera_recording.dart`
5. `lib/src/domain/repositories/asset_upload_repository.dart` / `upload_asset_use_case.dart` / `remote_asset_upload_repository.dart`
6. `lib/src/presentation/features/asset_lookup/asset_upload_dialog.dart` `_didTapPickFiles`
7. 호출·페이크: asset_lookup / job_lookup VM, camera_recording_dialog, test fakes

## 현재 상태
- 피커: `Future.wait`로 전 파일 `arrayBuffer` → 하나 실패 시 전체 `completeError`.
- 다이얼로그: `catch`에서 `error.toString()`을 `_error`에 표시.
- 확장자 검사는 선택 시점에 없음.

## 바꿀 것
1. **결과 타입** — `camera_recording.dart`에 `AssetPickResult { files, warnings }` 추가(새 파일·추상 계층 없음).
2. **피커** — `pickAssetFiles`가 `AssetPickResult` 반환. 파일마다 try/catch로 `arrayBuffer`. 성공→`files`, 실패→`warnings`에  
   `'{이름}: 파일을 읽지 못했습니다. 클라우드(미다운로드)·다른 앱 사용 중·권한을 확인한 뒤 로컬에 복사해 다시 고르세요.'`  
   (`NotReadable`/`could not be read` 포함 시). 그 외 실패는 `'{이름}: 파일을 열지 못했습니다.'`. 취소·빈 선택은 빈 `files`·빈 `warnings`. stub도 동일 시그니처.
3. **계층** — `pickFiles` / `pickUploadFiles`가 `AssetPickResult` 반환하도록 repository·use case·VM·다이얼로그 `pickFiles` 콜백·페이크를 맞춤. `pickAssetFile`/`pickFile`은 `result.files` 첫 요소(없으면 null); 단일 선택 실패 warnings는 호출부가 없으므로 피커에서 실패만 있으면 `AssetUploadException`(또는 기존 업로드 예외)으로 한 줄 throw해 단일 API도 안내 가능 — **다중 선택 다이얼로그만 warnings UI**, 단일 `pickFile`은 throw로 메시지 전달.
4. **다이얼로그** — `_didTapPickFiles`: `files`로 행 추가, `warnings`가 있으면 `_error`에 `join('\n')`. 전부 실패여도 예외로 죽이지 않고 warnings만 표시(행 추가 없음).
5. **테스트 페이크** — `pickFiles` 시그니처만 `AssetPickResult`로 맞춤(동작 변경 최소).

## 유지할 것
- 업로드·TUS·형식 표 검증, `accept` 미설정
- `initialFiles`로 여는 카메라 녹화 경로(이미 메모리 bytes)

## 이번 작업에서 만들지 않음
- 자동 재시도, `accept` 필터, 확장자 거절 메시지, 새 UseCase/피커 추상 계층

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
