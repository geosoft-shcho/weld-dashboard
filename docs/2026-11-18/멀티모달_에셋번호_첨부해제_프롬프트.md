# 멀티모달 에셋 번호 열 + 첨부 해제

## 목표
비디오 멀티모달 에셋 사이드 패널에서 자료 번호를 보고 검색·찾을 수 있게 하고, 클립을 지운 뒤 같은 패널에서 첨부를 해제할 수 있게 한다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md` (가이드라인 저장소는 워킹 트리 밖에서 읽기만)
3. `lib/src/presentation/features/video_multimodal/widgets/assets_side_body.dart`
4. `lib/src/presentation/features/video_multimodal/video_multimodal_view_model.dart`
5. `lib/src/presentation/core/di/locator.dart` (`VideoMultimodalViewModel` 등록)
6. `lib/src/presentation/features/job_lookup/widgets/job_attachment_tab.dart` (첨부 해제 확인·실패 문구)
7. `lib/src/domain/use_cases/job_admin_use_case.dart` (`detachAsset`)
8. `protos/mediatag/asset/v1/asset.proto` (`ListAssetsRequest.query` 숫자면 asset 번호 매칭, `DetachAsset`)

## 현재 상태
- `assets_side_body.dart`: 헤더/행이 점·이름·유형·길이. `attachment.attachmentId`가 assetId다.
- 검색: `didChangeAssetsSearch` → `ListAssets` `query`. 숫자면 그 번호 Asset도 매칭된다. 검색 API 변경은 필요 없다.
- 멀티모달 ViewModel에 `detachAsset` / `JobAdminUseCase`가 없다. Detach는 작업 상세 첨부 탭에만 있다.
- `SidePanelDataCell`은 텍스트/점만 지원한다.

## 바꿀 것
1. `assets_side_body.dart`
   - 헤더에 **번호**·**첨부해제** 열 추가. 값은 `attachment.attachmentId`. flex는 점 1 / 번호 3 / 이름 4 / 유형 3 / 길이 2 / 첨부해제 2. 해제 버튼은 `SidePanelDataCell.child`로 같은 열 안에 둔다. 에셋 패널 폭은 번호·유형(배지)이 잘리지 않을 정도로 둔다.
   - 검색 hint: `검색…` → `번호·이름 검색…`
   - 각 행 **첨부해제** 열에 아이콘 버튼.
   - 해제 전 확인: 제목 `첨부를 해제할까요?`, 본문 `이 작업에서만 떼어냅니다. 에셋 자체는 남습니다.` (첨부 탭과 동일).
   - 실패: 클립 FK(`clip_job_id_source_asset_id_fkey`)면 「이 자료를 쓰는 타임라인 클립을 먼저 지우세요」(이미 타임라인이므로 이동 버튼 없음). 코멘트/기타 `failed_precondition`은 첨부 탭과 같은 사용자 말. 성공 시 에셋 목록 재로드.
2. `video_multimodal_view_model.dart` + `locator.dart`
   - 기존 `JobAdminUseCase`를 주입하고 `detachAsset(assetId)` → 성공 시 현재 에셋 페이지를 다시 로드한다.
3. 테스트가 ViewModel 생성자를 직접 만들면 `jobAdminUseCase` mock/스텁을 맞춘다(깨지는 곳만).

## 유지할 것
- ListAssets 검색·페이지네이션·드래그로 클립 놓기
- 첨부 탭의 Detach·실패 시 타임라인 이동 UX
- DeleteClip 기존 UX

## 이번 작업에서 만들지 않음
- 일괄 클립 삭제 후 Detach
- assetId 타임라인 자동 필터/하이라이트
- `SidePanelDataCell` 커스텀 위젯 팩토리 확장
- DeleteAsset

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
