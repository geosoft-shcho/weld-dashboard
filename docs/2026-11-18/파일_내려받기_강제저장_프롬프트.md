# 파일 내려받기 강제 저장

## 목표
파일 목록·상세의 **내려받기**가 CSV뿐 아니라 PDF·영상·이미지·기타도 **파일로 저장**되게 한다. 서버 `content_url`에는 `Content-Disposition: attachment`가 없고, 현재 `openBrowserUrl`이 `window.open`만 해서 브라우저가 CSV는 저장·나머지는 인라인으로 연다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md` (가이드라인은 워킹 트리 밖 읽기만)
3. `lib/src/presentation/core/browser_open_url_web.dart` / stub / export
4. `lib/src/presentation/features/asset_lookup/asset_lookup_screen.dart` (`onDownload` → `openBrowserUrl`)
5. `lib/src/presentation/features/asset_lookup/asset_lookup_detail_screen.dart` 내려받기 버튼
6. `lib/src/data/repositories/remote_asset_lookup_repository.dart` `_rowFrom`의 `contentUrl` 매핑
7. `protos/mediatag/asset/v1/asset.proto` (content_url / `/assets/{id}/content`)

## 현재 상태
- ListAssets는 csv·png·webm·pdf·xlsx 모두 `contentUrl`을 채운다. 버튼 비활성(`contentUrl.isEmpty`)이 종류별 원인이 아니다.
- 파일 HTTP 응답에 `Content-Disposition: attachment` 없음. `text/csv`는 저장, `video/webm`·`application/pdf`·`image/png`는 새 탭 미리보기.
- CORS `Access-Control-Allow-Origin: *` → 웹에서 fetch → blob 저장 가능.
- `/assets/{id}/content`는 `/files/...`로 302.

## 바꿀 것
1. **웹 내려받기 헬퍼** — 기존 conditional export에 `downloadBrowserUrl(url, {fileName})` 추가(또는 `openBrowserUrl`에 optional `fileName`/`forceDownload`). 웹: `fetch` → blob → object URL → `<a download=fileName>` click → revoke. 실패 시 기존처럼 `window.open`. stub는 UnsupportedError 유지. 새 파일·추상 계층 없이 기존 3파일만 확장.
2. **목록** — `asset_lookup_screen.dart`: 내려받기 시 URL + `row.fileName`(비면 `assetId`)로 강제 저장 호출.
3. **상세** — `asset_lookup_detail_screen.dart` 내려받기 동일. `asset_preview_pane`의 내려받기가 있으면 같이 맞춤.
4. **빈 contentUrl 보정** — `_rowFrom`에서 `contentUrl`이 비고 `assetId`가 있으면 `_mediaTag.resolveContentUrl('/assets/{assetId}/content')`로 채운다(프로토 계약).

## 유지할 것
- 목록 삭제·행 탭→상세·CatalogLookupTable API
- MediaTag Connect 조회 흐름, generated 코드 미수정
- `contentUrl`이 이미 absolute/relative일 때 `resolveContentUrl` 동작

## 이번 작업에서 만들지 않음
- 서버 Content-Disposition 변경, 일괄 내려받기, 네이티브(non-web) 파일 저장 UI, 진행률 표시, 새 UseCase/Repository 메서드

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
