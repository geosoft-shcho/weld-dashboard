# 첨부 해제 클립 참조 시 타임라인 유도

## 목표
작업 상세 첨부 탭에서 `DetachAsset`이 타임라인 클립 참조(`clip_job_id_source_asset_id_fkey`)로 실패하면, 서버 제약 이름을 그대로 보이지 않고 사용자 말로 안내한 뒤 **비디오 멀티모달(타임라인)로 이동**해 해당 자료 클립을 수동으로 지우고 돌아오게 한다. 일괄 「클립 지우고 첨부 해제」는 넣지 않는다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md` (가이드라인 저장소는 워킹 트리 밖에서 읽기만)
3. `lib/src/presentation/features/job_lookup/widgets/job_attachment_tab.dart` (`_didTapDetach`, 실패 다이얼로그)
4. `lib/src/presentation/navigation/app_coordinator.dart` (`didTapOpenVideoMultimodal`)
5. `lib/src/presentation/features/job_lookup/job_lookup_detail_screen.dart` (멀티모달 진입·권한)
6. `protos/mediatag/asset/v1/asset.proto` (`DetachAsset` FailedPrecondition: Clip·성적서 세트)
7. 계약 예: `사용 중: clip_job_id_source_asset_id_fkey` / 코멘트 녹화 / 성적서 매칭(제약 이름 다름)

## 현재 상태
- `_didTapDetach`: 확인 다이얼로그 후 `detachAsset` 호출. 실패 시 `ContentDialog` 제목「첨부를 해제할 수 없습니다」, 본문은 ConnectException `message`(또는 toString), **닫기만** 있다.
- 작업 상세 상단「비디오 멀티모달」은 `AppCoordinator.didTapOpenVideoMultimodal`로 연다. `AuthSessionViewModel.canAccessVideoMultimodal`이 false면 비활성이다.
- 타임라인에서 클립 삭제는 멀티모달 보드의 기존「클립 삭제」/`DeleteClip` 흐름이 있다.
- 클립을 남긴 채 첨부만 떼는 API는 없다. 서버가 Clip 생성 시 자동 첨부한다.

## 바꿀 것
1. `job_attachment_tab.dart`에서 `DetachAsset` 실패 다이얼로그를 원인별로 나눈다.
   - `ConnectException`이고 `code == failedPrecondition`이며 message에 `clip_job_id_source_asset_id_fkey`가 있으면 **클립 참조**로 본다.
   - 클립 참조 본문(사용자 말): 이 자료를 쓰는 타임라인 클립이 있어 첨부를 뗄 수 없다. 타임라인에서 해당 자료 클립을 지운 뒤 다시 첨부 해제를 누른다. 클립 삭제는 되돌릴 수 없다. 자료 번호(`assetId`)를 본문에 넣는다.
   - 클립 참조 액션: **닫기**, **타임라인으로 이동**(Filled). 이동은 `AppCoordinator.didTapOpenVideoMultimodal(context, jobId: _viewModel.jobId)`. 다이얼로그를 닫은 뒤 이동한다. 멀티모달 권한이 없으면 이동 버튼을 비활성하거나 숨긴다(상세 화면과 같은 권한 소스).
   - `failedPrecondition`이고 message에 코멘트/DeleteComment 안내가 있으면: 코멘트가 이 녹화를 쓰므로 코멘트를 먼저 지우라는 사용자 말 + 닫기만.
   - 그 밖의 `failedPrecondition`: 성적서 세트 매칭 등일 수 있으므로「이 자료를 쓰는 클립이나 성적서 매칭이 남아 있을 수 있다. 참조를 끊은 뒤 다시 해제하라」는 사용자 말 + 가능하면 원문 message 한 줄 + 닫기. 클립 FK가 아니면 타임라인 이동 버튼을 넣지 않는다.
   - 위가 아닌 실패는 기존처럼 제목「첨부를 해제할 수 없습니다」+ `_userFacingError` + 닫기.
2. 성공·확인 다이얼로그·올리기·붙이기·패스 변경 흐름은 그대로 둔다.

## 유지할 것
- `detachAsset` ViewModel / UseCase / Repository 호출
- 첨부 해제 전 확인 다이얼로그 문구
- 타임라인 쪽 클립 삭제 UX·API (멀티모달에 이미 있음). 이번 작업에서 타임라인에 asset 필터·하이라이트를 새로 만들지 않는다.
- DetachAsset / DeleteClip 서버 계약

## 이번 작업에서 만들지 않음
- 「클립 N개 지우고 첨부 해제」일괄 옵션·자동 DeleteClip 연쇄
- Detach 전 타임라인 사전 조회·건수 뱃지
- 타임라인 화면에서 assetId 필터/자동 선택
- 성적서 매칭 해제 화면 신설·딥링크
- 새 UseCase·예외 타입·전역 ConnectException 매퍼 파일
- DeleteAsset UX 변경

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
