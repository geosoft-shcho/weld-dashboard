# 에셋 삭제 실패 시 서버 메시지 사용

## 목표
`_assetWriteFailure`의 `FailedPrecondition`에서 하드코딩 문구만 쓰지 않고, 서버 `ConnectException.message`를 UI에 보이게 한다.

## 먼저 읽을 것
1. `lib/src/data/repositories/remote_asset_lookup_repository.dart` `_assetWriteFailure`
2. 참고: `lib/src/data/repositories/remote_trace_repository.dart` `error.message.trim()` 후 비면 기본 문구

## 현재 상태
- `failedPrecondition` → 항상 「작업에 붙어 있거나…」 고정.
- `default` → `ConnectException` 그대로 throw.

## 바꿀 것
1. `_assetWriteFailure`의 `failedPrecondition` 분기:
   - `final message = error.message.trim();`
   - `message.isEmpty`이면 기존 고정 안내 문구, 아니면 `message`로 `_WriteFailure` 생성.
2. `default`는 그대로 `return error` 유지.

## 유지할 것
- `_WriteFailure`·`deleteAsset`/`updateAsset` 호출부
- 상세 화면 catch에서 `'$e'` 표시

## 이번 작업에서 만들지 않음
- equipment/worker의 다른 `_WriteFailure` 문구, UI 문구 변경

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
