# 업로드 파이프라인 칸 점등 디버그 로그

## 목표
업로드·후처리 중 파이프라인 칸이 어떤 Trace 이벤트·상태로 켜지는지 콘솔에서 짧게 확인한다.

## 먼저 읽을 것
- `lib/src/presentation/features/collection_monitoring/pipeline_trace_view_model.dart`
- `lib/src/domain/entities/pipeline_trace_graph.dart` (`pipelineStageVisual`)
- `lib/src/domain/use_cases/upload_asset_queue_use_case.dart` (`_waitForTrace`)

## 현재 상태
- 칸 시각은 `lastEvent`/`events`/`status` → `pipelineStageVisual`/`pipelineNodeVisual`로 결정된다.
- 업로드 대기열은 `GetTrace` 상태 변경 시에만 `debugPrint`한다.
- 파이프라인 폴링 VM에는 칸 점등 로그가 없다.

## 바꿀 것
1. `upload_asset_queue_use_case.dart`: Trace 폴링 시 `lastEvent`·events 요약도 `kDebugMode`로 찍는다(간소).
2. `pipeline_trace_view_model.dart`: traces 시그니처가 바뀔 때 running/선택 Trace의 lastEvent·events와 non-idle 단계 칸을 `kDebugMode`로 찍는다(간소).

## 복잡한 코드 제거 및 금지
- 새 추상 계층·로거 클래스·플래그 UI·상태관리 도입 금지
- 프롬프트 범위 밖 리팩터·이름 정리 금지
- release에서도 항상 찍히는 로그 금지(`kDebugMode`만)

## 완료 확인
- `./scripts/agent_check.sh` 통과
- 디버그 빌드에서 업로드·폴링 시 `[upload]`/`[pipeline]` 로그로 이벤트·칸 상태를 볼 수 있다
- 로그는 짧고, 시그니처/상태가 바뀔 때만 남긴다
