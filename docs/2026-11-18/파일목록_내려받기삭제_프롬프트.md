# 파일 목록 내려받기·삭제

## 목표
`asset_lookup_screen.dart` 표에서 상태 열 오른쪽에 **내려받기·삭제**를 두고, 상세로 들어가지 않고도 실행한다. 삭제는 서버 메시지를 확인 다이얼로그에 보여 준다(사전 FE 가드 없음).

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md` (가이드라인은 워킹 트리 밖 읽기만)
3. `lib/src/presentation/core/widgets/catalog_lookup_table.dart`
4. `lib/src/presentation/features/asset_lookup/asset_lookup_screen.dart`
5. `lib/src/presentation/features/asset_lookup/asset_lookup_detail_screen.dart` 내려받기·삭제 확인 다이얼로그
6. `lib/src/presentation/features/asset_lookup/asset_lookup_view_model.dart` / locator 등록

## 현재 상태
- 목록은 String 셀만. 내려받기·삭제는 상세에만 있음.
- `AssetLookupRow.contentUrl`은 `_rowFrom`에서 채움.
- `AssetLookupViewModel`에 `DeleteAssetUseCase` 없음.

## 바꿀 것
1. `catalog_lookup_table.dart`: 선택 인자 `actionsHeader`, `actionsFlex`, `actionsBuilder`. null이면 기존과 동일. 행 탭은 텍스트 영역만.
2. `asset_lookup_view_model.dart` + locator: `DeleteAssetUseCase` 주입, `deleteAsset` 성공 후 `load()`.
3. `asset_lookup_screen.dart`: 액션 열에 내려받기·삭제. URL 없으면 내려받기 비활성. 삭제는 확인 다이얼로그 + 서버 메시지.

## 유지할 것
- 다른 조회 화면의 `CatalogLookupTable` 호출(인자 생략)
- 행 탭 → 상세 이동
- 상세 화면의 내려받기·지우기

## 이번 작업에서 만들지 않음
- 일괄 삭제, 새 공통 액션 위젯 파일, CatalogLookupTable을 Widget 셀 전체로 확장

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
