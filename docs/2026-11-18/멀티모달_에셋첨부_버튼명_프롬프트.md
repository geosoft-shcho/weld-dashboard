# 멀티모달 에셋 첨부 + 버튼명 통일

## 목표
멀티모달 에셋 패널에서 이미 있는 에셋 번호로 이 작업에 첨부할 수 있게 하고, 첨부 탭·멀티모달의 버튼·다이얼로그 문구를「에셋 첨부」로 맞춘다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md` (가이드라인 저장소는 워킹 트리 밖에서 읽기만)
3. `lib/src/presentation/features/job_lookup/widgets/job_attachment_tab.dart` (`_didTapAttach`)
4. `lib/src/presentation/features/video_multimodal/widgets/assets_side_body.dart`
5. `lib/src/presentation/features/video_multimodal/video_multimodal_view_model.dart`
6. `lib/src/presentation/core/di/locator.dart`
7. `lib/src/domain/use_cases/job_admin_use_case.dart` (`attachAsset`)
8. `lib/src/domain/use_cases/list_job_passes_use_case.dart`
9. `protos/mediatag/asset/v1/asset.proto` (`AttachAsset`: 타임라인에 놓지 않고 작업 자료로만 둘 때·패스 고칠 때)

## 현재 상태
- 첨부 탭: 커맨드바 `에셋 붙이기(첨부만)`, 다이얼로그 제목 `에셋 붙이기`, 확인 `붙이기`. 에셋 번호·패스 후 `attachAsset`.
- 멀티모달 에셋 패널: 검색·초기화·첨부 해제만 있다. Attach 버튼 없음. ViewModel에 `attachAsset`·패스 목록 없음. `JobAdminUseCase`는 Detach용으로만 주입돼 있다.
- Clip을 만들면 서버가 자동 첨부한다. `AttachAsset`은 PDF 등 타임라인에 안 올리는 자료와, 드래그 전에 목록에 미리 붙일 때 쓴다.

## 바꿀 것
1. `job_attachment_tab.dart`
   - 커맨드바 `에셋 붙이기(첨부만)` → `에셋 첨부`
   - 다이얼로그 제목 `에셋 붙이기` → `에셋 첨부`, 확인 버튼 `붙이기` → `첨부`
   - PDF·성적서 안내 문구·API·패스 콤보는 유지
2. `assets_side_body.dart`
   - 헤더에 `에셋 첨부` 버튼(초기화 옆)
   - 다이얼로그: 에셋 번호*, 패스(작업 공용 / N패스), 본문「문서 PDF를 첨부하면 첨부만 됩니다. 성적서 세트에는 이어지지 않습니다.」확인 `첨부`
   - 숫자 검증 실패·API 실패는 메시지 다이얼로그. 성공 시 목록 재로드
3. `video_multimodal_view_model.dart` + `locator.dart`
   - `ListJobPassesUseCase` 주입. 패스 목록은 첨부 다이얼로그 전에 로드(또는 타임라인 open 시 한 번). getter로 UI에 넘긴다
   - `didTapAttachAsset(assetId, passId)` → `_jobAdminUseCase.attachAsset` → `_loadAssetsPage`
4. ViewModel을 직접 만드는 테스트에 `listJobPassesUseCase` 스텁을 맞춘다(깨지는 곳만)

## 유지할 것
- 첨부 탭「에셋 올리기」업로드 흐름
- 멀티모달 첨부 해제·검색·드래그 클립
- Detach / Attach 서버 계약

## 이번 작업에서 만들지 않음
- 멀티모달 파일 업로드(올리기)
- 첨부 직후 자동 CreateClip
- 첨부 탭·멀티모달 공용 다이얼로그 위젯 파일
- 새 UseCase·추상 계층

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
