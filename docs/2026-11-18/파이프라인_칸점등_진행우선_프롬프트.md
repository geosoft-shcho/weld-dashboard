# 파이프라인 칸 점등 진행 우선

## 목표
미선택 집계에서 같은 단계에 실패 Trace와 진행 Trace가 같이 있을 때, 로그·실제 업로드 진행(running/queued)이 칸에 보이도록 한다. `register.duplicates` 이벤트도 등록 칸 세부에 반영한다.

## 먼저 읽을 것
- `lib/src/domain/entities/pipeline_trace_graph.dart`
- `test/pipeline_trace_graph_test.dart`
- 터미널 `[pipeline]` 로그(id=76 `register.stored` running vs `cells … register:failed`)

## 현재 상태
- 미선택 `pipelineStageVisual` / `pipelineNodeVisual`은 실패 > 진행 > 완료.
- 옛 register 실패가 있으면 새 업로드가 register 진행 중이어도 칸이 `failed`로만 보인다.
- `register.duplicates`는 이벤트에 있으나 `pipelineStages` register `nodeIds`에 없다.

## 바꿀 것
1. `pipeline_trace_graph.dart` 미선택 집계 우선순위를 **진행(queued/running/active) > 실패 > 완료 > idle** 로 바꾼다(단계·세부 노드 동일).
2. register `nodeIds`·라벨·아이콘에 `register.duplicates`를 추가한다.
3. `test/pipeline_trace_graph_test.dart`에 “같은 단계 실패+진행 → 진행” 케이스를 넣고, 기존 실패-only 케이스는 유지한다.

## 복잡한 코드 제거 및 금지
- 새 추상 계층·상태관리·디자인 시스템 도입 금지
- 선택(selected) 여정 visual 규칙 변경 금지(집계만)
- 프롬프트 밖 리팩터·디버그 로그 대정리 금지

## 완료 확인
- `./scripts/agent_check.sh test/pipeline_trace_graph_test.dart` 통과
- 같은 단계에 failed+running이면 칸/점이 running(또는 queued)
- 실패만 있으면 기존처럼 failed
- `register.duplicates`가 등록 단계 세부 목록에 있다
