# 에셋 삭제 FE 사전 검사 제거

## 목표
파일 상세 「지우기」에서 `childCount`·`jobs`로 막는 사전 다이얼로그를 없앤다. 바로 확인 다이얼로그를 열고, 실패 시 서버(또는 repository가 매핑한) 메시지를 빨간 글씨로 보여 준다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `lib/src/presentation/features/asset_lookup/asset_lookup_detail_screen.dart` `_didTapDelete`
3. `lib/src/data/repositories/remote_asset_lookup_repository.dart` `deleteAsset` / `_assetWriteFailure`

## 현재 상태
- FE가 `파생의 부모`·`작업 첨부`면 「이 파일은 지울 수 없습니다」로 return.
- 그 외에는 확인 다이얼로그에서 `deleteAsset()` 호출, catch 시 `error = '$e'` 표시.
- repository는 `FailedPrecondition`을 「작업에 붙어 있거나…」 `_WriteFailure`로 매핑.

## 바꿀 것
1. `_didTapDelete`에서 `reasons` 구성·사전 `ContentDialog`·early `return` 블록만 삭제.
2. 확인 다이얼로그 → `deleteAsset` → catch에 `error` 표시하는 기존 흐름은 유지.

## 유지할 것
- 확인 문구·취소/지우기·성공 시 `didTapBackFromLookupDetail`
- repository `deleteAsset`·`_assetWriteFailure` 매핑

## 이번 작업에서 만들지 않음
- repository 문구 변경, detach/파생 UI, 다른 화면 삭제 가드 정리

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
