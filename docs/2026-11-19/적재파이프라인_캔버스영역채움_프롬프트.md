# 적재 파이프라인 캔버스 영역 채움

## 목표
DataFlow식 파이프라인 캔버스가 **초기 표시에서 스크롤/팬 없이** 탭의 그래프 가용 영역을 채우고, 전체 골격이 한 화면에 맞게 보이도록 한다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md` (가이드라인 저장소는 워킹 트리 밖에서 읽기만)
3. `lib/src/presentation/features/collection_monitoring/widgets/pipeline_trace_graph_view.dart`
4. `lib/src/presentation/features/collection_monitoring/widgets/pipeline_trace_tab_body.dart`
5. 없음

## 현재 상태
- `PipelineTraceTabBody`가 그래프를 `SingleChildScrollView`로 감싸 세로 스크롤이 생긴다.
- `PipelineTraceGraphView`는 고정 높이(280)와 고정 논리 캔버스 크기라 영역을 채우지 못하고, `InteractiveViewer(constrained: false)`로 초기에도 팬/스크롤이 필요하다.

## 바꿀 것
1. `pipeline_trace_tab_body.dart`: Expanded 안 `SingleChildScrollView` 제거, `PipelineTraceGraphView`가 남은 높이를 받도록 한다.
2. `pipeline_trace_graph_view.dart`: 요약 아래 캔버스를 `Expanded` + `LayoutBuilder`로 채운다. 논리 좌표를 viewport에 `BoxFit.contain` 비율로 스케일·중앙 배치해 **초기에는 스크롤 없이 전체가 보이게** 한다. 줌(InteractiveViewer)은 유지하되 초기 transform은 identity(맞춰 그린 상태).

## 유지할 것
- path 활성 연결 규칙, 노드 visual, 칩·목록·폴링

## 이번 작업에서 만들지 않음
- 도메인/테스트 로직 변경(레이아웃만이면 테스트 불변)
- DataFlow 패키지 이식

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
