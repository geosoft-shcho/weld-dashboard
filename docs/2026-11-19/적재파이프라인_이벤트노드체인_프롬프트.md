# 적재 파이프라인 이벤트 노드 체인

## 목표
적재 파이프라인 탭 그래프를 A안(가로 축 + 목록) 안에서 **이벤트(`stage.step`) 하나 = 노드 하나**로 바꾸고, DataFlow처럼 **골격 연결선 · path 강조 · 활성 visual · live 구간 흐름 입자**가 보이게 한다. 단계 큰 원은 없애고 단계 밴드/헤더만 둔다.

## 확정 (설계기획안 §13 권장)

1. 배치: **7.1 가로 이벤트 체인**
2. 단계 큰 원: **제거, 단계 밴드/헤더만**
3. 미선택 집계 강조: **합산 non-idle 인접 골격 간선** (현행 단계 합산과 동일 취지). 선택은 `pipelinePathNodeIds` path
4. done 분기: **`done.searchable` / `done.stored` 둘 다 표시, 강조는 path에 있는 쪽만**
5. 가로 스크롤: **그래프 영역만** 허용. 목록 세로 영역 유지

근거: `docs/2026-11-19/적재파이프라인_DataFlowDiagram_구조참고_설계기획안.md`

## 현재 상태
- `pipeline_trace_graph_view.dart`: 단계 큰 원 + 아래 세부 칩, 연결선은 `_StageConnector`(단계↔단계)만.
- `pipeline_trace_graph.dart`: `pipelineNodeVisual` · `pipelinePathNodeIds` · `pipelineHighlightStageIds` · `pipelineStages` 있음. 이벤트 인접 엣지 목록 헬퍼는 없음.
- `pipeline_trace_tab_body.dart`: 칩 + Expanded(그래프 SingleChildScrollView) + 목록. 골격 유지.

## 바꿀 것
1. `pipeline_trace_graph.dart`에 이벤트 골격 인접 엣지·강조 엣지 헬퍼를 최소로 추가한다.
   - 골격: `visibleStages`의 nodeIds를 단계 순·단계 안 순으로 펼친 뒤 인접 쌍.
   - 선택 시 강조: `pipelinePathNodeIds(selected)`에서 **골격에 존재하는 인접(또는 path 순서상 연속) 쌍**.
   - 미선택 강조: 양끝 노드 visual이 둘 다 idle이 아닌 골격 인접 쌍(합산).
   - 흐름(live) 대상: 강조 엣지 중 양끝 중 하나 이상이 `pipelineNodeIsLive`.
2. `pipeline_trace_graph_view.dart`를 가로 이벤트 노드 체인으로 재구성한다.
   - 상단 `_LiveStatusSummary` 유지.
   - 단계별 밴드/헤더(라벨·건수) + 그 아래(또는 같은 가로줄에) 이벤트 노드(원+짧은 라벨+상태 배지).
   - 노드 사이 CustomPaint 연결: 가이드(흐림) / 강조 / live 입자.
   - 단계 큰 원·세로 세부 칩 스택·단계-only 커넥터 제거.
   - 그래프 가로 넘침 시 그래프만 가로 스크롤.
   - 노드 탭 → 해당 event에 가까운 Trace 선택(현행 `_selectNear`와 동일 취지).
3. `PipelineNodeVisual` 7종·AppTheme·Fluent 아이콘 매핑 유지. bool on/off로 축소하지 않는다.
4. `test/pipeline_trace_graph_test.dart`에 골격 엣지·선택 path 강조·미선택 합산 강조 기대를 보강한다.
5. `pipeline_trace_tab_body.dart`는 칩+그래프+목록 역할을 유지한다. 그래프 위젯 API가 같으면 최소 수정.

## 유지할 것
- ListTraces/GetTrace 폴링, ViewModel, 단계 칩, 목록, 큐 병목 패널
- tool/embed는 데이터 있을 때만 `visibleStages`
- collect 하드코딩 선행, evidence-only skipped 규칙
- proto/API 변경 없음

## 이번 작업에서 만들지 않음
- DataFlowDiagram 위젯/패키지 이식, 줌 캔버스, 그룹 범례, 체인 FAB
- 새 상태관리·디자인 시스템·카드 UI
- 서버 그래프 API, GetQueue 재도입
- notification-mobile-app 수정

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
