# (2026-11-19) 적재 파이프라인 — 이벤트 노드 × DataFlow 문법 가능 여부

| 항목 | 내용 |

| 이번 초점 | **각 Trace 이벤트(`stage.step`)를 그래프 노드로 보고**, DataFlow처럼 **노드 · 연결선 · 활성 상태 · 흐름**으로 그릴 수 있는지 |

---

## 1. 문제 정의

A안은 “한 파이프라인 = 왼쪽→오른쪽”을 유지한다.  
다만 현재 구현은 **단계를 1급 노드**로 두고 이벤트는 단계 아래 라벨이다. 연결선·흐름 입자도 **단계↔단계**에만 있다.

요청은 다음이다.

> A안 축은 유지하되, **이벤트 하나 = 노드 하나**로 보고  
> DataFlowDiagram과 같이 **노드 · 연결선 · 활성 상태 · 흐름**으로 구현 가능한가?

즉 “단계 원 + 세부 칩”이 아니라 **이벤트가 본선 그래프의 정점**이 되는지가 핵심이다.

---

## 2. 목표 / 비목표

### 목표

- 이벤트 노드 모델로 DataFlow 4요소(노드·연결선·활성·흐름)를 옮길 수 있는지 **가능 / 조건 / 불가**를 판정한다.
- A안 원칙(한 가로 축, 다건 복제 금지, 목록 분리)을 깨지 않는 **레이아웃·엣지 규칙**을 제안한다.
- 구현 착수 전 확정할 질문을 남긴다.

### 비목표

- 코드 구현, DataFlow 위젯 복사, 패키지 공유
- proto / TraceService 변경 (서버에 그래프·노드를 두지 않음 — 현행 계약 유지)
- Modbus 체인·그룹 FAB·장비 SVG·줌 캔버스를 본화면 기본으로 도입
- 새 디자인 시스템·카드 UI

## 3. 전제: A안 + 이벤트=노드

| A안 원칙 (유지) | 이번 해석 (변경) |
|-----------------|------------------|
| 단계는 왼쪽→오른쪽 한 축 | 단계는 **구간(레인/묶음)** 이고, **정점은 이벤트 노드** |
| 다건은 그래프 복제하지 않음 | 동일. 한 골격 + 선택/집계 visual |
| 아래는 여정 목록 | 동일 (`PipelineTraceTabBody` 골격) |
| 연결선 = 단계 사이만 (원 권장안 §3.3) | **재검토:** 이벤트↔이벤트 본선으로 승격 |

원 권장안의 “세부끼리는 점만 / 세로 스택 금지”는 **이벤트=노드**와 충돌한다.  
이번 문서는 그 조항을 **이벤트 노드 그래프**로 바꿔 가능 여부를 다시 본다. 단계 큰 원은 필수가 아니다(헤더·배경 묶음으로만 둬도 됨).

## 4. 노드 집합 (이벤트 = 노드)

골격은 `pipelineStages`의 `nodeIds`다. (tool/embed는 데이터 있을 때만 표시 — 현행 `visibleStages`)

```text
collect.field → collect.capture
  → receive.started → receive.screened → receive.done
  → register.stored → register.asset → register.attached → register.duplicates
  → postprocess.run → props → duration → report → normalize → waveform → placed
  → [tool.run] → [embed.done]
  → done.searchable | done.stored
```

| 구분 | 대략 개수 | 비고 |
|------|-----------|------|
| 고정 골격 | 최대 ~19 | postprocess 7개가 가장  dens함 |
| 선택 표시 | tool / embed | 터치한 Trace가 있을 때만 |
| 분기 | `done.searchable` vs `done.stored` | 동시에 한 여정에 하나만 의미 있음 |
| 생략·스킵 | postprocess 일부, tool | 이벤트 증거 없으면 idle/skipped |

DataFlow의 `FlowNode.id` ↔ Trace의 `event.name` (`receive.started` 등).  
서버 그래프 API는 없다. **화면이 골격 위에 visual을 얹는다** (proto와 동일).

## 5. DataFlow 4요소 ↔ Trace 매핑

| DataFlow | Trace 이벤트 노드안 | 가능? |
|----------|---------------------|-------|
| **노드** `FlowNode` | 이벤트 1개 = 원/아이콘+라벨. 위치는 가로(단계 구간)×세로(단계 안 순서) 또는 한 줄 가로 | **가능** |
| **연결선** `FlowConnection` | 골격 인접쌍 + (선택 시) `pipelinePathNodeIds`가 거친 쌍만 강조 | **가능** (규칙 필요) |
| **활성 상태** `nodeStatus: bool` | `pipelineNodeVisual` 7종으로 대체 (축소하지 않음) | **가능** (더 풍부) |
| **흐름** 연결선 입자·펄스 | `active`/`running`/`queued` 노드에 인접한 강조 엣지에만 입자 | **가능** |

위젯 파일(`DataFlowDiagram`) 이식은 불필요. **문법만** 가져오면 된다.

## 6. 연결선 규칙 (구현 가능의 핵심)

이벤트 노드로 올리면 “모든 인접 이벤트를 항상 잇는다”와 “거친 경로만 잇는다”를 나눠야 한다.

### 6.1 골격 엣지 (가이드)

단계 안·단계 경계의 **정의 순서**로 인접 쌍을 잇는다.

예:

- `receive.started → screened → done`
- `receive.done → register.stored`
- `register.duplicates → postprocess.run`
- `postprocess.placed → tool.run` (tool 표시 시) 또는 `→ embed.done` / `→ done.*`

가이드선은 항상 흐리게. DataFlow의 회색 비활성 연결과 같은 역할.

### 6.2 강조 엣지 (실제 연결·흐름)

| 모드 | 강조 경로 | 흐름 입자 |
|------|-----------|-----------|
| 여정 선택 | `pipelinePathNodeIds(selected)`를 순서대로 이은 간선 | `last_event`에 닿는 간선(또는 live visual 노드 인접)만 |
| 미선택 집계 | visibleTraces 합산으로 non-idle인 인접 골격 간선, 또는 RUNNING 대표 1건 경로 | live visual이 있는 간선만 |

**거친 적 없는 간선에 흐름 애니를 돌리지 않는다.** (DataFlow가 비활성 체인을 회색으로 두는 것과 동일)

### 6.3 분기·스킵

| 케이스 | 규칙 |
|--------|------|
| `done.searchable` / `done.stored` | 골격은 둘 다 두되, 강조는 실제 path에 있는 쪽만 |
| tool / embed 미터치 | 노드 `skipped` 또는 단계 숨김(현행). 강조 경로에서 제외 |
| postprocess 일부 skipped | path에 없으면 강조 선 생략. 골격 가이드만 |
| 실패로 중단 | path 마지막 = `last_event`. 그 앞만 강조, 실패 노드 `failed` |

이 규칙이면 **이벤트 단위 연결상태**를 DataFlow처럼 “이어짐 / 안 이어짐 / 지금 흐름”으로 말할 수 있다.

## 7. 레이아웃 (A안 안에서의 배치)

절대 Offset 자유 배치(DataFlow 기본)는 A안의 “스크롤 최소·한 축”과 싸운다.  
이벤트=노드여도 **배치 방식은 Flex/격자**로 두는 편이 맞다.

### 7.1 권장 배치 — A-이벤트 가로 체인

```text
┌─ 단계 구간 라벨(받기 | 등록 | 후처리 | …) — 정점 아님, 묶음 헤더 ─────────┐
│  ○──○──○────○──○──○──○────○──○──…──○────○────○────○──○               │
│  started screened done  stored …        run  props … placed  embed  done │
│        ▲ 강조 실선+입자 = 거친·활성 구간                                   │
└──────────────────────────────────────────────────────────────────────────┘
┌─ 여정 목록 … ────────────────────────────────────────────────────────────┘
```

- **모든 이벤트가 같은 무게의 노드**(원+짧은 라벨). 단계 큰 원은 제거하거나 배경 밴드만.
- 단계 경계는 헤더 또는 배경 구분으로만 표시 (ProtocolGroup 배경 밴드와 유사, 필터 FAB는 불필요).
- 가로가 부족하면: (1) 단계 칩으로 구간 필터, (2) 해당 단계 구간만 확대, (3) 가로 스크롤 **그래프 영역만**.  
  → A안의 “본문 스크롤 최소”는 **목록은 고정, 그래프만 필요 시 가로 스크롤**로 완화.

### 7.2 대안 배치 — 단계 열 안 세로 노드 체인

```text
  받기        등록         후처리
  ○ started   ○ stored    ○ run
  │           │           │
  ○ screened  ○ asset     ○ props
  │           │           │
  ○ done ──── ○ … ─────── ○ …
```

- 열 안 세로 연결 + 열 사이 `done → stored` 횡단 연결.
- 현행 `_StageColumn`과 형태가 가깝지만, **칩이 아니라 노드+선**이 된다.
- 후처리 7단에서 세로 길이·한눈 가독성이 나빠짐. **가능하나 A안 “한 흐름” 가독성은 7.1이 낫다.**

### 7.3 기각 — DataFlow 자유 2D + InteractiveViewer 본화면

이벤트 수가 ~20이고 토폴로지가 거의 선형이라 줌 캔버스는 과설계.  
장비 type SVG·체인 FAB도 Trace와 무관.

## 8. 활성 상태 · 흐름 (이벤트 단위)

이미 도메인에 `pipelineNodeVisual` / `pipelinePathNodeIds` / `pipelineNodeIsLive`가 있다.  
**새 상태 모델은 거의 불필요.** UI가 이벤트 노드에 붙이면 된다.

| visual | 노드 | 연결선(인접 강조 시) |
|--------|------|----------------------|
| idle | 흐림 | 가이드만 |
| done | 채움·체크 | 강조 실선(지난 구간) |
| active / running | 링·펄스 | **입자 흐름** |
| queued | 경고색·펄스 | 입자 또는 느린 점선 |
| failed | 에러색 | 그 노드에서 경로 종료 |
| skipped | 흐린 점선 테두리 | 강조 경로에서 제외 |

집계(미선택) 시 한 노드에 여러 Trace가 겹치면 **현행과 동일 우선순위**(queued > running > failed > done).  
다건을 노드마다 여러 색으로 쌓지 않는다 (A안 §2).

## 9. 탭 구조 (유지 / 교체)

```text
PipelineTraceTabBody          ← 유지
├─ PipelineStageChips         ← 유지 (구간 필터·건수)
├─ [그래프 영역]              ← 교체 대상
│    현행: PipelineTraceGraphView (단계 원 + 세부 칩 + 단계 커넥터)
│    To-Be: 이벤트 노드 체인 + 이벤트 간 연결선·흐름
├─ PipelineTraceList          ← 유지
└─ 큐 병목 등                 ← 유지
```

ViewModel·폴링·선택 API는 그대로.  
그래프만 “단계 스테퍼” → “이벤트 노드 다이어그램”으로 바꾼다.

데이터 조립(개념):

```text
nodes[]  = visibleStages.expand(nodeIds)  → id, label, visual, stageId
edges[]  = 골격 인접쌍
activeEdges[] = path 간선 ∩ (선택 또는 집계 규칙)
flowEdgeIds = activeEdges 중 live 끝점 포함
```

CustomPaint 한 번으로 선+입자를 그려도 되고, 노드만 위젯·선만 Painter여도 된다.  
DataFlow의 SVG ConnectionRenderer 복제는 필수가 아니다.

## 10. 가능 여부 판정

### 10.1 결론

| 질문 | 판정 |
|------|------|
| A안(가로 축 + 목록) 유지하면서 이벤트=노드 가능한가? | **가능** |
| DataFlow처럼 노드·연결선·활성·흐름을 이벤트에 붙일 수 있는가? | **가능** (문법 이식, 위젯 이식 아님) |
| DataFlowDiagram을 그대로 쓰는가? | **불가 / 불필요** |
| 원 권장안 “연결선=단계만”과 병행하는가? | **병행 안 함.** 이벤트 본선으로 **정책을 갱신**해야 함 |

### 10.2 조건 (충족해야 구현 성립)

1. **엣지 규칙** §6을 코드/테스트로 고정 (`path` 강조 vs 골격 가이드).
2. **레이아웃**은 7.1(가로 체인) 또는 7.2(열 내 세로) 중 하나. 자유 2D는 본화면 제외.
3. **상태**는 bool이 아니라 `PipelineNodeVisual` 유지.
4. **후처리 밀도**: 가로 체인이면 그래프 영역 가로 스크롤 또는 단계 칩 필터 허용을 A안 예외로 문서화.
5. **다건 비복제**·목록 분리 유지.

### 10.3 리스크

| 리스크 | 완화 |
|--------|------|
| 노드 ~19 + 라벨 → 가로 넘침 | 단계 필터, 짧은 라벨, 그래프만 가로 스크롤 |
| 모든 인접을 강조하면 “다 연결된 것처럼” 보임 | 강조=path만, 흐름=live만 |
| 단계 큰 원 제거 시 구간 인지 약화 | 단계 밴드/헤더 유지 |
| 세로 열(7.2)이면 다시 “여러 파이프라인” 인상 | 7.1 권장 |

## 15. 한 줄 요약

**A안(가로 축 + 목록) 안에서 각 이벤트를 노드로 두고, DataFlow식 노드·연결선·활성·흐름으로 그리는 것은 가능하다.**  
조건은 위젯 복제가 아니라 **이벤트 인접 엣지 규칙 + path 강조 + live 흐름**을 가로 체인(권고)에 얹는 것이다.  
원 권장안의 “연결선=단계만·세부=점”은 이 방향으로 정책을 바꾸면 된다.
