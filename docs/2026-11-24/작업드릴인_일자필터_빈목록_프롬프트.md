# 작업 드릴인 일자 필터 빈 목록 UX

## 목표
작업에 파일이 있어도 선택일 `recorded_at` 창과 겹치지 않으면 목록이 비는 사실을 사용자가 버그로 오해하지 않게 한다. 빈 상태·작업 행 보조 문구·기록일 이동 CTA로 원인을 드러낸다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md` (가이드라인 저장소는 워킹 트리 밖에서 읽기만)
3. `docs/2026-11-24/작업드릴인_일자필터_빈목록_화면설계.md`
4. `lib/src/presentation/features/collection_monitoring/collection_monitoring_view_model.dart` (`_offsetsOf`, `didSelectLevelNode`, `ancestors`)
5. `lib/src/presentation/features/collection_monitoring/widgets/collection_resource_timeline_view.dart` (`resources.isEmpty` → `_emptyLabel`)
6. `lib/src/domain/use_cases/present_collection_nodes_use_case.dart` (`_rowSubtitle`)
7. `lib/src/presentation/features/collection_monitoring/widgets/collection_timeline_inspector.dart`

## 현재 상태
- Job parent일 때만 `_offsetsOf`가 선택일 창을 ns로 넣어 `ListCollectionNodes`를 호출한다. 창 밖 `recorded_at`이면 `nodes: []`.
- 빈 목록 UI는 `_emptyLabel` 한 줄(`이 날짜의 수집 이벤트가 없습니다` 등). 조상 `assetCount`·작업명을 쓰지 않는다.
- 작업 행 `subtitle`은 항상 `_levelName`(`작업`). 선택일 비겹침을 말하지 않는다.
- 인스펙터는 `selectedNode`만 본다. 빈 드릴인 후 선택 없으면 조상 작업 요약이 안 보일 수 있다.

## 바꿀 것
1. **ViewModel**
   - getter: 현재 parent가 job이고 `_nodes`가 비었을 때 상태 A/B와 표시용 `(label, assetCount, selectedDate, canJumpToRecordDate)`.
   - `didTapJumpToJobRecordDate()`: 조상 job의 `firstRecordedAt ?? startedAt` 일자로 `didSelectDate` → 재조회.
2. **빈 상태 UI** (`collection_resource_timeline_view.dart` 또는 host의 빈 분기)
   - A: `이 작업에 첨부된 파일이 없습니다`
   - B: 제목 `이 날짜에 기록된 파일이 없습니다` / 본문 `{label} 파일 {N}개 · {date}에는 기록 없음` / 보조 `파일 목록은 선택일 기준으로 서버가 걸러 줍니다.` / 버튼 `기록이 있는 날 보기`(가능 시만)
3. **작업 행 자막** (`PresentCollectionNodesUseCase`): job이고 `(assetCount??0)>0`이며 해당 노드의 일자 창 이벤트가 0이면 `이 날짜 기록 없음 · 파일 {N}`.
4. **인스펙터**: job 하위가 비었고 선택 노드가 없으면 `ancestors.last`(작업)를 보여 주고, 상태 B일 때 `선택일 겹침` = `없음` 필드 추가.
5. 범위 제외: `전체 파일 보기`(오프셋 해제), InfoBar, 일자 필드 포커스 CTA, 가짜 ◆/막대.
6. CTA1 날짜: 조상 작업의 `firstRecordedAt`이 있으면 그날, 없으면 `startedAt`의 일자. 둘 다 없으면 CTA 숨김.

## 유지할 것
- Job 드릴인 기본 오프셋·일자 타임라인 계약(빈 날 가짜 막대/◆ 금지)
- `ListCollectionNodes` / Present 점·구간 필터 로직
- 크럼·커맨드바 구조, generated proto

## 이번 작업에서 만들지 않음
- 오프셋 없는 전체 파일 모드 / InfoBar / 새 상태관리·카드 UI / day view empty 문구 대개편

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
