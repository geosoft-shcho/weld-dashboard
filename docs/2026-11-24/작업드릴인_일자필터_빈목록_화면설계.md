# (2026-11-24) 작업 드릴인 · 일자 필터 빈 목록 화면 설계

| 항목 | 내용 |
|------|------|
| PM | — |
| 개발 담당 | weld-dashboard |
| 관련 | `ListCollectionNodes` job parent + `start_offset_ns`/`end_offset_ns` |
| 목적 | 작업에 파일(예: 97건)이 있어도 **선택일 기록 창에 없으면 목록이 비는** 현상을 사용자가 버그로 오해하지 않게 한다 |

## 1. 문제

- 품목 → 작업 목록: 오프셋 없음 → `hasChildren: true`, `assetCount: 97`로 “파일이 있는 작업”으로 보인다.
- 작업 클릭 → 파일 목록: 오프셋으로 **`asset.recorded_at ∈ [선택일 창)`만** 요청한다.
- 선택일에 기록이 없으면 `nodes: []` → 화면은 빈 타임라인/빈 목록만 보여, 사용자는 “97개인데 왜 없지?” “클릭이 깨졌다”로 느낀다.

앱 목적(수집값 가시화)상 **빈 날도 사실**이지만, **왜 비었는지**와 **어디에 기록이 있는지**를 같은 작업 맥락에서 보여 줘야 한다.

## 2. 설계 원칙

1. **두 질문을 구분한다.** “이 작업에 파일이 있나?” vs “이 날짜에 기록이 있나?”
2. **빈 목록 ≠ 하위 없음.** `hasChildren`/작업 summary의 파일 수와, 일자 필터 결과 0건을 문구·숫자로 분리한다.
3. **다음 행동을 제시한다.** 일자 변경, 기록 있는 날로 이동, (선택) 오프셋 없이 전체 파일 보기.
4. **수집값을 숨기지 않는다.** 빈 날을 가짜 막대/◆로 채우지 않는다. (일자 segment 겹침 정책과 동일)

## 3. As-Is / To-Be

| | As-Is | To-Be |
|--|-------|-------|
| 작업 행 | 파일 수·하위 있음만 강조 | 선택일과 겹치는 segment/기록 여부를 보조로 드러냄 |
| 작업 드릴인 빈 목록 | 범용 “없음” 또는 빈 그리드만 | **일자 필터 빈 상태** 전용 문구 + 작업 전체 파일 수 + CTA |
| 일자 | 사용자가 연결을 유추해야 함 | 빈 상태에서 일자가 원인임을 명시 |

## 4. 화면별 권장

### 4.1 작업 단계 리소스 행 (드릴인 전)

- 유지: 작업명, 막대(`segments` ∩ 선택일).
- 추가(권장):
  - 선택일과 segment가 **안 겹치면** 행 보조 문구 예: `이 날짜 기록 없음 · 파일 97`
  - 또는 배지: `다른 날` / `선택일 없음` (짧게).
- 더블클릭/진입은 유지하되, 보조 문구로 “들어가면 비어 있을 수 있음”을 암시한다.

### 4.2 작업 → 파일 목록이 비었을 때 (핵심)

진입 조건: `parent.level = JOB` + 오프셋 요청 후 `nodes` 비어 있음, 그리고 조상 작업 노드에 `assetCount > 0` (또는 `hasChildren`).

빈 상태 영역(타임라인 본문 또는 목록 패널)에 **한 덩어리**로:

| 요소 | 내용 예 |
|------|---------|
| 제목 | `이 날짜에 기록된 파일이 없습니다` |
| 본문 | `{작업명}에는 파일이 {N}개 있지만, {YYYY-MM-DD} 기록 시각(`recorded_at`)과 겹치는 항목이 없습니다.` |
| 보조 | `파일 목록은 선택일 기준으로 서버가 걸러 줍니다.` (한 줄, 작은 글씨) |
| 일차 CTA | `기록 있는 날로` — `firstRecordedAt`~`lastRecordedAt`(또는 segment)에서 **가장 가까운 날짜**로 일자 변경 후 재조회 |
| 이차 CTA(선택) | `전체 파일 보기` — 오프셋 없이 같은 job parent로 다시 호출(또는 파일 관리/작업 상세로 이동). 제품 타임라인 기본 동작과 다르면 토글/메뉴에 둔다 |

금지:

- “조건에 맞는 장비가 없습니다” 등 **계층/필터 일반 문구**만 쓰기.
- 빈 칸에 가짜 ◆·막대 채우기.
- `hasChildren`만 보고 로딩 스피너를 끝없이 돌리기.

### 4.3 크럼·커맨드바

- 크럼: `공사 > 품목 > 작업명` 유지.
- 일자 칩/필드 근처(또는 빈 상태 CTA 옆): 현재 일자 강조.
- (선택) InfoBar 1회: `작업 파일은 선택일 기록만 표시됩니다.` — 첫 빈 드릴인에만.

### 4.4 인스펙터 / 선택 작업 요약

작업이 선택된 채 파일 목록이 비면 인스펙터에:

- 파일 수(전체): summary `assetCount`
- 기록 기간: `firstRecordedAt` ~ `lastRecordedAt`
- 선택일: 겹침 없음

숫자로 “전체는 있는데 오늘은 없음”을 고정한다.

## 5. 상태 정의

| 상태 | 조건 | UI |
|------|------|-----|
| A. 작업에 파일 없음 | `assetCount == 0` / `!hasChildren` | `이 작업에 첨부된 파일이 없습니다` (일자와 무관) |
| B. 파일 있으나 선택일 없음 | 조상 `assetCount > 0` && 자식 `nodes` 빈 | **§4.2 일자 필터 빈 상태** |
| C. 선택일 파일 있음 | `nodes` 비어 있지 않음 | 기존 파일 리소스/타임라인 |
| D. 로딩/오류 | 기존과 동일 | 기존 |

상태 B는 **클라이언트만으로** 가능: 드릴인 직전 캐시한 작업 노드의 `assetCount`/`hasChildren` + 응답 `nodes.isEmpty`.

## 6. 카피 초안 (한국어)

- 제목: `이 날짜에 기록된 파일이 없습니다`
- 본문: `{label} 파일 {N}개 · {date}에는 기록 없음`
- CTA1: `기록이 있는 날 보기`
- CTA2: `일자만 바꾸기` (포커스를 일자 필드로)
- CTA3(선택): `날짜 무시하고 전체 파일`

## 7. 정책 · 예외

- 오프셋은 proto대로 job 드릴인에만 유지. 빈 목록을 피하려고 기본 오프셋을 끄지 않는다(일자 타임라인 계약 유지).
- `전체 파일 보기`를 넣으면 요청에서 오프셋을 빼고, UI에 `전체 기간` 뱃지를 붙여 일자 모드와 구분한다.
- 기록 기간이 없으면(요약 시각 null) CTA1은 숨기고 CTA2만 둔다.
- 다중 일 segment인 작업은 “가장 가까운 날” 대신 **기록 시작일**로 이동해도 된다(구현 단순).

## 8. 구현 시 건드릴 곳 (참고, 이번 문서는 설계만)

- 빈 라벨: `collection_resource_timeline_view` `_emptyLabel` — JOB 하위(파일) + 일자 빈 상태 분기
- 드릴인 직후 빈 응답 처리: `collection_monitoring_view_model` / host
- 인스펙터: `collection_timeline_inspector`
- 작업 프롬프트는 별도 확인 후 `docs/<날짜>/…_프롬프트.md`로 저장·구현
