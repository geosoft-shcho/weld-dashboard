# 타임라인 수집 상태·범례 자연 표시

## 목표
`ListCollectionNodes` 파일(Asset) 구간이 잘못 **단절**로 보이지 않게 하고, 범례·막대 문구가 수집 모니터링 의미에 맞게 읽히게 한다.

## 먼저 읽을 것
1. `README.md` 목적 절
2. `.cursor/skills/apply-guidelines/SKILL.md` (가이드라인 저장소는 워킹 트리 밖에서 읽기만)
3. `lib/src/domain/use_cases/present_collection_nodes_use_case.dart`
4. `lib/src/data/repositories/remote_collection_catalog_repository.dart`
5. `lib/src/domain/entities/connection_status.dart`
6. `lib/src/presentation/features/collection_monitoring/widgets/collection_timeline_host.dart`
7. `protos/mediatag/work/v1/work.proto` (`CollectionNode.summary` — Asset이면 비어 있음)

## 현재 상태
- 파일 노드 JSON에 `asset`만 있고 `summary.assetCount` 없음 → 회색·「단절」.
- 범례는 장비 모니터형 5종(수집/단절/오류/유실/지연)인데 Present는 사실상 수집·단절만 씀.
- 상태 판정: `(summary.assetCount ?? 0) > 0` → 수집, 아니면 단절.

## 바꿀 것
1. Present·remote catalog에서 연결 상태 판정: `(assetCount ?? 0) > 0 || node.isAssetNode` 이면 `connected`, 아니면 `disconnected`.
2. `ConnectionStatus.disconnected` 라벨을 `기록 없음`으로 (`수집`·`오류` 유지).
3. `_Legend`를 수집 / 기록 없음 / 오류 세 항목으로. 유실≥10%·지연·미동기는 범례에서 제거. `colorOf` 분기는 유지.
4. 새 추상 계층·헬퍼 파일 없이 기존 판정 자리에 조건을 넣는다.

## 유지할 것
- ConnectionStatus enum 값·색 매핑(`STATUS_OK`/`OFF`/`ERROR`)
- segment 일자 창 필터·빈 목록 UX
- generated proto 미수정

## 이번 작업에서 만들지 않음
- 새 상태 enum·디자인 시스템
- 유실/지연 데이터를 API에서 채우는 작업
- 커맨드바 연결상태 필터 UX 대개편

## 복잡한 코드 제거 및 금지
- 한 화면·한 동작을 위해 새 추상 계층, 전략, 팩토리, 제네릭 헬퍼를 만들지 않는다.
- 같은 역할의 위젯, ViewModel, UseCase, 화면 흐름이 있으면 그것을 쓴다.
- 이번 변경으로 쓰이지 않게 된 분기, 플래그, 래퍼, 죽은 코드는 제거한다.
- 조건 중첩과 모드 플래그 조합으로 경우를 늘리지 않는다.
- 호출을 한 겹 감싸기 위한 파일은 만들지 않는다. 파일 분리는 책임이 분명할 때만 한다.
- 새 상태관리, 새 디자인 시스템, 카드 UI를 도입하지 않는다.
- 프롬프트 범위 밖의 리팩터, 이름 정리, 스타일 통일을 끼워 넣지 않는다.
