# 깃 커밋·푸시

사용자가 커밋 또는 푸시를 요청했을 때만 실행한다. 요청 없이 커밋하거나 푸시하지 않는다.

커밋푸시, 커밋하고 푸시, commit and push, 올려줘(커밋 의도)면 기본은 **커밋 후 푸시**다.

- 커밋만 / 푸시하지 마 → 커밋만 하고 푸시하지 않는다
- 푸시만 → 이미 있는 커밋을 푸시한다. 커밋도 같이 달라고 하지 않았으면 새 커밋을 만들지 않는다

## 안전

- `git config`, `--no-verify`, `--no-gpg-sign`, `git commit --amend`(사용자 커밋 프로토콜이 허용하는 경우가 아니면), `main`/`master`에 강제 푸시는 하지 않는다
- `git rebase -i`, `git add -i`는 쓰지 않는다
- `.env`, 자격 증명, 키, 비밀 파일은 커밋하지 않는다. 있으면 알리고 제외한다
- 커밋할 내용이 없으면 빈 커밋을 만들지 않는다
- 푸시는 `git push` (업스트림이 없으면 `git push -u origin HEAD`). `--force`는 쓰지 않는다

## 코딩 가이드라인 저장소 (워킹 트리 금지)

https://github.com/geosoft-co-kr/guidelines.git 는 weld-dashboard 워킹 트리에 두지 않는다. 서브모듈로 넣지 않는다. 그 레포는 수정·편집·커밋·푸시하지 않는다.

- `docs/guidelines` 또는 가이드라인 `.git`이 있으면 **부모 레포에서 제거**한다 (`git rm` / 폴더 삭제). 안쪽 레포에 커밋하지 않는다
- `.gitmodules`에 이 URL을 다시 추가하지 않는다
- `git add -A`를 쓸 때도 가이드라인 클론은 제외한다

## 올리지 않을 파일

커밋·푸시에서 빼는 경로는 **변경사항에 남기지 않는다.** 부모 레포에서 되돌리거나 지운다.

- 비밀 파일·빌드 산출물·실수로 생긴 미추적 파일 → 커밋하지 않고 삭제하거나 `git restore`
- 되돌린 뒤 `git status`에 해당 경로가 없어야 한다

## 1. 확인 (병렬)

레포 루트에서 함께 실행한다.

```bash
git status
git diff && git diff --staged
git log -8 --oneline
git rev-parse --abbrev-ref HEAD
git status -sb
```

diff 전체를 읽는다. 확인하지 않은 파일은 커밋하지 않는다.

## 2. 커밋 나누기

스테이징되지 않은 것·추적되지 않은 것·이미 스테이징된 것을 **파일 개수가 아니라 목적**으로 묶는다.

- 목적이 하나(기능 하나·수정 하나)면 커밋 하나
- 목적이 서로 다르면(예: 스킬 문서 vs 앱 기능) **커밋을 나누고** 메시지도 각각 쓴다
- 빌드 산출물, `.gitignore`에 있는 로컬 IDE 잡파일, 비밀 파일, 가이드라인 클론은 빼둔다

각 묶음은 경로를 명시해 `git add`한다. 트리 전체가 한 묶음일 때만 `git add -A`를 쓴다.

## 3. 커밋 메시지

한국어, 1–2문장, 파일 목록이 아니라 **이유**. 첫 줄 72자 이하. HEREDOC만 사용한다.

```bash
git commit -m "$(cat <<'EOF'
수집 모니터링 화면에 장비 행 타임라인을 넣는다.

EOF
)"
```

구분:

- `추가` — 없던 동작이나 파일
- `수정` / `개선` — 있던 동작 변경
- `수정` (버그) — 잘못된 동작 고침

예:

```text
페이지·위젯 구현 전에 코딩 가이드라인을 읽도록 스킬을 추가한다.
```

```text
로그인 화면을 MVVM-C 구조에 맞게 나눈다.
```

`update`, `fix`, `wip`, `asdf` 같은 메시지와 `git status` 경로 나열은 쓰지 않는다.

커밋마다 `git status`로 확인한다.

## 4. 푸시

이번 실행에 푸시가 포함되면:

```bash
git push -u origin HEAD
```

non-fast-forward로 거절되면 멈춘다. 상황을 알리고 강제 푸시하지 않는다.

## 5. 보고

브랜치 이름, 커밋 해시와 제목, 푸시 성공 여부, 알 수 있으면 리모트 URL을 답한다. 커밋할 내용이 없으면 그렇게 말하고, 푸시 요청이 있었으면 아직 안 올라간 커밋은 푸시한다.
